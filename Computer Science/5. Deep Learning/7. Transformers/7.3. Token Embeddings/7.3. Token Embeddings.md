>[!note] Token Embeddings
>A transformer works with vectors, but text arrives as a string. Two steps connect them:
>- **Tokenization** splits the string into tokens from a fixed vocabulary of $V$ entries and replaces each token by its index. [[7.3.1. Tokenization]] covers how the vocabulary is built.
>- **Embedding** maps each index to a learned vector in $\mathbb R^D$.
>
>The **embedding layer** is a linear layer applied to one-hot vectors. Token $i$ becomes the one-hot vector $\mathbf e_i \in \mathbb R^V$, and the layer computes $\mathbf W_e\mathbf e_i$ with $\mathbf W_e \in \mathbb R^{D \times V}$. The product picks out column $i$ of $\mathbf W_e$. The layer is therefore a lookup table with one learned vector per token. Gradient descent trains it like any other weight. The lecture's example has $V = 32{,}000$ and $D = 1000$, so the table holds $32$ million numbers.
>
>At the output, each final token vector $\mathbf h \in \mathbb R^D$ must become a probability for every token in the vocabulary. A second linear layer, the **de-embedding** layer $\mathbf W_u \in \mathbb R^{V \times D}$, computes $V$ scores $\mathbf z = \mathbf W_u\mathbf h$. A softmax turns them into probabilities $p_i = e^{z_i}/\sum_j e^{z_j}$.
>
>The lecture sets the scale of both layers with RMS norms. The vectors entering the attention blocks should have RMS norm $1$:
>- **Embedding**: the output $\mathbf W_e\mathbf e_i$ is column $i$ itself. Each column of $\mathbf W_e$ should therefore have RMS norm $1$, with entries of size about $1$.
>- **De-embedding**: the input $\mathbf h$ has RMS norm $1$. For scores of size about $1$, each row of $\mathbf W_u$ should have Euclidean norm $1$. Its entries are then about $1/\sqrt D$. For $D = 1000$ that is about $0.03$.

# Intuition

A one-hot vector already identifies a token, so the network could read it directly. One-hot vectors make every pair of tokens equally different, though. The Fall 2022 lecture 19 notes use "actual", "actually" and "banana" as the example. In one-hot form, "actual" is as far from "actually" as from "banana". A learned table can place related tokens close together. A network is a continuous function, so close inputs give close outputs. A small mistake in an input vector then causes only a small change in the prediction.

The table holds one vector per token, the same in every sentence. "Bank" gets one vector, whether the sentence is about rivers or money. The transformer blocks then change each vector according to its context. The vector for "bank" leaving the last block depends on the whole sentence. These output vectors are **contextual embeddings**, and [[7.5. Encoder and Decoder Models|BERT]] uses them as features. The table's vectors are **static embeddings**, like those of [[7.3.2. Word2vec]].

The RMS rules come from the same reasoning as in [[4.3. Maximal Update Parameterization]]. A one-hot input has RMS norm $1/\sqrt V$, about $0.0056$ for $V = 32{,}000$. The embedding layer must raise this to $1$, the scale that the attention blocks expect. The output layer must map a vector of RMS norm $1$ to scores that are neither tiny nor huge.

# Properties

#### *(A Lookup Is a Matrix Product)* Multiplying $\mathbf W_e$ by a one-hot vector returns one column, so the layer is computed by indexing.

No multiplication is needed in practice. The layer reads column $i$ from memory. The gradient also touches only the columns of tokens that appear in the batch. The column of a token that never appears in the training data stays at its initial value. The tokenizer runs on the CPU before training starts, and the table lives on the GPU with the other weights.

#### *(Scale of the Embedding)* Each column of $\mathbf W_e$ should have RMS norm $1$, because the layer's output is a column.

The lecture asks for an RMS norm of $1$ at the input to the attention heads. The input $\mathbf e_i$ has RMS norm $1/\sqrt V$. The output $\mathbf W_e\mathbf e_i$ is the column $\mathbf w_i$, so its RMS norm is the column's own. Entries of size about $1$ give $\mathrm{RMS}(\mathbf w_i) \approx 1$. In the RMS-to-RMS view, the layer multiplies the RMS norm of its input by about $\sqrt V$.

#### *(Scale of the De-embedding)* Each row of $\mathbf W_u$ should have Euclidean norm about $1$, so that the scores stay of size about $1$.

Score $z_j$ is the inner product of row $j$ with $\mathbf h$. The lecture asks each row to satisfy $\sum_i w_{ji}^2 = 1$, which gives $D w^2 = 1$ for equal entries, so $w \approx 1/\sqrt D$. If $\mathbf h$ and the row point in unrelated directions, the score is then about $\mathrm{RMS}(\mathbf h)$, which is $1$. Entries of size $1$ would multiply all scores by $\sqrt D$. The softmax would then be nearly one-hot from the start, with gradients near $0$.

#### *(Weight Tying)* Many models use one matrix for both layers, setting $\mathbf W_u = \mathbf W_e^T$.

>[!warning] Not Taught in Lecture
>Weight tying follows Press and Wolf (2017) and Vaswani et al. (2017).

Tying saves $VD$ parameters, which matters for small models. It also links the two jobs. A token's input vector and its output row are the same vector. The two layers want different scales, though. The de-embedding rows need entries near $1/\sqrt D$, while the embedding columns need entries near $1$. The original transformer ties the weights and multiplies the embedding output by $\sqrt D$. This factor is exactly the gap between the two RMS rules.

#### *(Where the Table Comes From)* The table is usually trained with the rest of the model, but it can start from embeddings learned separately.

The embedding table gets its gradient from the model's loss, like every other weight. Some models start the table from [[7.3.2. Word2vec|word2vec]] vectors. The Fall 2022 lecture 20 notes point out a mismatch. Word2vec learns one vector per word, while a tokenizer may split a rare word into several tokens. Those fragments have no word2vec vectors.

# Examples

>[!example] (Easy) A Lookup
>A vocabulary has $V = 4$ tokens, indexed $0$ to $3$, and $D = 3$. The embedding matrix is
>$$\mathbf W_e = \begin{bmatrix} 1 & 0 & -1 & 2 \\ 0 & 1 & 1 & 0 \\ 2 & -1 & 0 & 1 \end{bmatrix}.$$
>
>>[!example]- Embed the token sequence $(2, 0, 2)$. Check the RMS norm of each column.
>>The output is column $2$, column $0$, then column $2$ again: $(-1, 1, 0)$, $(1, 0, 2)$, $(-1, 1, 0)$. The two copies of token $2$ get the same vector, since the table has no context. The column RMS norms are $\sqrt{5/3} = 1.29$, $\sqrt{2/3} = 0.82$, $\sqrt{2/3} = 0.82$ and $\sqrt{5/3} = 1.29$. All are close to $1$, as the lecture's rule asks.

>[!example] (Medium) Tying and the $\sqrt D$ Factor
>A model has $V = 50{,}000$ and $D = 768$, with tied weights $\mathbf W_u = \mathbf W_e^T$. The entries of $\mathbf W_u$ follow the de-embedding rule.
>
>>[!example]- What RMS norm does a one-hot input have? What RMS norm does the tied embedding layer output? What factor restores the RMS norm of $1$?
>>A one-hot vector of length $50{,}000$ has RMS norm $1/\sqrt{50{,}000} = 0.0045$. The de-embedding rule gives entries of size $1/\sqrt{768} = 0.036$. A column of $\mathbf W_e = \mathbf W_u^T$ is a row of $\mathbf W_u$, so its entries are also about $0.036$. The embedding output therefore has RMS norm about $0.036$. Multiplying it by $\sqrt{768} = 27.7$ brings the RMS norm to $1$. This is the $\sqrt D$ factor of the original transformer.

>[!example] (Hard) How Much of a Model Is Embeddings
>A small model has $V = 32{,}000$, $D = 512$ and $6$ blocks with $12D^2$ weights each, and separate input and output tables. GPT-3 has $V = 50{,}257$, $D = 12{,}288$ and $96$ blocks, with one table.
>
>>[!example]- Compute the share of the parameters held by the tables in each model, with biases ignored. What does tying save in the small model?
>>The small model's blocks have $12 \cdot 512^2 \cdot 6 = 18{,}874{,}368$ weights. Each table has $32{,}000 \cdot 512 = 16{,}384{,}000$, and the two tables together hold $32{,}768{,}000$. The total is $51{,}642{,}368$, and the tables hold $63\%$ of it. Tying removes one table and leaves $35{,}258{,}368$ parameters, of which the table is $46\%$.
>>
>>GPT-3's table has $50{,}257 \cdot 12{,}288 = 617{,}558{,}016$ entries. Its blocks have $12 \cdot 96 \cdot 12{,}288^2 \approx 1.74 \times 10^{11}$ weights. The table is $0.35\%$ of the block weights. The table grows like $VD$, but the blocks grow like $LD^2$, so the table matters less as models grow.
