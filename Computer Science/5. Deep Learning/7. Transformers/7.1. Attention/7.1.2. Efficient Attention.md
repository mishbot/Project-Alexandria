>[!note] Efficient Attention
>Standard [[7.1. Attention|attention]] compares every query with every key. For $N$ tokens, the score matrix $\mathbf Q\mathbf K^T$ has $N^2$ entries. One head needs $O(N^2 D_k)$ arithmetic and $O(N^2)$ memory for its attention matrix. A causal decoder skips about half of the pairs, but its cost still grows as $N^2$. **Efficient attention** methods lower this cost in one of two ways:
>- **Exact methods** compute the same output with less memory traffic. **FlashAttention** never stores the $N \times N$ matrix. It processes the keys and values in blocks that fit in the GPU's fast on-chip memory. It keeps running softmax statistics for each query.
>- **Approximate methods** compute a different function. **Sparse attention** lets each query read only some keys. Examples are a window of neighbors, a dilated pattern or a few global tokens. **Kernelized** and **ridge** attention, from HW10, replace the softmax weights with other weights.

>[!warning] Not Taught in Lecture
>The lecture gives only the quadratic cost. Sparse patterns follow Prince §12.9 and its chapter notes. FlashAttention follows Dao et al. (2022), and FlashAttention-2 follows Dao (2023). Kernelized and ridge attention come from HW10.

# Intuition

A GPU has two kinds of memory. Its main memory (HBM) is large but slow to read. Its on-chip memory (SRAM) is fast but tiny. Dao et al. give numbers for an A100 GPU. It has $40$ to $80$ GB of HBM with a bandwidth of $1.5$ to $2$ TB/s. Each of its $108$ processors has $192$ KB of SRAM, with a total bandwidth of about $19$ TB/s. Every operation reads its inputs from HBM into SRAM, computes, and writes the result back to HBM.

Standard attention runs as three separate operations. The first computes $\mathbf S = \mathbf Q\mathbf K^T/\sqrt{D_k}$ and writes it to HBM. The second reads $\mathbf S$, applies the softmax, and writes $\mathbf A$. The third reads $\mathbf A$ and computes $\mathbf A\mathbf V$. The $N \times N$ matrices travel to and from HBM four times. For long sequences this traffic, not the arithmetic, sets the running time.

FlashAttention fuses the three steps into one. It loads a block of queries and a block of keys and values into SRAM. It computes their scores there and updates the output, then moves on to the next key block. No $N \times N$ matrix is ever written to HBM. The difficulty is the softmax, whose denominator needs all the scores of a row. The **online softmax** solves this with a running maximum and a running sum.

# Properties

#### *(Online Softmax)* A row of softmax-weighted values can be computed one block of keys at a time by keeping three running quantities.

Fix one query. After some key blocks, keep the largest score so far $m$, the sum $\ell = \sum_j e^{s_j - m}$ and the vector $\tilde{\mathbf o} = \sum_j e^{s_j - m}\mathbf v_j$. Both sums run over the keys seen so far. A new block brings scores $s_j$ with values $\mathbf v_j$. Set $m' = \max(m, \max_j s_j)$. Then
$$\ell' = e^{m - m'}\ell + \sum_{j \in \text{block}} e^{s_j - m'}, \qquad \tilde{\mathbf o}' = e^{m - m'}\tilde{\mathbf o} + \sum_{j \in \text{block}} e^{s_j - m'}\mathbf v_j.$$
After the last block, the output is $\mathbf o = \tilde{\mathbf o}/\ell$. The factor $e^{m - m'}$ rescales the old sums whenever the maximum grows. Subtracting the maximum keeps every exponential at most $1$, so nothing overflows. The result equals the ordinary softmax output exactly, as the Hard example proves.

#### *(Tiling)* FlashAttention splits $\mathbf Q$, $\mathbf K$ and $\mathbf V$ into blocks of rows sized to fit in SRAM and loops over the blocks.

Take a block of query rows. For each block of key and value rows, the kernel computes the block of scores in SRAM. It then updates $m$, $\ell$ and $\tilde{\mathbf o}$ for every query in its block. After the last key block, it divides by $\ell$ and writes the output rows to HBM. It also writes $m$ and $\ell$, or the single number $m + \ln\ell$ per query, for the backward pass. The extra memory is $O(N)$ numbers instead of the $O(N^2)$ of a stored attention matrix.

#### *(Fewer Memory Accesses, Same Arithmetic)* FlashAttention does the same $O(N^2 D_k)$ arithmetic as standard attention but far fewer reads and writes to HBM.

Let $M$ be the SRAM size in numbers, with $D_k \le M \le ND_k$. Dao et al. prove that standard attention makes $\Theta(ND_k + N^2)$ HBM accesses. FlashAttention makes $\Theta(N^2 D_k^2/M)$. The ratio of the $N^2$ terms is about $D_k^2/M$. With $D_k = 64$ and $M = 10^5$, that ratio is $0.04$, so the traffic drops about $25$-fold. With $D_k = 256$ it is $0.66$, and the saving mostly disappears. These are orders of magnitude, since the $\Theta$ bounds drop constant factors. A model with heads of size $64$ to $128$ gains the most.

#### *(Recompute Instead of Store)* The backward pass recomputes the attention blocks from $\mathbf Q$, $\mathbf K$ and the saved statistics instead of reading a stored matrix.

The gradient of attention needs the weights $\mathbf A$. Standard training stores $\mathbf A$ in the forward pass, which costs $O(N^2)$ memory per head and layer. FlashAttention stores only the output and the row statistics. In the backward pass it reloads blocks of $\mathbf Q$, $\mathbf K$ and $\mathbf V$ and recomputes each block of $\mathbf A$ in SRAM. This adds arithmetic but removes most of the memory traffic, so the backward pass also runs faster. The same trade of compute for memory appears in gradient checkpointing.

#### *(FlashAttention-2)* FlashAttention-2 changes the order and the split of the work and runs about twice as fast as FlashAttention.

The outer loop runs over blocks of queries. Different query blocks can then run on different processors at the same time. This adds parallelism over the sequence, which helps when the batch is small and the sequence long. The division by $\ell$ moves to the very end, which removes some operations that are not matrix multiplications. Such operations run much slower than matrix multiplications on GPU hardware. The work inside each processor is also split differently between its thread groups.

#### *(Sparse Attention)* If each query reads a fixed set of keys, the cost falls from $N^2$ to $N$ times the set size.

Prince describes the allowed pairs as an interaction matrix. In a convolutional pattern, each token reads only the $w$ tokens nearest to it, which costs $O(NwD_k)$. Information still travels far over several layers, because the receptive field grows with depth as in a CNN. Dilated windows skip tokens and grow the receptive field faster. A few tokens can also be made global, so that they read and are read by all tokens. The `<cls>` token of [[7.5. Encoder and Decoder Models|BERT]] is a natural choice. BigBird combines windows, global tokens and random connections. Unlike FlashAttention, these patterns change the model, since some pairs can never interact within one layer.

# Examples

>[!example] (Easy) Memory for the Attention Matrix
>A model reads $N = 16{,}384$ tokens with $H = 16$ heads per layer. Numbers are stored in 16-bit floats of $2$ bytes, and the statistics in 32-bit floats of $4$ bytes.
>
>>[!example]- How much memory do the attention matrices of one layer take for one sequence? How much do FlashAttention's statistics take?
>>One head's matrix has $N^2 = 268{,}435{,}456$ entries, or $0.54$ GB. Sixteen heads need $8.6$ GB for a single layer and a single sequence. Training would store this for every layer, so standard attention cannot train at this length on one GPU. FlashAttention keeps $2$ numbers per query and head, so $16 \cdot 16{,}384 \cdot 2 \cdot 4 = 2{,}097{,}152$ bytes, about $2.1$ MB.

>[!example] (Medium) Online Softmax by Hand
>One query has scores $(1, 3, 4)$ for three keys with scalar values $(10, 20, 30)$. The keys arrive in two blocks: the first two keys, then the third.
>
>>[!example]- Run the online softmax and check the result against the ordinary softmax.
>>Block $1$ has the scores $1$ and $3$, so $m = 3$. The sums are
>>$$\ell = e^{1-3} + e^{0} = 1.1353, \qquad \tilde o = e^{-2}\cdot 10 + 1\cdot 20 = 21.353.$$
>>Block $2$ has the score $4$, so $m' = 4$ and the old sums are rescaled by $e^{3-4} = 0.3679$:
>>$$\ell' = 0.3679 \cdot 1.1353 + e^{0} = 1.4177, \qquad \tilde o' = 0.3679 \cdot 21.353 + 30 = 37.855.$$
>>The output is $37.855/1.4177 = 26.70$. The ordinary softmax of $(1, 3, 4)$ gives the weights $(0.0351, 0.2595, 0.7054)$, and $0.351 + 5.190 + 21.162 = 26.70$. The two results agree. The new maximum in block $2$ forced the rescaling, which kept every exponential at most $1$.

>[!example] (Hard) The Online Softmax Is Exact
>Prove that the online softmax gives the ordinary softmax output for any split of the keys into blocks.
>
>>[!example]- Show by induction that $\ell$ and $\tilde{\mathbf o}$ equal the sums over all keys seen, measured from the current maximum.
>>We claim that after each block, $m$ is the largest score seen so far, $\ell = \sum_j e^{s_j - m}$ and $\tilde{\mathbf o} = \sum_j e^{s_j - m}\mathbf v_j$. Both sums run over every key seen so far.
>>
>>After the first block, the algorithm starts from $\ell = 0$ and $\tilde{\mathbf o} = \mathbf 0$ and computes these sums directly. Suppose the claim holds before a new block, with maximum $m$. The new maximum is $m'$. For an old key, $e^{m - m'}e^{s_j - m} = e^{s_j - m'}$. Rescaling therefore turns each old sum into the same sum measured from $m'$. Adding the new block's terms, measured from $m'$, gives the sums over all keys seen. The claim holds after the new block.
>>
>>After the last block, $m$ is the overall maximum, and
>>$$\frac{\tilde{\mathbf o}}{\ell} = \frac{\sum_j e^{s_j - m}\mathbf v_j}{\sum_j e^{s_j - m}} = \frac{\sum_j e^{s_j}\mathbf v_j}{\sum_j e^{s_j}}.$$
>>The factor $e^{-m}$ cancels between numerator and denominator. The right side is the ordinary softmax output, so the method is exact. The order of the blocks and their sizes do not matter.
