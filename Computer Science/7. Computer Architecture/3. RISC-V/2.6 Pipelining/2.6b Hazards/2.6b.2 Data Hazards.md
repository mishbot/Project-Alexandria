>[!note] RISC-V Data Hazards
>In the RISC-V [[2.6a Pipelining|datapath]], data hazards occur when an instruction is dependent on the result of a previous instruction, such as two operations which (1) perform an arithmetic operation, and (2) save the output of that operation to memory.
>
>Data hazards can be solved by:
>- **Stalling**, by waiting for the first instruction to write its result before the second instruction reads it using **nop** (no-op) instructions (such as `add x0 x0 x0`), which do not have any intrinsic value, but add extra overhead to our code.
>	- This approach varies depending on whether the register file implements **double pumping**, where a new value is read by an instruction in the same cycle it was written to a register by another instruction.
>- **Forwarding**, by adding extra hardware (logic) to send the result back to earlier stages before the result is written.
>- Code scheduling, by rearranging 

# Examples
>[!example] RISC-V
>Suppose we currently have the following RISC-V instructions in our pipeline:
>
>|  Instruction   |  1  |  2  |  3  |   4    |   5    |   6    |  7  |
| :------------: | :-: | :-: | :-: | :----: | :----: | :----: | :-: |
| `add t0 t1 t2` | IF  | ID  | EX  |   M    | ==WB== |        |     |
| `or t3 t4 t5`  |     | IF  | ID  |   EX   |   M    | ==WB== |     |
| `slt t6 t0 t3` |     |     | IF  | ==ID== |   EX   |   M    | WB  |
>There is a clear data hazard in this pipeline, as `slt` reads registers `t0` and `t3` before the results of the first two operations are written to them. However, we can address this. 
>>[!example]- Stalling
>>One way we can do so is by stalling using **nops**. Then, if the register file supports double pumping:
>>
>>|  Instruction   |  1  |  2  |  3  |  4  |   5    |   6    |  7  |  **8**   |  **9**   |
| :------------: | :-: | :-: | :-: | :-: | :----: | :----: | :-: | :-: | :-: |
| `add t0 t1 t2` | IF  | ID  | EX  |  M  | WB |        |     |     |     |
| `or t3 t4 t5`  |     | IF  | ID  | EX  |   M    | ==WB== |     |     |     |
| `add x0 x0 x0` |     |     | IF  | ID  |   EX   |   M    | WB  |     |     |
| `add x0 x0 x0` |     |     |     | IF  |   ID   |   EX   |  M  | WB  |     |
| `slt t6 t0 t3` |     |     |     |     |   IF   | ==ID== | EX  |  M  | WB  |
>>Note how the decode stage of the `slt` instruction overlaps with the write-back stage of the `or` instruction. If double pumping was not implemented, then we would need one additional nop, such that `or` writing back precedes `slt` decoding.
>

| `add t0 t1 t2` | IF  | ID  | EX  |  M  | WB |        |     |     |     |

| `lw a0 4(a0)` |     |     |     | IF  |   ID   |   EX   |  M  | WB  |     |
| `slt t6 t0 t3` |     |     |     |     |   IF   | ==ID== | EX  |  M  | WB  |
