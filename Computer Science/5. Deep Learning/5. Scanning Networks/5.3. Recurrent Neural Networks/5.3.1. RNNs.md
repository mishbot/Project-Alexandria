>[!note] Recurrent Neural Networks
>A **recurrent neural network** (RNN) processes a sequence one time step at a time. It keeps a **hidden state** $\mathbf h_t \in \mathbb R^d$ that summarizes the inputs seen so far. Time runs over $t = 1, \dots, T$, with input $\mathbf u_t \in \mathbb R^m$ and output $\mathbf y_t \in \mathbb R^p$. The model is **causal**, which means that $\mathbf y_t$ depends only on $\mathbf u_1, \dots, \mathbf u_t$. Signal processing offers two causal ways to map inputs to outputs:
>
>- **FIR filter** (finite impulse response): $\mathbf y_t = \sum_{i=0}^{K-1} \mathbf H_i\, \mathbf u_{t-i}$, with **taps** $\mathbf H_i \in \mathbb R^{p \times m}$. Tap $\mathbf H_i$ sets how much the input from $i$ steps ago counts. This is a convolution over time with kernel size $K$, and it ignores inputs older than $K - 1$ steps.
>- **IIR filter** (infinite impulse response): $\mathbf h_t = f(\mathbf h_{t-1}, \mathbf u_t; \theta)$ and $\mathbf y_t = g(\mathbf h_t, \mathbf u_t; \theta)$. A finite hidden state carries the past forward, so one input can affect every later output. The steps must run in order.
>
>A CNN shares weights across space, like an FIR filter. An RNN shares weights across time, like an IIR filter.
>
>The **linear time-invariant (LTI)** state-space model is the simplest IIR filter:
>$$\mathbf h_t = \mathbf A\mathbf h_{t-1} + \mathbf B\mathbf u_t, \qquad \mathbf y_t = \mathbf C\mathbf h_t,$$
>with $\mathbf A \in \mathbb R^{d \times d}$, $\mathbf B \in \mathbb R^{d \times m}$ and $\mathbf C \in \mathbb R^{p \times d}$. Unrolling the recursion gives
>$$\mathbf h_t = \mathbf A^t\mathbf h_0 + \sum_{i=0}^{t-1} \mathbf A^i\mathbf B\,\mathbf u_{t-i}.$$
>With $\mathbf h_0 = \mathbf 0$, the output has the FIR form with taps $\mathbf H_i = \mathbf C\mathbf A^i\mathbf B$. These taps exist for every $i \ge 0$, so their number has no fixed limit.
>
>The traditional RNN puts a nonlinearity $\sigma$, usually sigmoid or tanh, inside the state update:
>$$\mathbf h_{t+1} = \sigma(\mathbf W\mathbf h_t + \mathbf B\mathbf u_{t+1} + \mathbf b_h), \qquad \mathbf y_{t+1} = \mathbf C\mathbf h_{t+1} + \mathbf b_y,$$
>with $\mathbf W \in \mathbb R^{d \times d}$, $\mathbf B \in \mathbb R^{d \times m}$, $\mathbf C \in \mathbb R^{p \times d}$, $\mathbf b_h \in \mathbb R^d$ and $\mathbf b_y \in \mathbb R^p$. The same parameters act at every step, so the parameter count does not depend on $T$. The initial state $\mathbf h_0$ is usually $\mathbf 0$. An extra output term $\mathbf D\mathbf u_{t+1}$, with $\mathbf D \in \mathbb R^{p \times m}$, works like a residual connection.
>
>A **vanilla RNN** layer outputs its hidden state directly, which lets layers stack. A **stacked RNN** feeds the states of layer $\ell - 1$ to layer $\ell$ as its inputs, with $\mathbf h_t^{(0)} = \mathbf u_t$:
>$$\mathbf h_{t+1}^{(\ell)} = \sigma\big(\mathbf W^{(\ell)}\mathbf h_t^{(\ell)} + \mathbf B^{(\ell)}\mathbf h_{t+1}^{(\ell-1)} + \mathbf b^{(\ell)}\big).$$
>Deep stacks use vertical residual connections, vertical $1 \times 1$ MLPs and [[4.5.2. Layer Normalization|LayerNorm]] at each time step. They do not use BatchNorm, and no normalization may use future time steps.
>
>The same network serves several task shapes:
>
>- **Many-to-one**: the network reads the whole sequence and predicts once from $\mathbf h_T$, as in classifying a sentence.
>- **Aligned many-to-many**: the network predicts $\mathbf y_t$ at every step, as in labeling each frame of an audio clip.
>- **One-to-many**: the network starts from one input, such as an image, and produces a sequence of outputs.

>[!warning] Not Taught in Lecture
>The names of the task shapes come from the homework, not the lecture. The lecture's examples put a loss on every output, which is the aligned many-to-many shape.

>[!warning] Homework Notation
>The homework writes the RNN layer as $\mathbf h_t = \sigma(\mathbf W_h\mathbf h_{t-1} + \mathbf W_x\mathbf x_t + \mathbf b)$ and adds the readout $\hat{\mathbf y}_t = \mathbf W_f\mathbf h_t + \mathbf b_f$. In the lecture's symbols, $\mathbf W_h = \mathbf W$, $\mathbf W_x = \mathbf B$, $\mathbf x_t = \mathbf u_t$, $\mathbf b = \mathbf b_h$, $\mathbf W_f = \mathbf C$ and $\mathbf b_f = \mathbf b_y$. The lecture steps from $t$ to $t + 1$, and the homework steps from $t - 1$ to $t$. Both describe the same recurrence. The Kalman filter section below uses $\mathbf x_t$ for the hidden state of a system, not for the input.

# Intuition

Speech, text, control signals and sensor readings arrive in order. A prediction at time $t$ may depend on inputs from long before. A model can see the past in two ways. One is a fixed window of recent inputs, as in an FIR filter or a 1D [[5.2.1. Convolutional Layer|convolution]] over time. The other is a running summary that the model updates at every step, as in an IIR filter. A running sum needs one number of state, and each new input is added to it. An FIR filter that reaches back equally far needs one tap per past step. An RNN learns its own update rule for the summary.

The figure unrolls an RNN over four steps. Every step applies the same $\mathbf W$ to the previous state and the same $\mathbf B$ to the new input. The same $\mathbf C$ reads out every output. The nonlinearity $\sigma$ lets the update keep summaries that no linear system can, such as the largest value so far. Each $\mathbf h_t$ needs $\mathbf h_{t-1}$, so the steps run one after another. Gradients also pass back through every step, which [[5.3.2. Backpropagation Through Time]] covers.

# Properties

#### *(Nilpotent A Gives a Finite Filter)* If $\mathbf A^K = \mathbf 0$ for some $K$, the LTI model is an FIR filter with $K$ taps.

Every tap $\mathbf H_i = \mathbf C\mathbf A^i\mathbf B$ with $i \ge K$ is then zero. A delay line shows that every FIR filter arises this way. Take scalar inputs, $d = K$, a matrix $\mathbf A$ that moves each state entry down one place, and $\mathbf B = \mathbf e_1$. The state then holds the last $K$ inputs, $\mathbf h_t = [u_t, u_{t-1}, \dots, u_{t-K+1}]^T$. The readout $\mathbf C = [H_0, H_1, \dots, H_{K-1}]$ gives back the FIR filter. Not every LTI model is an FIR filter. A running sum has $A = B = C = 1$ and $H_i = 1$ for every $i$, and no FIR filter with finite $K$ matches it. When $\mathbf A$ is diagonalizable, each tap is a combination of powers $\lambda_j^i$ of its eigenvalues ([[12.2 Eigendecomposition]]). Eigenvalues inside the unit circle give memory that fades, and eigenvalues outside it make the taps grow.

#### *(Memory Needs the Right State)* The state must hold what future outputs need, and some useful summaries need a nonlinear update.

A running sum keeps $\bar z_t = \bar z_{t-1} + x_t$, an LTI update with one number of state. A running average keeps $\bar x_t = \frac{1}{t}\big((t-1)\,\bar x_{t-1} + x_t\big)$. Its coefficients change with $t$, so it is linear but not time-invariant. Tracking the two largest values of $u_1, u_2, \dots$ needs the maximum $a_t$ and the second largest $b_t$. If the inputs have a known lower bound, both start at that bound. The update is then $a_t = \max(a_{t-1}, u_t)$ and $b_t = \max\big(b_{t-1}, \min(a_{t-1}, u_t)\big)$. Without such a bound, the state also needs a count of the inputs seen so far, up to $2$. No LTI model can do this. With $\mathbf h_0 = \mathbf 0$ its output is a linear function of the inputs, and the maximum is not linear. This is why the RNN puts a nonlinearity inside the update.

#### *(Counterpart of a Convolution)* The recurrent block keeps the design ideas of a CNN, with time in place of space and causality enforced.

A convolution shares one kernel across positions, and the RNN shares $\mathbf W$, $\mathbf B$ and $\mathbf C$ across time steps. It learns one update rule and runs on sequences of any length. Weight sharing also gives shift equivariance in time ([[5.2.1b. Equivariance and Invariance]]). For the LTI model with $\mathbf h_0 = \mathbf 0$, delaying the input by $\tau$ steps delays the output by $\tau$ steps. A nonlinear RNN has this property exactly only when $\mathbf h_0$ is a state that zero inputs leave unchanged. Causality is the new constraint. An image convolution looks in every direction, while the RNN may look only back. The skip term $\mathbf D\mathbf u_{t+1}$ gives the input a direct path to $\mathbf y_{t+1}$, like a [[5.2.5. Residual Networks|residual connection]].

Each layer has its own $\mathbf W^{(\ell)}$ and $\mathbf B^{(\ell)}$, shared across all time steps. Deep stacks borrow three tools from CNNs. Vertical residual connections add $\mathbf h_t^{(\ell-1)}$ to the output of layer $\ell$. Vertical MLPs act on each $\mathbf h_t^{(\ell)}$ alone, like a [[5.2.1c. 1x1 and Depthwise Convolution|1x1 convolution]]. LayerNorm normalizes each $\mathbf h_t^{(\ell)}$ over its own $d$ entries, so it uses only the current step. BatchNorm fails here for three reasons. The weights are shared across time, but the statistics of $\mathbf h_t$ change with $t$. Sequences in a batch also have different lengths, so late steps have few examples to average. Any statistic taken along the time axis would also use future steps and break causality.

#### *(Kalman Filter as a Learned RNN)* The steady-state Kalman filter is a linear RNN, so its matrices can be learned from recorded traces.

Consider the controlled linear Gaussian system
$$\mathbf x_{t+1} = \mathbf A\mathbf x_t + \mathbf B\mathbf u_{t+1} + \mathbf w_{t+1}, \qquad \mathbf y_{t+1} = \mathbf C\mathbf x_{t+1} + \mathbf D\mathbf u_{t+1} + \mathbf v_{t+1},$$
with noise $\mathbf w_t \sim \mathcal N(\mathbf 0, \mathbf K_w)$ and $\mathbf v_t \sim \mathcal N(\mathbf 0, \mathbf K_v)$. The steady-state [[3.12.1 Kalman Filter|Kalman filter]] estimates the hidden state $\mathbf x_t$ with
$$\hat{\mathbf x}_{t+1} = \tilde{\mathbf A}\hat{\mathbf x}_t + \tilde{\mathbf B}\mathbf u_{t+1} + \mathbf F\mathbf y_{t+1}, \qquad \tilde{\mathbf A} = (\mathbf I - \mathbf F\mathbf C)\mathbf A, \qquad \tilde{\mathbf B} = (\mathbf I - \mathbf F\mathbf C)\mathbf B - \mathbf F\mathbf D.$$
The gain is $\mathbf F = \mathbf P\mathbf C^T(\mathbf C\mathbf P\mathbf C^T + \mathbf K_v)^{-1}$, where $\mathbf P = \mathbf A\mathbf P\mathbf A^T + \mathbf K_w - \mathbf A\mathbf P\mathbf C^T(\mathbf C\mathbf P\mathbf C^T + \mathbf K_v)^{-1}\mathbf C\mathbf P\mathbf A^T$. This recursion is a linear RNN with state $\hat{\mathbf x}_t$ and inputs $(\mathbf u_t, \mathbf y_t)$. Suppose the system matrices and noise covariances are unknown, but traces of $\mathbf x_t$, $\mathbf u_t$ and $\mathbf y_t$ are recorded. Then $\tilde{\mathbf A}$, $\tilde{\mathbf B}$ and $\mathbf F$ become learnable weights. Training minimizes the mean of $\|\mathbf x_t - \hat{\mathbf x}_t\|^2$ over blocks of consecutive steps, and memory limits the block length. The linked note writes $\Phi$, $A_t$, $Q$, $R$ and $K_t$ for the $\mathbf A$, $\mathbf C$, $\mathbf K_w$, $\mathbf K_v$ and $\mathbf F$ used here. Its prior covariance $P_t^{t-1}$ becomes $\mathbf P$ in steady state.

#### *(Identifiable Only Up to a Basis)* Without $\mathbf x_t$, data on $\mathbf u_t$ and $\mathbf y_t$ fix the learned matrices only up to an invertible change of basis $\mathbf M$.

Write $\tilde{\mathbf x}_t = \mathbf M\mathbf x_t$. Then
$$\tilde{\mathbf x}_{t+1} = \mathbf M\mathbf A\mathbf M^{-1}\tilde{\mathbf x}_t + \mathbf M\mathbf B\mathbf u_{t+1} + \mathbf M\mathbf w_{t+1}, \qquad \mathbf y_{t+1} = \mathbf C\mathbf M^{-1}\tilde{\mathbf x}_{t+1} + \mathbf D\mathbf u_{t+1} + \mathbf v_{t+1},$$
and the new process noise has covariance $\mathbf M\mathbf K_w\mathbf M^T$. Both systems give the same joint distribution of controls and observations ([[2.8b Change of Basis]]). No loss on $\mathbf u$ and $\mathbf y$ can prefer one of them. The lecture therefore assumes a diagonal $\mathbf A$. A linear head predicts $\mathbf y_{t+1}$ from $\hat{\mathbf x}_{t+1}$ and $\mathbf u_{t+1}$. The loss compares the predicted and recorded $\mathbf y_{t+1}$. If the diagonal entries are distinct, the remaining freedom is to reorder and rescale the state coordinates.

#### *(Gated and Bidirectional Variants)* Gates, a second direction and an encoder-decoder split extend the vanilla RNN.

>[!warning] Not Taught in Lecture
>The lecture covers only the vanilla RNN and its linear relatives. These variants follow Goodfellow et al., *Deep Learning*, §10.3, §10.4 and §10.10. Lecture 18 later covers the encoder-decoder, in [[5.3.3. Sequence-to-Sequence Models]].

The **LSTM** (Hochreiter and Schmidhuber, 1997) adds a cell state $\mathbf c_t$ next to $\mathbf h_t$. Three sigmoid gates control the cell. The input gate decides what is written, and the forget gate decides what is erased. The output gate decides what is read out. The forget gate was added later by Gers et al. (2000). Along the cell, the gradient is multiplied by the forget gate at each step instead of by $\mathbf W$. With the forget gate near $1$, gradients keep their size over many more steps. The **GRU** (Cho et al., 2014) is a smaller variant with an update gate and a reset gate. A **bidirectional RNN** runs one RNN forward and one backward and concatenates their states at each $t$. Every output then sees past and future, which requires the whole sequence in advance, as in transcribing a recording. An **encoder-decoder** pair handles unaligned many-to-many tasks such as translation, as in [[5.3.3. Sequence-to-Sequence Models]]. The encoder's final state starts the decoder, so the whole input must fit in one fixed-size vector. That limit motivated [[7.1. Attention|attention]] and [[7.2. Transformer Architecture|transformers]], which replaced gated RNNs as the standard sequence models.

# Examples

>[!example] (Easy) Smoothing a Temperature Sensor
>A thermostat smooths noisy readings $u_t$ with the scalar LTI model $h_t = 0.8\,h_{t-1} + 0.2\,u_t$ and $y_t = h_t$, starting from $h_0 = 0$.
>
>>[!example]- Find the taps. How many taps does an FIR filter need if it may drop only taps below 1% of the first one?
>>Here $A = 0.8$, $B = 0.2$ and $C = 1$, so $H_i = CA^iB = 0.2 \cdot 0.8^i$. The first taps are $0.2$, $0.16$, $0.128$ and $0.1024$. The ratio $H_i / H_0 = 0.8^i$ first drops below $0.01$ at $i = 21$, since $0.8^{20} \approx 0.0115$ and $0.8^{21} \approx 0.0092$. The FIR filter therefore needs the $21$ taps $H_0$ to $H_{20}$. They hold $1 - 0.8^{21} \approx 99.1\%$ of the total weight $\sum_i H_i = 1$. The state-space model stores one number and has two parameters, and its memory has no cutoff. A constant input of $1$ gives $y_t = 1 - 0.8^t$, which approaches $1$.

>[!example] (Medium) A ReLU RNN That Tracks the Maximum
>A trader wants the highest price seen so far, and prices are positive. A ReLU RNN with three hidden units computes $\mathbf h_t = \mathrm{ReLU}(\mathbf W\mathbf h_{t-1} + \mathbf B u_t)$ and $y_t = \mathbf C\mathbf h_t$, with $\mathbf h_0 = \mathbf 0$, no biases and
>$$\mathbf c = \begin{bmatrix} 1 & -1 & 1 \end{bmatrix}, \qquad \mathbf W = \begin{bmatrix} \mathbf c \\ -\mathbf c \\ -\mathbf c \end{bmatrix}, \qquad \mathbf B = \begin{bmatrix} 0 \\ 0 \\ 1 \end{bmatrix}, \qquad \mathbf C = \mathbf c.$$
>
>>[!example]- Show that $y_t = \max(u_1, \dots, u_t)$, and run the network on the prices $3, 5, 4, 7$.
>>Write $m_{t-1} = \mathbf c\,\mathbf h_{t-1}$. The three units compute $\mathrm{ReLU}(m_{t-1})$, $\mathrm{ReLU}(-m_{t-1})$ and $\mathrm{ReLU}(u_t - m_{t-1})$. The readout adds the first and third and subtracts the second. The first two terms give $\mathrm{ReLU}(m_{t-1}) - \mathrm{ReLU}(-m_{t-1}) = m_{t-1}$, so $y_t = m_{t-1} + \max(0, u_t - m_{t-1}) = \max(m_{t-1}, u_t)$. Since $m_t = y_t$, induction from $m_0 = 0$ gives the running maximum of $0, u_1, \dots, u_t$. For positive prices this is $\max(u_1, \dots, u_t)$. On the prices, the states are $[0, 0, 3]$, $[3, 0, 2]$, $[5, 0, 0]$ and $[5, 0, 2]$, and the outputs are $3, 5, 5, 7$. A linear RNN cannot do this, because the maximum is not a linear function of the prices.

>[!example] (Hard) Two Models With the Same Behavior
>Two engineers fit a two-state LTI model $\mathbf h_t = \mathbf A\mathbf h_{t-1} + \mathbf B u_t$, $y_t = \mathbf C\mathbf h_t$ to the same heater-to-temperature data. One finds the first set of matrices below, and the other finds the second set:
>$$\mathbf A = \begin{bmatrix} 0.5 & 0 \\ 0 & 0.9 \end{bmatrix}, \ \mathbf B = \begin{bmatrix} 1 \\ 1 \end{bmatrix}, \ \mathbf C = \begin{bmatrix} 1 & 1 \end{bmatrix}; \qquad \mathbf A' = \begin{bmatrix} 0.5 & 0.4 \\ 0 & 0.9 \end{bmatrix}, \ \mathbf B' = \begin{bmatrix} 2 \\ 1 \end{bmatrix}, \ \mathbf C' = \begin{bmatrix} 1 & 0 \end{bmatrix}.$$
>
>>[!example]- Do the two models disagree on any input? Which models could a learner that requires a diagonal $\mathbf A$ still confuse?
>>The first model has taps $\mathbf C\mathbf A^i\mathbf B = 0.5^i + 0.9^i$, which gives $2$, $1.4$, $1.06$ and $0.854$ for $i = 0$ to $3$. The second model gives the same taps. The reason is $\mathbf A' = \mathbf M\mathbf A\mathbf M^{-1}$, $\mathbf B' = \mathbf M\mathbf B$ and $\mathbf C' = \mathbf C\mathbf M^{-1}$ with $\mathbf M = \begin{bmatrix} 1 & 1 \\ 0 & 1 \end{bmatrix}$. Equal taps give equal outputs for every input sequence, so the data cannot choose between the models. A diagonal constraint on $\mathbf A$ rules out the second model. It still allows $\mathbf M = \mathrm{diag}(2, 1/3)$, which keeps $\mathbf A$ and gives $\mathbf B'' = [2, 1/3]^T$ and $\mathbf C'' = [0.5, 3]$. Swapping the two state coordinates is also allowed. Neither change alters any tap.
