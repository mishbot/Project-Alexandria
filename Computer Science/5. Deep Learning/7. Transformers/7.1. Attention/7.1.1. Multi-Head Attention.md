>[!note] Multi-Head Attention
>**Multi-head attention** runs $H$ [[7.1. Attention|attention]] lookups in parallel on the same input. Each lookup is a **head** with its own queries, keys and values. Head $h$ has projections $\mathbf W_q^{(h)}, \mathbf W_k^{(h)} \in \mathbb R^{D \times D_k}$ and $\mathbf W_v^{(h)} \in \mathbb R^{D \times D_v}$, usually with $D_k = D_v = D/H$. For input $\mathbf X \in \mathbb R^{N \times D}$, with biases left out,
>$$\mathbf H_h = \mathrm{softmax}\!\left(\frac{(\mathbf X\mathbf W_q^{(h)})(\mathbf X\mathbf W_k^{(h)})^T}{\sqrt{D_k}}\right)\mathbf X\mathbf W_v^{(h)} \in \mathbb R^{N \times D_v}.$$
>The head outputs are placed side by side and mixed by one more linear map $\mathbf W_o \in \mathbb R^{HD_v \times D}$:
>$$\mathrm{MHA}(\mathbf X) = \big[\mathbf H_1 \ \ \mathbf H_2 \ \cdots \ \mathbf H_H\big]\,\mathbf W_o \in \mathbb R^{N \times D}.$$
>Heads play the role that channels play in a CNN. One head returns one weighted average per token, and several heads can fetch several different things.
>
>A decoder that generates text stores the keys and values of all earlier tokens in a **KV cache**. Two variants make the cache smaller by sharing keys and values across heads:
>- **Multi-query attention (MQA)**: every head keeps its own query projection. All heads share one key projection and one value projection.
>- **Grouped-query attention (GQA)**: the $H$ query heads form $G$ groups, and each group shares one key and one value projection. $G = H$ gives standard multi-head attention, and $G = 1$ gives MQA.

# Intuition

A single head gives each token one convex combination of the values. A token often needs several facts at once. The Spring 2023 lecture 17 notes use verb agreement as the example. To conjugate a verb, the decoder may need the number and the gender of the subject. These facts can sit in different places. One head would have to blend these lookups into one average. With several heads, each lookup gets its own query and its own weights.

The channels of a CNN give the same picture. Different channels detect different patterns, and a max pool over each channel keeps its own strongest response. Different heads score the keys differently, so each head can attend to different tokens. Prince also notes that several heads seem to make training more robust to bad initializations.

Splitting $D$ into $H$ heads of size $D/H$ costs almost nothing extra. The projections have the same total size as one head of size $D$. The score computation also costs the same in total. Each of the $H$ heads works with vectors of length $D/H$.

# Properties

#### *(Parameter Count)* With $D_k = D_v = D/H$, a multi-head attention layer has $4D^2$ weights, whatever the number of heads.

The query projections of all heads together form one $D \times D$ matrix. The key projections and the value projections do too. That gives $3D^2$ weights. The output map $\mathbf W_o$ is $HD_v \times D = D \times D$, which adds $D^2$. The total is $4D^2$, and biases add $4D$ more. In practice one $D \times 3D$ matrix computes all queries, keys and values at once. The result is then split into $H$ blocks of $D/H$ columns each.

#### *(Concatenation Restores the Width)* The head outputs must add up to width $D$, so that the block's output can be added to its input.

A transformer block adds the attention output to its input through a residual connection. Each head returns $D_v$ numbers per token, and $\mathbf W_o$ maps $HD_v$ numbers back to $D$. The Spring 2023 lecture 17 notes make the same point. Each head's values should be $1/H$ the size of the input, so that $HD_v = D$.

#### *(Why the Keys and Values Can Be Cached)* In causal attention, a token's key and value never change after they are computed, so a decoder stores them.

To generate token $t + 1$, the decoder needs the query of token $t$. It also needs the keys and values of tokens $1$ to $t$. The causal mask means that token $i$'s keys and values depend only on tokens $1$ to $i$. They are the same at every later step. Without a cache, each step would recompute all earlier keys and values. With a cache, each step computes one new key and value per head and layer and appends them. The cache holds $2 \cdot L \cdot G \cdot D_k$ numbers per token, for $L$ layers and $G$ key-value heads. Standard multi-head attention has $G = H$.

#### *(Sharing Keys and Values)* MQA and GQA shrink the KV cache by the factor $H/G$, while every head keeps its own query.

In GQA, number the heads $h = 0, \dots, H - 1$ and the groups $g = 0, \dots, G - 1$. Head $h$ uses the keys and values of group $g = \lfloor hG/H \rfloor$. Its scores are
$$\mathbf S_h = \frac{(\mathbf X\mathbf W_q^{(h)})(\mathbf X\mathbf W_k^{(g)})^T}{\sqrt{D_k}}.$$
Heads in one group still produce different attention matrices, because their queries differ. They mix the same values, though. The lecture states the motivation as saving memory. During generation, reading the cache from memory takes much of the time per token. A smaller cache also lets more sequences fit on the GPU at once.

#### *(Converting a Trained Model)* A trained multi-head model can be converted to GQA by averaging its key and value projections within each group.

>[!warning] Not Taught in Lecture
>Uptraining follows Ainslie et al. (2023), who introduced GQA. MQA was introduced by Shazeer (2019).

The averaged projections give a GQA model that starts close to the original. It then trains for a small fraction of the original compute to recover quality. Ainslie et al. call this **uptraining**. Llama 2 70B and Mistral 7B are examples of models that use GQA with $8$ key-value heads.

# Examples

>[!example] (Easy) Shapes and Parameters
>A multi-head attention layer has $D = 512$ and $H = 8$ heads, and it reads $N = 10$ tokens.
>
>>[!example]- Give the shapes inside each head and of the layer output. Count the parameters.
>>Each head has $D_k = D_v = 512/8 = 64$. Its queries, keys and values are $10 \times 64$. Its score matrix and attention matrix are $10 \times 10$, and its output $\mathbf H_h$ is $10 \times 64$. The eight outputs side by side form a $10 \times 512$ matrix, and $\mathbf W_o$ maps it to $10 \times 512$. The layer has $4 \cdot 512^2 = 1{,}048{,}576$ weights and $4 \cdot 512 = 2048$ biases, so $1{,}050{,}624$ parameters.

>[!example] (Medium) Size of the KV Cache
>A decoder has $L = 32$ layers, $D = 4096$ and $H = 32$ heads of size $D_k = 128$. It holds a context of $T = 4096$ tokens in 16-bit floats, which take $2$ bytes each.
>
>>[!example]- Compute the cache size for one sequence with MHA, GQA with $G = 8$ and MQA. How large is the MHA cache for a batch of $16$ sequences?
>>The cache holds $2 \cdot L \cdot G \cdot D_k \cdot T$ numbers. With MHA, $G = 32$:
>>$$2 \cdot 32 \cdot 32 \cdot 128 \cdot 4096 = 1{,}073{,}741{,}824 \text{ numbers} = 2.15 \text{ GB}.$$
>>GQA with $G = 8$ stores a quarter of that, $268{,}435{,}456$ numbers or $0.54$ GB. MQA with $G = 1$ stores $33{,}554{,}432$ numbers or $0.067$ GB, which is $32$ times less than MHA. A batch of $16$ sequences with MHA needs $16 \cdot 2.15 = 34.4$ GB for the cache alone. That fills a large part of a GPU before any weights are loaded. The same batch fits in $1.1$ GB with MQA.

>[!example] (Hard) What GQA Saves in Parameters
>Take the decoder from the Medium example, with $D = 4096$ and $H = 32$ heads of size $128$. Compare MHA with GQA using $G = 8$.
>
>>[!example]- Count the attention weights per layer in both models. Show that two heads in the same GQA group can still attend to different tokens.
>>MHA has $4D^2 = 4 \cdot 4096^2 = 67{,}108{,}864$ weights per layer. In GQA, the query projection is still $D \times D$, with $16{,}777{,}216$ weights, and so is $\mathbf W_o$. The key projection has only $G = 8$ heads of size $128$, so it is $4096 \times 1024$, with $4{,}194{,}304$ weights. The value projection has the same size. The total is
>>$$2 \cdot 16{,}777{,}216 + 2 \cdot 4{,}194{,}304 = 41{,}943{,}040,$$
>>which is $37.5\%$ fewer than MHA.
>>
>>Head $h$ belongs to group $\lfloor 8h/32 \rfloor = \lfloor h/4 \rfloor$, so heads $0$ to $3$ form group $0$. They share the keys $\mathbf K_0$ and the values $\mathbf V_0$. Head $h$ in this group computes $\mathrm{softmax}(\mathbf Q_h\mathbf K_0^T/\sqrt{128})$. Two heads with different query projections give different score rows for the same token. One head can put its weight on the previous token while another puts it on the first token. Both outputs are then averages of the same value vectors $\mathbf V_0$, with different weights.
