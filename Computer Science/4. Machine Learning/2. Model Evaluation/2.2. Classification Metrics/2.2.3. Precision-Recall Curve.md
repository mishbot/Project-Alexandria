>[!note] Precision-Recall Curve
>The **precision-recall curve** (PR curve) plots precision against recall for a scoring classifier. The threshold $t$ sweeps from high to low. Recall is on the horizontal axis and precision on the vertical axis. Lowering $t$ flags more points, so recall never falls and precision usually does. This is the **precision-recall tradeoff**. At the lowest threshold every point is flagged. The curve then ends at recall 1 and precision $\pi$, the prevalence of positives. Precision is undefined until at least one point is flagged. By convention the curve starts at the precision of the top-ranked point.
>
>Precision at each threshold follows from the ROC rates and the prevalence:
>$$\text{precision}(t) = \frac{\pi\,\text{TPR}(t)}{\pi\,\text{TPR}(t) + (1 - \pi)\,\text{FPR}(t)}.$$
>Here TPR is the recall and FPR is the false positive rate from the [[2.2.1. Confusion Matrix|confusion matrix]]. For a fixed $\pi$, each ROC point maps to exactly one PR point. A random scorer has expected precision $\pi$ at every recall, so the **baseline** is a horizontal line at height $\pi$.
>
>**Average precision** (AP) summarizes the curve in one number. It sums the precision at each threshold, weighted by the gain in recall at that threshold:
>$$\text{AP} = \sum_{k} (R_k - R_{k-1})\,P_k = \frac{1}{n_+}\sum_{i:\, y_i = 1} \text{precision}@\text{rank}(i).$$
>Here $P_k$ and $R_k$ are the precision and recall at the $k$-th threshold, with $R_0 = 0$. The count $n_+$ is the number of positives. The second form averages, over the positives, the precision among the points ranked at or above each one.
>
>- **Range**: AP lies in $[0, 1]$. It is 1 for a perfect ranking and about $\pi$ for a random one.
>- **Name**: AP is often reported as **PR-AUC** or AUPRC.
>- **Interpolation**: the trapezoidal area under the PR points is a different number, because precision does not vary linearly between two points.
>- **Threshold**: the **maximum-$F_1$ threshold** is the point on the curve with the largest $F_1 = 2PR/(P + R)$. It is the usual choice when precision and recall matter equally.
>
>The PR curve is the preferred threshold-free summary when positives are rare and the top of the ranking matters most. Fraud alerts, search and screening for rare diseases are typical cases. The [[2.2.2. ROC Curve|ROC curve]] stays preferable when both classes matter or the prevalence differs between deployments.

# Intuition

The names come from information retrieval. A search engine's recall is the fraction of relevant documents it returns. Its precision is the fraction of returned documents that are relevant. The PR curve takes the viewpoint of whoever acts on the flagged cases. A fraud analyst who works down a ranked list of alerts catches more frauds with each step. Each step also adds legitimate transactions to review, and the curve records both effects together.

The curve never uses true negatives. In fraud detection or web search the negatives number in the millions, and almost all of them are easy. Dividing by that count keeps the false positive rate tiny, even when false alarms outnumber the real cases. Precision divides the false alarms by the number of flags, which stays small. The PR curve therefore changes sharply where the ROC curve moves only slightly to the right.

# Properties

#### *(Baseline Equals Prevalence)* A random scorer has AP close to $\pi$, so an AP value means little without the prevalence next to it.

An AP of 0.30 is a strong result when $\pi = 0.01$, thirty times the random baseline. The same AP is worse than random when $\pi = 0.5$. AP values from test sets with different prevalence cannot be compared directly. The same model scores a lower AP on a test set with fewer positives. Its ROC curve stays the same. Report AP together with $\pi$, or report the ratio $\text{AP}/\pi$. Benchmarks that balance the classes by subsampling negatives report an AP that will not hold at the real prevalence.

#### *(Why PR Beats ROC for Rare Positives)* With rare positives, a small false positive rate can yield more false alarms than true positives.

Suppose a fraud model reaches $\text{TPR} = 0.8$ at $\text{FPR} = 0.01$. With 1,000 frauds among 1,000,000 transactions, it flags 800 frauds and 9,990 legitimate transactions. The ROC point $(0.01, 0.8)$ looks excellent. The PR point $(0.8, 0.074)$ shows that about 93% of the alerts are false. ROC-AUC also gives equal weight to high-FPR regions that no fraud team would use. Saito and Rehmsmeier (2015) found that PR curves separate models on imbalanced data that ROC curves rate as nearly equal. Davis and Goadrich (2006) proved that one curve dominates another in ROC space exactly when it dominates in PR space. The two plots disagree only on how they weight the regions where neither model dominates.

#### *(Precision Is Not Monotone)* Precision can rise or fall as the threshold drops, so the PR curve zigzags.

Each positive added at the next threshold raises precision or keeps it at 1, and each negative lowers it. The ROC curve, by contrast, only moves up or right. Straight lines between PR points are wrong. Between two achievable points, true and false positives grow together, and precision follows a curve. Take 10 positives and two points on the curve. One has 5 true and 0 false positives, and the other has 10 true and 50 false. Recall goes from 0.5 to 1 and precision from 1 to 0.167. A straight line predicts precision 0.583 at recall 0.75. Interpolating the counts gives 7.5 true and 25 false positives, a precision of only 0.231. AP avoids interpolation by using the step sum, and libraries such as scikit-learn compute it that way.

#### *(The Max-F1 Threshold)* For calibrated probabilities, the threshold that maximizes $F_1$ equals half of the best $F_1$ (Lipton, Elkan and Naryanaswamy 2014).

Write $F_1 = 2\,TP/(2\,TP + FP + FN)$ and use $FN = n_+ - TP$. The denominator becomes the number of flagged points plus $n_+$. Flagging one more point with calibrated probability $p$ adds $p$ expected true positives and 1 to the denominator. The expected $F_1$ then rises exactly when $2p > F_1$. The optimal rule therefore flags every point with $p > F_1^*/2$, where $F_1^*$ is the best achievable $F_1$. Since $F_1^* \le 1$, the threshold never exceeds 0.5. When positives are rare and $F_1^*$ is low, the threshold falls well below 0.5. For uncalibrated scores, choose the threshold on a validation set instead.

# Examples

>[!example] (Easy) Average Precision for Ten Alerts
>A fraud model ranks ten transactions by score. Four of them are fraud. Write F for fraud and L for legitimate. From the top, the labels read F, L, F, F, L, L, F, L, L, L.
>
>>[!example]- Compute precision and recall at each cutoff, the average precision and the best $F_1$.
>>Flagging the top $k$ transactions for $k = 1, \dots, 10$ gives precision 1, 0.5, 0.667, 0.75, 0.6, 0.5, 0.571, 0.5, 0.444 and 0.4. Recall reaches 0.25 at the first fraud, 0.5 at the second, 0.75 at the third and 1 at the fourth. AP averages the precision at the four frauds, $(1 + 2/3 + 3/4 + 4/7)/4 = 0.747$. The $F_1$ score is largest at $k = 4$, where precision and recall both equal 0.75, so $F_1 = 0.75$. The cutoff $k = 7$ catches every fraud with $F_1 = 0.727$. The random baseline is the prevalence, $4/10 = 0.4$.

>[!example] (Medium) ROC and PR Disagree
>A test set has 1,000 legitimate transactions and 10 frauds, so $\pi \approx 0.0099$. Model A ranks five frauds at positions 1 to 5. It ranks the other five at positions 200, 250, 300, 350 and 400. Model B ranks its ten frauds at positions 30, 45, 60, ..., 165, in steps of 15. A fraud analyst reviews the top 20 alerts each day.
>
>>[!example]- Compute ROC-AUC and AP for both models. Which model should the analyst use?
>>For ROC-AUC, count the legitimate transactions ranked below each fraud. Model A's first five frauds beat all 1,000. The fraud at position 200 has 194 legitimate transactions above it, so it beats 806. The other four beat 757, 708, 659 and 610. Model A's AUC is $(5{,}000 + 3{,}540)/10{,}000 = 0.854$, and the same count gives 0.908 for Model B. For AP, Model A has precision 1 at each of its first five frauds. Its later frauds add $6/200 + 7/250 + 8/300 + 9/350 + 10/400 = 0.135$. Its AP is $(5 + 0.135)/10 = 0.514$. Model B's first fraud sits at position 30 with precision 0.033, and its AP is 0.053. ROC-AUC prefers Model B, while AP prefers Model A by a factor of ten. The analyst's top 20 alerts hold five frauds under Model A and none under Model B. AP weights the top of the ranking, which is where the analyst works.

>[!example] (Hard) The Max-F1 Threshold for a Readmission Model
>A hospital model sorts discharged patients into four groups with calibrated readmission probabilities 0.9, 0.6, 0.3 and 0.05. The groups hold 5%, 10%, 20% and 65% of patients. The hospital will phone the flagged patients and wants the largest $F_1$.
>
>>[!example]- Which groups should the hospital flag? Check the answer with the $F_1^*/2$ rule.
>>The prevalence is $0.05 \cdot 0.9 + 0.10 \cdot 0.6 + 0.20 \cdot 0.3 + 0.65 \cdot 0.05 = 0.1975$. Work per patient. Flagging only the 0.9 group gives expected $TP = 0.045$, $FP = 0.005$ and $FN = 0.1525$, so $F_1 = 0.09/0.2475 = 0.364$. Adding the 0.6 group gives $TP = 0.105$, $FP = 0.045$, $FN = 0.0925$ and $F_1 = 0.604$. Adding the 0.3 group gives $TP = 0.165$, $FP = 0.185$, $FN = 0.0325$ and $F_1 = 0.603$. Flagging everyone gives $F_1 = 0.330$. The best choice flags the top two groups, with $F_1^* = 0.604$. The rule flags a group exactly when its probability exceeds $F_1^*/2 = 0.302$. The 0.3 group falls slightly below this line, so adding it changes $F_1$ by only 0.0016. Any threshold above 0.3 and up to 0.6 flags the best groups, so the default of 0.5 also works here. The $F_1^*/2$ rule places the boundary at 0.302, well below 0.5.
