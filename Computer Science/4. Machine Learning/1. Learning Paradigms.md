>[!note] Learning Paradigms
>A **learning paradigm** describes what data a learner receives and what feedback tells it how well it is doing. Every paradigm fits a model $f_{\boldsymbol\theta}$ with parameters $\boldsymbol\theta$ by optimizing an objective computed from data. The paradigms differ in where the training signal comes from. Pick one from the data at hand:
>
>- **[[#Supervised Learning|Supervised learning]]**: every input $\mathbf{x}_i$ comes with a label $y_i$. Fit $f$ by minimizing the empirical risk $\hat R(f) = \frac{1}{n}\sum_i \ell(y_i, f(\mathbf{x}_i))$, where the loss $\ell$ scores one prediction.
>- **[[#Unsupervised Learning|Unsupervised learning]]**: there are inputs and no labels. Find structure, such as clusters, low-dimensional coordinates or a density $p_{\boldsymbol\theta}(\mathbf{x})$ fit by maximizing $\sum_i \log p_{\boldsymbol\theta}(\mathbf{x}_i)$.
>- **[[#Semi-Supervised Learning|Semi-supervised learning]]**: a few inputs have labels and many do not. Train on the labeled loss plus a term that uses the unlabeled inputs.
>- **[[#Self-Supervised Learning|Self-supervised learning]]**: there are no human labels. Targets are taken from the input itself, such as the next word or a hidden image patch. Train on these targets with supervised losses and reuse the learned representation.
>- **[[#Reinforcement Learning|Reinforcement learning]]**: an agent in state $s_t$ takes action $a_t$ and receives a scalar reward $r_t$. Learn a policy $\pi(a \mid s)$ that maximizes the expected discounted return $\mathbb{E}[\sum_t \gamma^t r_t]$, where $0 \le \gamma < 1$ is the discount factor.
>
>Supervised learning is the default whenever labels exist for the actual task. When labels are scarce and unlabeled inputs are plentiful, pretrain with self-supervision and fine-tune on the labels. Use unsupervised methods when the goal is structure in the data and no target exists. Use reinforcement learning when the learner's actions change the data it sees and feedback arrives as rewards.

# Intuition

The names describe the feedback. In supervised learning the labels play the role of a supervisor. The supervisor gives the right answer for each example (Prince, *Understanding Deep Learning*, section 1.1.3). Unsupervised learning has no supervisor, so the method itself must define what a good result is. Semi-supervised learning has a supervisor for a small part of the data. In self-supervised learning each example supplies its own target. Reinforcement learning takes its name from behavioral psychology, where a reward strengthens, or reinforces, the action that earned it.

The paradigms differ in how much a unit of feedback tells the learner and in what it costs. A label states the correct output for one input. It is the most direct feedback and the most expensive, since a person or a measurement must produce it. A reward is a single number, often delayed, about a whole sequence of actions. Unlabeled data are cheap and plentiful, but they do not say what is correct. Self-supervised and semi-supervised methods extract a training signal from unlabeled data, so a model needs fewer expensive labels.

# When to Use Which

Start from what the deployed model must do, then check which data exist. If labeled pairs exist for the exact task, train a supervised model and evaluate it on held-out labeled data. If labels exist only for a related task, fine-tune a model trained on that task, as in [[8.2. Transfer Learning]]. Suppose only a few hundred labels exist beside many unlabeled inputs. Then pretrain on all inputs with a self-supervised task and fine-tune on the labels. Add pseudo-labeling or consistency regularization when the unlabeled inputs come from the deployment distribution. If no target exists and the question concerns the data themselves, use unsupervised methods. If the model's outputs are actions whose results are scored only later, use reinforcement learning.

# The Paradigms

## Supervised Learning

Supervised learning fits a map from inputs to labels using $n$ labeled pairs $(\mathbf{x}_i, y_i)$. The type of $y$ names the task. A real number, such as a price, makes it **regression** ([[3. Regression]]). One of $K$ classes, such as spam or not spam, makes it **classification** ([[4. Classification]]). Outputs can also be structured, such as one class per pixel in segmentation or a sentence in translation. Training minimizes the empirical risk, while the real target is the population risk on new data, as [[2.3. Generalization]] explains. Four objects in a supervised project should be kept apart:

- **Intended outcome**: what should happen in deployment, such as users seeing little spam and losing no real mail.
- **Evaluation metric**: what will be measured, such as recall at a false-positive rate of $0.1\%$.
- **Training surrogate**: the loss that supplies a usable gradient, such as cross-entropy.
- **Update estimator**: how each update is computed, such as a gradient on a random minibatch in [[6.4.1. Stochastic Gradient Descent|SGD]].

The metric is often not differentiable, so the surrogate replaces it during training. A model can improve on the surrogate and still fail the intended outcome.

A **parametric** model has a fixed number of parameters that does not grow with $n$. Linear regression with $d + 1$ coefficients and a neural network of fixed size are parametric. After training, the data can be discarded. A **nonparametric** model grows with the data. [[4.5. k-Nearest Neighbors|k-NN]] stores every training point, and a decision tree can add leaves as $n$ grows. The name is misleading, since these models do have parameters. Their number is set by the data instead of fixed in advance. Nonparametric models assume less about the shape of $f$. They cost more memory and prediction time, and in high dimensions they need far more samples ([[7.2. Curse of Dimensionality]]).

## Unsupervised Learning

Unsupervised learning receives inputs $\mathbf{x}_1, \dots, \mathbf{x}_n$ and no labels. It describes the structure of the data instead of predicting a target. Five tasks are common:

- **Clustering** assigns each input to one of $K$ groups, as in [[6.1. K-Means]] and [[6.2. Gaussian Mixture Models]].
- **Dimensionality reduction** maps each input to $k < d$ coordinates that keep most of its information, as in [[7.1. Principal Component Analysis]] and [[6.2. Autoencoders|autoencoders]].
- **Density estimation** fits a probability model $p_{\boldsymbol\theta}(\mathbf{x})$, usually by maximum likelihood.
- **Generation** produces new samples that resemble the data, as in [[10.1. Generative Adversarial Networks|GANs]] and diffusion models. A density is one route to generation, and some generators define no density at all.
- **Anomaly detection** flags inputs that have low density or a large reconstruction error.

Without labels, there is no correct answer to compare against, so other criteria must be used. A probabilistic model is scored by its log-likelihood on held-out data (Prince, section 14.3). The training likelihood is not used, since a model can raise it by memorizing the training points. A clustering is judged by internal criteria, such as the within-cluster sum of squares or the silhouette score. Its stability across resamples is a second check. Dimensionality reduction uses reconstruction error on held-out data. Image generators are scored with sample-quality measures such as the Fréchet inception distance. When a downstream task exists, its accuracy is often the most useful score.

## Semi-Supervised Learning

>[!warning] Not Taught in Lecture
>Pseudo-labeling and consistency regularization follow Lee (2013), Laine and Aila (2017) and Sohn et al. (2020). Lecture covered only pretraining followed by fine-tuning.

Semi-supervised learning has $n_L$ labeled pairs and $n_U \gg n_L$ unlabeled inputs from the same distribution. A typical objective adds an unlabeled term to the supervised loss:
$$\min_{\boldsymbol\theta} \; \frac{1}{n_L}\sum_{i=1}^{n_L} \ell\big(y_i, f_{\boldsymbol\theta}(\mathbf{x}_i)\big) + \lambda\,\frac{1}{n_U}\sum_{j=1}^{n_U} u\big(f_{\boldsymbol\theta}, \mathbf{x}_j\big).$$
Here $u$ is a loss on one unlabeled input, and $\lambda > 0$ sets its weight. Unlabeled inputs help only if their distribution carries information about $P(y \mid \mathbf{x})$. The usual assumption is that the decision boundary passes through regions where inputs are rare. Two choices of $u$ are common:

- **Pseudo-labeling**: train on the labeled data, predict the unlabeled inputs, and keep confident predictions as labels. Wrong pseudo-labels can reinforce themselves, so a high confidence threshold such as $0.95$ is used.
- **Consistency regularization**: require the same prediction for two perturbed versions of one unlabeled input, such as two [[4.4.2. Data Augmentation|augmentations]]. The term $u$ is then a distance between the two outputs.

FixMatch combines the two. It takes a pseudo-label from a weakly augmented image and trains the prediction on a strongly augmented copy. In deep learning the most common route is **pretraining followed by fine-tuning**. A network first learns a representation from all inputs with a self-supervised task. It is then fine-tuned on the $n_L$ labels, as in [[8.2. Transfer Learning]].

## Self-Supervised Learning

Self-supervised learning uses unlabeled data with the mechanics of supervised learning. It splits each example into an input and a target, both computed from the example. A language model predicts each next word from the words before it. A masked model hides image patches or words and predicts them from the rest. The prediction problem is called a **pretext task**. The representation the network builds to solve it usually matters more than the task itself. That representation then serves a **downstream task** that may have few labels. No person writes the targets, so the method scales to billions of examples. [[9.1. LLMs|Large language models]] are trained this way. [[8.1. Self-Supervised Learning]] covers the pretext tasks in detail.

## Reinforcement Learning

Reinforcement learning trains an **agent** (Prince, section 1.3). At each step the agent observes a **state** $s_t$, takes an **action** $a_t$ and receives a **reward** $r_t$. It differs from supervised learning in three ways. The reward scores the chosen action without naming the best one. The reward may arrive many steps after the actions that earned it. The agent must then work out which actions deserve credit. This is the **temporal credit assignment** problem. The agent's own actions also decide which states it sees. It must therefore balance **exploitation** of actions known to pay off against **exploration** of untried ones. Deep reinforcement learning uses a neural network as the policy, mapping a state such as a chessboard to an action. The framework and its algorithms are covered in [[5.1. Reinforcement Learning]] and [[6.2. Markov Decision Processes]].

# Examples

>[!example] (Easy) Naming the Paradigm
>Name the paradigm in each scenario. For supervised ones, also say whether the task is regression or classification.
>
>1. A landlord predicts monthly rent from size and location, using $5{,}000$ past listings with their rents.
>2. A retailer groups $20{,}000$ shoppers by purchase history. Nobody has defined the groups.
>3. A warehouse robot learns to stack boxes. It gets $+1$ for each stack that stays up for ten seconds.
>4. A lab has $300$ lung scans labeled by radiologists and $40{,}000$ unlabeled scans from the same scanners.
>5. A company trains a network to predict the next word in two billion sentences from the web.
>6. An email provider trains a spam filter on messages that users marked as spam or moved back to the inbox.
>
>>[!example]- Which paradigm fits each scenario?
>>1. Supervised regression, since every listing has a numeric label.
>>2. Unsupervised clustering, since there is no target.
>>3. Reinforcement learning. The robot's actions change the stack, and the reward arrives after a sequence of moves.
>>4. Semi-supervised learning. Pretraining on the $40{,}000$ scans and fine-tuning on the $300$ labels is a strong default.
>>5. Self-supervised learning, since each target word comes from the text itself.
>>6. Supervised classification. Users create the labels as they use the product. The labels are noisy, but every message has one.

>[!example] (Medium) One Factory, Three Questions
>A factory records vibration and temperature from 500 machines every minute. It also logs every failure and its repair cost. Management asks three questions. How many hours remain until a given machine fails? Which machines behave unlike the others right now? When should each machine be serviced, given that servicing costs downtime and failures cost repairs?
>
>>[!example]- Which paradigm answers each question, and how should each answer be evaluated?
>>The first question is supervised regression. The failure log gives each past reading the label "hours until the next failure". The team should evaluate the model by RMSE with a split by time. It trains on earlier months and tests on later ones. The model will predict the future, so the test data must lie in the future of the training data.
>>
>>The second question is unsupervised anomaly detection. A density model or an [[6.2. Autoencoders|autoencoder]] is fit to readings from normal operation. Readings with low density or a high reconstruction error are flagged. No labels exist at prediction time, but the team can check the flags against the failure log afterward. A useful score is the fraction of flagged machines that fail within a week.
>>
>>The third question is reinforcement learning. A servicing decision changes which states the machine visits later, and its cost shows up only afterward. The team evaluates a servicing policy by its average total cost per machine over a long period. It first tests the policy in a simulator fit to the logs and then on a few real machines.
