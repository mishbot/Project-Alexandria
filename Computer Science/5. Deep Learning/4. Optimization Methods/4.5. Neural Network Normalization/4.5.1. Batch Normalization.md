>[!note] Batch Normalization
>**Batch normalization** (BatchNorm) standardizes each activation $h$ across the examples of a batch $\mathcal{B}$, then shifts and rescales it with learned parameters. It first computes the batch mean and standard deviation,
>$$m_h = \frac{1}{|\mathcal{B}|}\sum_{i \in \mathcal{B}} h_i, \qquad s_h = \sqrt{\frac{1}{|\mathcal{B}|}\sum_{i \in \mathcal{B}} (h_i - m_h)^2},$$
>where $h_i$ is the activation for example $i$. It then standardizes and rescales every example:
>$$h_i \leftarrow \frac{h_i - m_h}{s_h + \epsilon}, \qquad h_i \leftarrow \gamma\, h_i + \delta \qquad \forall i \in \mathcal{B}.$$
>Here $\epsilon > 0$ prevents division by zero when every example has the same value, and the scale $\gamma$ and offset $\delta$ are learned. After the operation the batch has mean $\delta$ and standard deviation $\gamma$. In a dense network each hidden unit has its own statistics and parameters, so $K$ layers of $D$ units add $2KD$ parameters. In a convolutional network the statistics of each channel are pooled over the batch and over all spatial positions, so $K$ layers of $C$ channels add $KC$ offsets and $KC$ scales. This version is sometimes called spatial batch normalization.
>
>At test time there may be no batch. The network then uses fixed statistics from one of three sources:
>- **Training-set averages**, computed over the whole training set after training.
>- **Running averages**, updated during training. PyTorch uses these.
>- **Held-out statistics**, computed on separate data.
>
>In a plain CNN, BatchNorm usually sits between a convolution and its ReLU. In a pre-activation [[5.2.5. Residual Networks|residual block]] it sits at the start of the block. **Ghost batch normalization** computes the statistics on a subset of the batch.
>
>BatchNorm has four benefits:
>- **Stable forward pass**: initializing $\delta = 0$ and $\gamma = 1$ gives every normalized activation unit variance.
>- **Higher learning rates**: training tolerates larger steps.
>- **Regularization**: the batch statistics add noise to every example.
>- **Smoother loss**: the loss and its gradient vary less.
>
>It also has three costs:
>- **Batch dependence**: each output depends on the other examples in the batch.
>- **Train-test mismatch**: training uses batch statistics, while testing uses fixed ones.
>- **Redundant parameters**: the mean subtraction cancels the bias of the preceding layer, and the scale of that layer's weights no longer affects the output.

>[!warning] Two Ways to Write the Same Layer
>The lecture and the textbook write $(h - m_h)/(s_h + \epsilon)$ with offset $\delta$. Implementations such as PyTorch, and the homework, write $\hat{x} = (x - \mu)/\sqrt{\sigma^2 + \epsilon}$ and $y = \gamma\hat{x} + \beta$, with $\epsilon$ inside the square root and $\beta$ as the offset. The two agree when $\epsilon \to 0$. The derivation below uses the implementation form.

# Intuition

A layer's input distribution changes every time the earlier layers update, and without control its scale can drift by a factor at each layer. BatchNorm measures where the batch currently sits and moves it back to mean zero and unit spread before the next layer sees it. The learned $\gamma$ and $\delta$ then put the activations wherever the network finds useful, so no expressive power is lost. Each example is standardized against the other examples in the same batch. That coupling is what makes the layer both a regularizer and a source of trouble.

# Properties

#### *(Invariance to Weight Scale)* The output of BatchNorm does not change when all the weights and the bias feeding an activation are multiplied by the same positive constant.

If the weights and bias that produce $h$ double, every $h_i$ doubles, $m_h$ doubles, $s_h$ doubles, and the standardized values stay the same. A whole family of weights therefore gives one function, and only the direction of each weight vector matters. Any bias before BatchNorm is also redundant, since subtracting $m_h$ removes it, and $\delta$ takes its role. Implementations therefore drop the bias of a convolution followed by BatchNorm. The scale invariance also decouples the size of the weights from the learning rate. Very aggressive learning-rate schedules, even exponentially growing ones, can still train.

#### *(Why It Works)* The evidence favors a smoother loss surface over the originally proposed reduction of internal covariate shift.

The original paper argued that BatchNorm reduces **internal covariate shift**, the change in each layer's input distribution caused by updates to earlier layers. A later experiment injected random covariate shift after BatchNorm and found that the networks trained equally well. The same study measured that BatchNorm makes the loss and its gradient change more slowly along the gradient direction. A smoother surface keeps the gradient informative after each step, so a larger learning rate is safe, and larger learning rates also tend to improve generalization. BatchNorm also reduces shattered gradients in deep networks. The full mechanism is still not well understood.

#### *(Batch Noise Regularizes)* Each example is normalized with statistics that depend on the other examples in its batch, which adds random noise during training.

The same image is standardized slightly differently on every step, depending on which images share its batch. This noise works like other noise injected during training, such as [[4.4.1. Dropout|dropout]], and it improves generalization. The amount of noise falls as the batch grows, since larger batches give more accurate statistics. Ghost batch normalization computes the statistics on sub-batches to keep the noise when very large batches are used for speed. Alternatives to BatchNorm that only fix the initialization usually generalize worse, probably because they lack this noise.

#### *(Train-Test Mismatch)* BatchNorm computes a different function at test time than during training, and it fails when the batch is too small.

During training the statistics come from the current batch, and at test time they are frozen. If the frozen statistics do not match the test data, accuracy drops. Small batches give noisy statistics. In a dense layer with a batch of one, $h_i - m_h = 0$ for every unit, so the output is the constant $\delta$ for any input, and no gradient reaches the earlier layers. A convolutional layer still pools over the $HW$ positions of the single image. Sequence models are awkward, because statistics would be needed for every time step, and a test sequence can be longer than every training sequence. Training split across several machines needs the statistics of the whole batch. These cases are why [[4.5.2. Layer Normalization|layer normalization]] and [[4.5.3. Group Normalization|group normalization]] exist.

# Derivation

We want the gradient of the loss with respect to each input of a BatchNorm layer during training. For one channel and a batch of $N$ values $x_1, \dots, x_N$ (for a convolution, $N$ counts examples times positions), the forward pass is
$$\mu = \frac{1}{N}\sum_{j=1}^{N} x_j, \qquad \sigma^2 = \frac{1}{N}\sum_{j=1}^{N} (x_j - \mu)^2, \qquad \hat{x}_i = \frac{x_i - \mu}{\hat{\sigma}}, \qquad y_i = \gamma\hat{x}_i + \beta,$$
where $\hat{\sigma} = \sqrt{\sigma^2 + \epsilon}$. Write $dy_i = \partial\mathcal{L}/\partial y_i$. The parameter gradients follow directly from the last equation:
$$\frac{\partial\mathcal{L}}{\partial \beta} = \sum_{i} dy_i, \qquad \frac{\partial\mathcal{L}}{\partial \gamma} = \sum_{i} dy_i\,\hat{x}_i, \qquad d\hat{x}_i = \gamma\, dy_i.$$
Each $x_i$ affects the loss through $\hat{x}_i$ directly and through $\mu$ and $\sigma^2$, which every $\hat{x}_j$ uses. The figure shows the computational graph for a batch of three. The paths that start at $x_1$ are red. The paths through $\mu$ and $\sigma^2$ reach every $\hat{x}_j$, so the gradient for $x_1$ collects a sum over all $j$.

By the chain rule,
$$d\sigma^2 = -\frac{1}{2\hat{\sigma}^3}\sum_{j} d\hat{x}_j\,(x_j - \mu), \qquad d\mu = -\frac{1}{\hat{\sigma}}\sum_{j} d\hat{x}_j,$$
where the contribution of $\mu$ through $\sigma^2$ vanishes because $\sum_j (x_j - \mu) = 0$. Collecting the three paths,
$$dx_i = \frac{d\hat{x}_i}{\hat{\sigma}} + d\sigma^2\,\frac{2(x_i - \mu)}{N} + \frac{d\mu}{N}.$$
Substituting and writing $x_i - \mu = \hat{\sigma}\hat{x}_i$ gives the closed form
$$\frac{\partial \mathcal{L}}{\partial x_i} = \frac{\gamma}{N\hat{\sigma}}\Big(N\,dy_i - \sum_{j=1}^{N} dy_j - \hat{x}_i\sum_{j=1}^{N} dy_j\,\hat{x}_j\Big).$$
Two consequences follow by summing. The input gradients add to zero, $\sum_i \partial\mathcal{L}/\partial x_i = 0$, and they are orthogonal to the standardized values, $\sum_i \hat{x}_i\,\partial\mathcal{L}/\partial x_i = 0$. Shifting or rescaling the whole batch does not change the output, so the gradient has no component in those two directions. With $N = 1$, as in a dense layer with a batch of one, the bracket is $dy_1 - dy_1 - 0 = 0$, which matches the batch-of-one failure above.

# Examples

>[!example] (Easy) Normalizing a Batch
>One hidden unit takes the values $h = [2, 4, 6, 8]$ on a batch of four examples. Its BatchNorm layer has $\gamma = 2$ and $\delta = 1$, and $\epsilon$ is negligible.
>
>>[!example]- Compute the output.
>>The mean is $m_h = 5$, and the standard deviation is $s_h = \sqrt{(9 + 1 + 1 + 9)/4} = \sqrt{5} \approx 2.236$. Standardizing gives $[-1.342, -0.447, 0.447, 1.342]$. Scaling by $2$ and adding $1$ gives $[-1.683, 0.106, 1.894, 3.683]$, which has mean $1 = \delta$ and standard deviation $2 = \gamma$. The spacing between examples is kept, and only the location and scale change.

>[!example] (Medium) A Weight Whose Size Does Not Matter
>A unit computes $h = w\,x$ from a scalar input and feeds BatchNorm. A batch has inputs $x = [1, 2, 3]$.
>
>>[!example]- Compare the normalized outputs for $w = 2$ and $w = 6$. What does this mean for the gradient with respect to $w$? What changes with two inputs?
>>For $w = 2$ the values are $[2, 4, 6]$, and for $w = 6$ they are $[6, 12, 18]$. Both have the standardized form $[-1.225, 0, 1.225]$, so the output is identical. With one input, BatchNorm output depends only on the sign of $w$, and the gradient with respect to $w$ is zero apart from the effect of $\epsilon$. With two inputs, $h = w_1 x_1 + w_2 x_2$, the output depends only on the direction of $(w_1, w_2)$. The gradient is then perpendicular to $(w_1, w_2)$, and its size falls in proportion to $1/\|(w_1, w_2)\|$. Larger weights therefore learn more slowly, which acts like an automatic reduction of the learning rate.

>[!example] (Hard) Backpropagating Through BatchNorm
>A batch of three values $x = [1, 2, 6]$ passes through BatchNorm with $\gamma = 1$, $\beta = 0$ and negligible $\epsilon$. The upstream gradient is $dy = [1, 0, 0]$, so the loss depends only on the first output.
>
>>[!example]- Compute $\partial\mathcal{L}/\partial x_i$ for each input and check the two sum rules.
>>The mean is $\mu = 3$ and the variance is $\sigma^2 = (4 + 1 + 9)/3 = 14/3$, so $\hat{\sigma} = 2.160$ and $\hat{x} = [-0.926, -0.463, 1.389]$. The sums are $\sum_j dy_j = 1$ and $\sum_j dy_j\,\hat{x}_j = -0.926$. The closed form gives
>>$$\frac{\partial\mathcal{L}}{\partial x} = \frac{1}{3 \cdot 2.160}\big([3, 0, 0] - [1, 1, 1] + 0.926\,[-0.926, -0.463, 1.389]\big) = [0.176, -0.220, 0.044].$$
>>The entries add to zero, and $0.176 \cdot (-0.926) - 0.220 \cdot (-0.463) + 0.044 \cdot 1.389 = 0$ up to rounding. A finite-difference check gives the same values. Without BatchNorm the gradient would be $[1, 0, 0]$. Raising $x_2$ lowers the first output because it raises the batch mean, and raising $x_3$ changes it through both the mean and the spread.
