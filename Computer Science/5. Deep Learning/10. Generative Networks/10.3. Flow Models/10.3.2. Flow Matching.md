>[!note] Flow Matching
>**Flow matching** trains a neural network to move samples of Gaussian noise to samples of a data distribution $q$ along a learned velocity field. Time runs from $t = 0$ (pure noise) to $t = 1$ (clean data). A noise sample $x_0 = \epsilon \sim \mathcal{N}(0, I)$ has the same shape as a data sample $x_1 \sim q$, for example $1 \times 28 \times 28$ for an MNIST digit. Training builds a noisy input by linear interpolation:
>$$x_t = (1 - t)\,x_0 + t\,x_1, \qquad t \sim \mathcal{U}[0, 1].$$
>Smaller $t$ means more noise. For a fixed pair $(x_0, x_1)$, the point $x_t$ moves on a straight line at constant velocity. This velocity is the **conditional flow**, conditioned on the single data point $x_1$:
>$$u_t(x_t \mid x_1) = \frac{d x_t}{dt} = x_1 - x_0 = \frac{x_1 - x_t}{1 - t}.$$
>The network $v_\theta(x_t, t)$ is trained with the **conditional flow matching loss**
>$$\mathcal{L}_{\text{CFM}}(\theta) = \mathbb{E}_{t,\, x_0,\, x_1} \big\| v_\theta(x_t, t) - (x_1 - x_0) \big\|^2 .$$
>A conditional model $v_\theta(x_t, t, c)$ also receives a condition $c$, such as a class label or a text prompt.
>
>The velocity we want is the **marginal flow** $u_t(x)$, which carries the whole noise distribution onto $q$. It averages the conditional flows over all data points, weighted by how likely each one is to have produced $x$:
>$$u_t(x) = \mathbb{E}\big[u_t(X_t \mid X_1) \,\big|\, X_t = x\big] = \sum_{x_1} u_t(x \mid x_1)\,\frac{p_t(x \mid x_1)\, q(x_1)}{p_t(x)} .$$
>Here $p_t(x \mid x_1) = \mathcal{N}\big(x;\ t x_1,\ (1-t)^2 I\big)$ is the distribution of $x_t$ given $x_1$, and $p_t(x) = \sum_{x_1} p_t(x \mid x_1)\, q(x_1)$. The sum becomes an integral when $q$ is continuous. The **flow matching loss** $\mathcal{L}_{\text{FM}}(\theta) = \mathbb{E}_{t,\, x_t} \| v_\theta(x_t, t) - u_t(x_t) \|^2$ cannot be computed, because $u_t$ is unknown. The theorem $\nabla_\theta \mathcal{L}_{\text{FM}} = \nabla_\theta \mathcal{L}_{\text{CFM}}$ guarantees that training on per-sample targets learns $u_t$ anyway.
>
>Sampling draws $x_0 \sim \mathcal{N}(0, I)$ and integrates the deterministic ODE $dx/dt = v_\theta(x, t)$ from $t = 0$ to $t = 1$. The usual solver is Euler's method with step size $h$:
>$$x_{t+h} = x_t + h\, v_\theta(x_t, t).$$
>A single evaluation also gives the **one-step estimate** of the clean image, $\hat{x}_1 = x_t + (1 - t)\, v_\theta(x_t, t)$. It is blurry for small $t$ and sharp near $t = 1$. The network is usually a [[6.4. U-Net]]. Steering samples toward a condition is the subject of [[10.3.2. Classifier-Free Guidance]].

>[!warning] Time Runs the Other Way in DDPM Notation
>[[10.3.1. Diffusion Models|DDPM-style diffusion]] writes $x_0$ for the clean image and $x_T$ for pure noise, and its network predicts the noise $\epsilon$. Flow matching writes $x_0$ for noise and $x_1$ for the clean image, and its network predicts a velocity. Under the interpolation above the three common predictions convert into each other at fixed $(x_t, t)$: $\hat{x}_1 = x_t + (1-t)\,v$, $\epsilon = x_t - t\,v$, and $v = (x_t - \epsilon)/t$. The last formula divides by $t$ and breaks down at $t = 0$.

>[!warning] Names for the Velocity Network
>The lecture's loss slides write the network as $u_t^\theta(X_t)$, and its sampling slides and Project 3 Part A write $v_\theta(x_t, t, c)$. Project 3 Part B and the discussion worksheets write $u_\theta(x_t, t)$. All of these denote the same trained network. This note keeps $u_t$ for the exact target fields and $v_\theta$ for the network.

# Intuition

Turning noise into a realistic image in one step is hard. The reverse direction is easy, since adding enough noise destroys any image. Locally the two directions are almost reversible. A slightly noisy image can be cleaned up well. Flow matching uses this asymmetry. It defines a path from noise to data and trains a network to take small steps along it. A single big step does not work. Project 3 trains a [[6.4. U-Net]] with an L2 loss to map pure noise straight to MNIST digits, and the outputs look like one blurry average of all digits. The input carries no information about which digit to produce, so the [[2.1.1. Mean Squared Error|L2]]-optimal output is the mean of the training set.

During training, the data point $x_1$ behind each noisy input is known, so the target $x_1 - x_0$ is exact. During sampling it is unknown, and many data points could have produced the same $x_t$. The network therefore sees one input with several targets. Under the L2 loss it learns their average, weighted by the posterior probability of each data point given $x_t$, as computed by [[1.6 Bayes' Rule|Bayes' rule]]. The average is called *marginal* because the data point is averaged out, as in a marginal distribution. A **flow** is the motion of points under a velocity field, and *matching* means regressing the network's velocity onto a target velocity. The figure shows the 1D case with two data points at $\pm 1$. The two conditional paths through $(t, x) = (0.5, 0.5)$ have slopes $1$ and $-3$. The marginal velocity $0.52$ is their average with weights $0.88$ and $0.12$. The gray curves are the marginal paths that the sampler follows.

# Properties

#### *(Training and Sampling Loops)* Training draws a random time at every step, while sampling visits all times in order.

The training loop never runs the sampler. Each step draws an image, a time and a noise tensor, and regresses on one velocity. In PyTorch the loop reads:
```python
x = next(dataset)                      # clean image x_1
t = torch.rand(1)                      # t ~ U[0, 1]
noise = torch.randn_like(x)            # x_0 ~ N(0, I)
x_t = (1 - t) * noise + t * x          # noisy input
flow_pred = model(x_t, t)              # v_theta(x_t, t)
flow_gt = x - noise                    # target x_1 - x_0
loss = F.mse_loss(flow_pred, flow_gt)
loss.backward()
optimizer.step()
```
Sampling starts from pure noise and takes `steps` Euler steps of size `dt = 1/steps`:
```python
x_t = torch.randn_like(x)              # x_0 ~ N(0, I)
steps = 100
dt = 1.0 / steps
for i in range(steps):
    t = i * dt
    velocity = model(x_t, t)           # v_theta(x_t, t)
    x_t = x_t + dt * velocity
```
Each Euler step costs one network evaluation. Project 3 Part A uses $h = 0.02$, so generation from pure noise takes $50$ evaluations, and denoising an image from $t = 0.5$ takes $25$. Noise is drawn fresh for every batch, so the network never sees the same noisy input twice.

#### *(One-Step Estimate Is a Posterior Mean)* With the exact marginal flow, the one-step estimate equals $\mathbb{E}[X_1 \mid X_t = x_t]$, the average of all plausible clean images.

Solving the interpolation for the noise gives $x_0 = (x_t - t x_1)/(1 - t)$. Taking the conditional expectation of $x_1 - x_0$ given $x_t$ yields $u_t(x_t) = \big(\mathbb{E}[X_1 \mid X_t = x_t] - x_t\big)/(1 - t)$, so $x_t + (1 - t)\,u_t(x_t) = \mathbb{E}[X_1 \mid X_t = x_t]$. At small $t$ the likelihood $p_t(x \mid x_1)$ is close to $\mathcal{N}(0, I)$ for every $x_1$. The posterior then stays close to $q$, and the estimate is close to the mean of the whole dataset. This explains why early one-step predictions look like Galton's composite portraits (Galton, 1878), which average many faces into one blurry face. As $t$ grows, the Gaussians narrow (standard deviation $1 - t$) and their centers $t x_1$ separate. The posterior concentrates on a subpopulation, and the estimate becomes the mean of that subpopulation. Near $t = 1$ it concentrates on one image and the estimate turns sharp. Colorization with an L2 loss shows the same averaging, as described in [[8.3. Image Colorization]].

#### *(Straight Conditional, Curved Marginal Paths)* Every training pair moves on a straight line, yet sampling trajectories curve.

The marginal velocity depends on $(x, t)$ through the posterior weights, and these weights change along the path. A trajectory first heads toward the dataset mean, while all data points are still plausible. It then turns toward one region of the data once the posterior commits. This curvature is why a single Euler step from noise gives the blurry mean and why the step size matters. The ODE trajectories never cross, since the velocity at a point is unique. In 1D they therefore keep their order, so the lowest noise values end at the lowest data values.

#### *(Training Averages Targets by Frequency)* At each $(x_t, t)$ the network converges to the average of the training targets, weighted by how often each target occurs.

Consider data at $A = +0.5$ and $B = -0.5$ with probability $1/2$ each. At $t = 0$ and $x_t = 0.5$, both data points need the same noise $\epsilon = 0.5$, so the targets $A - 0.5 = 0$ and $B - 0.5 = -1$ appear equally often, and $v_\theta(0.5, 0) \to -0.5$. At $t = 0.5$ and $x_t = 0$, the targets $+1$ and $-1$ are equally likely, and $v_\theta(0, 0.5) \to 0$. At $t = 0.9$ and $x_t = 0.5$, reaching $B$ needs $\epsilon = 9.5$, more than nine standard deviations. Target $A$ dominates, and $v_\theta(0.5, 0.9) \approx 0$. The frequencies follow $q$ as well as the Gaussian. Duplicating $A$ in the dataset makes the sampler produce $A$ twice as often as $B$.

#### *(Exact Minimizer Memorizes)* The loss can be minimized perfectly without a network, and the result can only reproduce training images.

For a finite training set, the marginal flow formula can be evaluated directly by summing over all training images. This non-parametric velocity minimizes the loss exactly. Near $t = 1$ its posterior collapses onto the nearest training image, so every sample is a copy of a training image. Minimizing the objective alone therefore guarantees neither interpolation between images nor new combinations of content. A neural network cannot represent this sum exactly. Its smoothing is what produces new images, and why this works is still an open research question.

#### *(Train/Test Mismatch)* The network is trained on exact interpolations of real images but tested on its own trajectories.

Training inputs are $x_t = (1 - t)x_0 + t x_1$ with a real $x_1$ and fresh Gaussian noise. Sampling inputs are Euler iterates $x_{t+h} = x_t + h\,v_\theta(x_t, t)$, which carry the network's earlier errors and the discretization error. These inputs can drift away from the distribution the network was trained on. In machine learning one normally trains on the same distribution one tests on. Flow and diffusion models break this rule and still work reasonably well. Smaller steps reduce the discretization part of the error at the cost of more network evaluations.

#### *(One Family of Schedules)* DDPM, DDIM, VP and VE ODEs, flow matching and rectified flow differ mainly in how $x_t$ mixes noise and data.

A general path writes $x_t = a_t\,x_0 + b_t\,x_1$ with schedule functions $a_t$ and $b_t$. Linear interpolation ($a_t = 1 - t$, $b_t = t$) gives flow matching and rectified flow. A **variance-preserving** (VP) schedule keeps $a_t^2 + b_t^2 = 1$, as in DDPM. A **variance-exploding** (VE) schedule keeps the image unscaled and adds noise of growing size, $x_{\text{clean}} + \sigma\,\epsilon$. The choices differ in time steps and image scaling, and some train or sample better than others. DDIM and EDM are further choices of time steps and samplers within the same family. The training target can be the clean image ($\|x_{\text{clean}} - \hat{x}\|^2$), the noise ($\|\epsilon - \hat{\epsilon}\|^2$, as in diffusion) or the velocity ($\|v - \hat{v}\|^2$ with $v = x_{\text{clean}} - \epsilon = (x_{\text{clean}} - x_t)/(1 - t)$). At fixed $(x_t, t)$ the three targets are affine functions of each other.

#### *(Deterministic Versus Stochastic Sampling)* A flow sampler maps each noise sample to one fixed image, while a DDPM sampler re-injects noise along the way.

Flow sampling integrates an ODE, so the same $x_0$ always gives the same image, and the trajectory is smooth. A DDPM sampler takes one step that reduces the noise and then adds a little fresh noise back. Its trajectories therefore wiggle, and the same starting noise can end at different images. Both procedures carry the noise distribution to the data distribution. Project 3 Part A builds its editing applications on the deterministic Euler sampler, as described in [[8.6. Flow-Based Image Editing]].

# Derivation

We want to show that $\mathcal{L}_{\text{CFM}}$ and $\mathcal{L}_{\text{FM}}$ differ by a constant that does not depend on $\theta$. Fix $t$ and write $v = v_\theta(X_t, t)$, $u_c = u_t(X_t \mid X_1)$ and $u = u_t(X_t)$. Expanding both squared errors with the [[3.4a Inner Product|inner product]] gives
$$\|v - u_c\|^2 = \|v\|^2 - 2\langle v, u_c\rangle + \|u_c\|^2, \qquad \|v - u\|^2 = \|v\|^2 - 2\langle v, u\rangle + \|u\|^2.$$
The first terms are identical. For the cross terms, condition on $X_t$. The network output $v$ depends only on $X_t$, so by the tower property of [[2.5a Expectation|expectation]] and the definition of $u$,
$$\mathbb{E}\,\langle v, u_c\rangle = \mathbb{E}\,\big\langle v,\ \mathbb{E}[u_c \mid X_t]\big\rangle = \mathbb{E}\,\langle v, u\rangle .$$
The last terms $\|u_c\|^2$ and $\|u\|^2$ do not involve $\theta$. Hence $\mathcal{L}_{\text{CFM}}(\theta) = \mathcal{L}_{\text{FM}}(\theta) + C$ with $C$ independent of $\theta$, and $\nabla_\theta \mathcal{L}_{\text{FM}} = \nabla_\theta \mathcal{L}_{\text{CFM}}$. The same expansion shows that the best function of $X_t$ is $\mathbb{E}[u_c \mid X_t] = u_t(X_t)$. This is the general fact that L2 regression learns a conditional mean. It matches the marginal flow formula in the callout.

# Examples

>[!example] (Easy) Plugging a Noise Predictor into a Flow Sampler
>A classmate has a pretrained network $\epsilon_\theta(x_t, t)$ that predicts the noise in $x_t$, as diffusion models do. Assume it was trained on the same interpolation $x_t = (1 - t)\epsilon + t\,x_{\text{clean}}$. They want to reuse the Euler sampler from Project 3, which expects a velocity. At one pixel, $x_t = 0.2$ at $t = 0.6$, and the network predicts $\hat{\epsilon} = -0.7$.
>
>>[!example]- Convert the prediction to a velocity, take one Euler step with $h = 0.1$, and find the one-step estimate. What goes wrong near $t = 0$?
>>The velocity is $u = x_{\text{clean}} - \epsilon$, so $x_{\text{clean}} = u + \epsilon$. Substituting into the interpolation gives $x_t = (1 - t)\epsilon + t(u + \epsilon) = \epsilon + t\,u$. Therefore $u = (x_t - \epsilon)/t = (0.2 + 0.7)/0.6 = 1.5$. The Euler step gives $x_{0.7} = 0.2 + 0.1 \cdot 1.5 = 0.35$. The one-step estimate is $\hat{x}_1 = 0.2 + 0.4 \cdot 1.5 = 0.8$. Solving the interpolation for the clean value gives the same number, $(x_t - (1 - t)\hat{\epsilon})/t = (0.2 + 0.28)/0.6 = 0.8$.
>>
>>The conversion divides by $t$. An error $\delta$ in $\hat{\epsilon}$ becomes an error $\delta/t$ in the velocity, so at $t = 0.01$ an error of $0.01$ grows to $1$. At $t = 0$ we have $x_t = \epsilon$ exactly. A perfect noise predictor returns $\hat{\epsilon} = x_t$, and the formula gives $0/0$. The noise prediction at $t = 0$ carries no information about the data, while the true velocity $u_0(x) = \mathbb{E}[x_1] - x$ does. The converted sampler must therefore start at a small $t > 0$.

>[!example] (Medium) Marginal Velocity for a Two-Point Dataset
>A 1D dataset holds two values, $x_1 = +1$ and $x_1 = -1$, each with probability $1/2$. Think of one pixel that is either white or black after normalization. Noise is $x_0 \sim \mathcal{N}(0, 1)$.
>
>>[!example]- Compute the posterior weights, the marginal velocity $u_t(x)$ and the one-step estimate $\hat{x}_1$ at $(x, t) = (0.5, 0)$, $(0.5, 0.5)$ and $(-0.2, 0.8)$.
>>Given $x_1$, the noisy value is $x_t \sim \mathcal{N}\big(t x_1, (1-t)^2\big)$. The ratio of the two Gaussian likelihoods is
>>$$\frac{p_t(x \mid {+1})}{p_t(x \mid {-1})} = \exp\!\Big(\frac{2 t x}{(1-t)^2}\Big).$$
>>The posterior weight of $+1$ is therefore $w_+ = 1/\big(1 + e^{-2tx/(1-t)^2}\big)$, and $w_- = 1 - w_+$. The conditional velocities are $(1 - x)/(1-t)$ and $(-1 - x)/(1-t)$. The marginal velocity is their weighted sum, and the one-step estimate simplifies to $\hat{x}_1 = x + (1-t)\,u_t(x) = w_+ - w_-$.
>>
>>| $(x, t)$ | $w_+$ | $w_-$ | conditional velocities | $u_t(x)$ | $\hat{x}_1$ |
>>|---|---|---|---|---|---|
>>| $(0.5, 0)$ | $0.500$ | $0.500$ | $0.5$ and $-1.5$ | $-0.500$ | $0.000$ |
>>| $(0.5, 0.5)$ | $0.881$ | $0.119$ | $1$ and $-3$ | $0.523$ | $0.762$ |
>>| $(-0.2, 0.8)$ | $0.0003$ | $0.9997$ | $6$ and $-4$ | $-3.997$ | $-0.999$ |
>>
>>At $t = 0$ the noise does not depend on the data. The weights equal the prior, the velocity points at the dataset mean $0$, and the one-step estimate is that mean. This is the 1D version of a blurry average image. At $t = 0.5$ the value $0.5$ is $e^2 \approx 7.4$ times as likely under $+1$, so the estimate moves to $0.762$. At $t = 0.8$, producing $-0.2$ from $+1$ needs $\epsilon = -5$, while producing it from $-1$ needs $\epsilon = 3$. The likelihood ratio is $e^{-8}$, and the estimate is almost exactly $-1$. In closed form, $\hat{x}_1 = \tanh\big(t x/(1-t)^2\big)$.

>[!example] (Hard) Four Euler Steps on the Two-Point Dataset
>Use the same dataset and the exact marginal velocity $u_t(x) = \big(\tanh(tx/(1-t)^2) - x\big)/(1 - t)$ from the previous example. A sampler starts at $x_0 = 0.3$ and takes four Euler steps of size $h = 0.25$.
>
>>[!example]- Compute the four steps, compare them with the exact ODE trajectory, and explain the shape of the path.
>>
>>| $t$ | Euler $x_t$ | $u_t(x_t)$ | exact $x_t$ |
>>|---|---|---|---|
>>| $0$ | $0.300$ | $-0.300$ | $0.300$ |
>>| $0.25$ | $0.225$ | $-0.167$ | $0.238$ |
>>| $0.5$ | $0.183$ | $0.335$ | $0.244$ |
>>| $0.75$ | $0.267$ | $2.919$ | $0.570$ |
>>| $1$ | $0.997$ | | $1$ |
>>
>>The path first moves toward the dataset mean $0$ and then turns toward $+1$. Early on both data points are plausible, and their pulls nearly cancel. Later the posterior commits to $+1$. At $t = 0.75$ Euler lags well behind the exact path ($0.267$ against $0.570$). Each step reuses the velocity from the start of the step over a long interval. The last step still ends near $+1$. Its size $h = 1 - t$ makes it a one-step estimate, and with the exact velocity this estimate is the posterior mean $\tanh(0.75 \cdot 0.267/0.0625) = 0.997$. With $100$ steps, Euler ends at $1.000$. Every start $x_0 > 0$ ends at $+1$ and every start $x_0 < 0$ ends at $-1$, which sends half of the noise to each data point, as $q$ requires. A trained network replaces the exact velocity, so its own errors add to the Euler error.
