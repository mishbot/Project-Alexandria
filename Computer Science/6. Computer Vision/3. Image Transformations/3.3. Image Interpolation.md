>[!note] Image Interpolation
>**Interpolation** estimates pixel values at non-integer coordinates when transforming or resizing images. It is essential in [[3.2. Image Warping|inverse warping]], where the transformed coordinate $(x, y)$ usually does not align with integer pixel positions. Let $f(i, j)$ be the stored value at integer column $i$ and row $j$. Interpolation defines a function $\ell(x, y)$ of continuous coordinates that uses the discrete samples $f$ as its parameters.
>
>**Nearest neighbor interpolation** assigns to the new location the value of the pixel at the nearest integer position, found by rounding:
>$$\ell_{\text{NN}}(x, y) = f(\lfloor x+0.5 \rfloor, \lfloor y+0.5 \rfloor).$$
>It is the fastest method, but it often produces blocky or jagged edges due to intensity jumps.
>
>**Bilinear interpolation** adds smoothing by using the four pixels around $(x, y)$. Let $x_0 = \lfloor x \rfloor$, $y_0 = \lfloor y \rfloor$, $\Delta x = x - x_0$ and $\Delta y = y - y_0$, so that $\Delta x, \Delta y \in [0, 1)$. Then
>$$\ell_{\text{Bil}}(x, y) = (1 - \Delta x)(1 - \Delta y)\,f(x_0, y_0) + \Delta x(1 - \Delta y)\,f(x_0 + 1, y_0) + (1 - \Delta x)\Delta y\,f(x_0, y_0 + 1) + \Delta x\,\Delta y\,f(x_0 + 1, y_0 + 1).$$
>The four weights are non-negative and sum to $1$, so the result is a weighted average of the four neighbors. It equals linear interpolation along $x$ on both rows, followed by linear interpolation along $y$ (or the other order). The result is continuous, but its slope jumps at pixel borders.
>
>The lecture also lists **Gaussian** interpolation, a Gaussian-weighted average of nearby pixels that blurs slightly. **Bicubic** interpolation fits cubics through a $4 \times 4$ neighborhood. It is smoother and sharper than bilinear, at a higher cost. Library versions are MATLAB's `interp2`, `scipy.ndimage.map_coordinates` (`order=0` nearest, `order=1` bilinear, `order=3` cubic) and `cv2.remap`.

>[!warning] $f(x, y)$ Versus `img[y, x]`
>The formulas above put the column $x$ first. NumPy arrays put the row first, so $f(x, y)$ is `img[y, x]`, and `map_coordinates` expects coordinates in (row, column) order. Swapping the two gives a plausible but wrong number with no error message. The first example below shows the size of the mistake.

# Intuition

A digital image stores values only at grid points. Any value between them is a guess about what the underlying scene did between samples, which is the reconstruction problem of [[2.3. Resampling|resampling]]. Nearest neighbor guesses that the image is constant around each sample, so it copies the closest one. Bilinear guesses that the image changes linearly between neighbors. Its weights have a simple picture. Draw the point inside the cell of four pixels, and split the cell into four rectangles through the point. Each corner gets the area of the rectangle on the opposite side of the point. As the point moves toward a corner, the rectangle opposite that corner grows, and so does its weight.

# Properties

#### *(Exact on Ramps)* Bilinear interpolation reproduces any image of the form $a + bx + cy$ exactly, and it never leaves the range of its four neighbors.

The weights form an average that is linear in $\Delta x$ along each row and linear in $\Delta y$ along each column. A linear ramp therefore comes back unchanged, which the second example below checks. Since all four weights are non-negative and sum to $1$, the output lies between the smallest and largest of the four corner values. The term $\Delta x\,\Delta y$ makes the surface curved along diagonals. With corners $0, 0, 0$ and $f(x_0{+}1, y_0{+}1) = 1$, the value along the diagonal $\Delta x = \Delta y = s$ is $s^2$. The method is linear in each coordinate separately, which is what "bilinear" means.

#### *(Interpolation as Filtering)* Nearest neighbor and bilinear interpolation are convolutions of the samples with a box kernel and a tent kernel.

The nearest-neighbor kernel is a box of width one pixel, so each sample spreads into a flat square. The bilinear kernel is the tent $\max(0, 1 - |x|)\max(0, 1 - |y|)$, so each sample spreads into a pyramid that reaches zero at the neighboring pixels. The tent is the convolution of two boxes. This ties interpolation to [[2.1.1. Linear Filters|linear filters]] and to [[2.2b LTI Convolution|convolution]] in signal processing. For example, $2\times$ upsampling with bilinear interpolation equals inserting zeros between samples and then filtering with the kernel $[\tfrac{1}{2}, 1, \tfrac{1}{2}]$ along each axis. Bicubic kernels have small negative lobes. They sharpen edges but can overshoot, for example above $255$ next to a bright edge. Clip the result before casting back to `uint8`, as explained in [[1.1. Digital Images]].

#### *(Choosing a Method)* Use nearest neighbor for labels and masks, bilinear as the default for photos, and bicubic when enlarging.

Nearest neighbor never creates new values. A binary mask stays binary, and a segmentation map keeps valid class labels. Bilinear averaging of labels $2$ and $4$ would invent label $3$. For photos, bilinear is the usual default. It acts as a small blur, so repeated warps soften an image a little more each time. Composing all transformations into one matrix and resampling once avoids this. Bicubic keeps more sharpness when enlarging, at about four times the number of neighbors.

#### *(Borders)* Near the last row or column, the neighbor $x_0 + 1$ or $y_0 + 1$ falls outside the image.

Even a point exactly on the last column, with $\Delta x = 0$, reads index $x_0 + 1$ in a direct implementation. One fix clamps the index to the last valid value (copy edge). Another pads the image by one pixel. A third treats any point outside $[0, W - 1] \times [0, H - 1]$ as outside and returns a fill value, where $W$ and $H$ are the image width and height. [[3.2. Image Warping|Warping]] code usually takes the last option and records it in an alpha mask.

# Examples

>[!example] (Easy) Bilinear Interpolation on a $2 \times 2$ Patch
>A patch has $f(0,0) = 10$, $f(1,0) = 20$, $f(0,1) = 30$ and $f(1,1) = 60$. As a NumPy array with rows first, it is `img = np.array([[10, 20], [30, 60]])`. We want the value at $(x, y) = (0.25, 0.5)$.
>
>>[!example]- Compute the bilinear and nearest-neighbor values. Check the bilinear value with both orders of 1D interpolation and with SciPy.
>>Here $x_0 = y_0 = 0$, $\Delta x = 0.25$ and $\Delta y = 0.5$. The weights are $(0.75)(0.5) = 0.375$ for $f(0,0)$, $(0.25)(0.5) = 0.125$ for $f(1,0)$, $(0.75)(0.5) = 0.375$ for $f(0,1)$, and $(0.25)(0.5) = 0.125$ for $f(1,1)$. They sum to $1$. The value is
>>$$0.375 \cdot 10 + 0.125 \cdot 20 + 0.375 \cdot 30 + 0.125 \cdot 60 = 3.75 + 2.5 + 11.25 + 7.5 = 25.$$
>>Along $x$ first, row $0$ gives $10 + 0.25 \cdot 10 = 12.5$ and row $1$ gives $30 + 0.25 \cdot 30 = 37.5$. Then along $y$, $12.5 + 0.5 \cdot 25 = 25$. Along $y$ first, column $0$ gives $20$ and column $1$ gives $40$, and then $20 + 0.25 \cdot 20 = 25$. Both orders agree.
>>
>>Nearest neighbor rounds to $(\lfloor 0.75 \rfloor, \lfloor 1.0 \rfloor) = (0, 1)$ and returns $f(0, 1) = 30$. The tie at $\Delta y = 0.5$ rounds up with this formula.
>>
>>`scipy.ndimage.map_coordinates(img, [[0.5], [0.25]], order=1)` returns $25$, with the row coordinate $0.5$ first. Passing `[[0.25], [0.5]]` returns $22.5$, the value at $(x, y) = (0.5, 0.25)$.

>[!example] (Medium) Sampling a Rotated Gradient
>An image is a horizontal gradient with $f(x, y) = 10x + y$. It is rotated by $30^\circ$ about the origin with the lecture's $R(\theta)$, using inverse warping. Consider the output pixel $\mathbf{p}' = (3, 2)$.
>
>>[!example]- Find the source location, the bilinear value and the nearest-neighbor value. How large is each error?
>>The source location is $R(30^\circ)^{-1}\mathbf{p}' = R(-30^\circ)\,(3, 2)$:
>>$$x = 3\cos 30^\circ + 2\sin 30^\circ = 3.598, \qquad y = -3\sin 30^\circ + 2\cos 30^\circ = 0.232.$$
>>So $x_0 = 3$, $y_0 = 0$, $\Delta x = 0.598$ and $\Delta y = 0.232$. The four neighbors are $f(3,0) = 30$, $f(4,0) = 40$, $f(3,1) = 31$ and $f(4,1) = 41$, with weights $0.309$, $0.459$, $0.093$ and $0.139$. The bilinear value is $36.21$. The true value of the gradient there is $10(3.598) + 0.232 = 36.21$, so the error is zero, as the *(Exact on Ramps)* property predicts.
>>
>>Nearest neighbor rounds to $(4, 0)$ and returns $40$, an error of $3.79$. Across the full output, nearest neighbor turns the smooth gradient into steps one pixel wide.
