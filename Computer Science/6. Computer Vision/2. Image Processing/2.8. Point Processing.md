>[!note] Point Processing
>A **point process**, or point operation, changes each pixel using only that pixel's own value:
>$$s = T(r).$$
>Here $r$ is the input gray level, $s$ is the output gray level, and $T$ is one function applied at every pixel. Position and neighbors play no role, which separates point processing from filtering and from warping. Gray levels run over $0, 1, \dots, L - 1$, with $L = 256$ for 8-bit images.
>
>The **negative** is $s = L - 1 - r$. The **log** map $s = c \log(1 + r)$ compresses large values, and it is the standard way to display a Fourier magnitude spectrum. The **power-law** or **gamma** map, with $r$ and $s$ normalized to $[0, 1]$, is
>$$s = c\, r^{\gamma}, \qquad c = 1.$$
>The exponent $\gamma > 0$ sets the shape of the curve. A $\gamma < 1$ brightens dark regions and spreads out detail in the shadows. A $\gamma > 1$ darkens the image and spreads out detail in the highlights. **Contrast stretching** is a piecewise-linear $T$ through two control points $(r_1, s_1)$ and $(r_2, s_2)$. With $r_1 = r_2$, $s_1 = 0$ and $s_2 = L - 1$, it becomes thresholding.
>
>The **histogram** counts the pixels at each level, $h(r_k) = n_k$, and $p(r_k) = n_k / n$ for an image of $n$ pixels. The **cumulative histogram** at level $r_k$ is $\sum_{j=0}^{k} p(r_j)$, the fraction of pixels at or below $r_k$. **Histogram equalization** uses $L - 1$ times the cumulative histogram as the map:
>$$s_k = T(r_k) = \operatorname{round}\Big( (L - 1) \sum_{j=0}^{k} p(r_j) \Big).$$
>The output histogram is roughly flat, so the image uses the full range of gray levels. **Color transfer** (Reinhard, Ashikhmin, Gooch and Shirley, 2001) applies a point process to each channel of a decorrelated color space, $l\alpha\beta$. It shifts and scales each channel so that its mean and standard deviation match those of a target image. Point processing cannot use spatial context. Two images with the same histogram, such as a photo and a random shuffle of its pixels, receive identical treatment.

# Intuition

The numbers in an image file are already a squeezed view of the scene. A pixel's value follows $f(x, y) = \text{reflectance}(x, y) \times \text{illumination}(x, y)$, with reflectance in $[0, 1]$ and illumination anywhere in $[0, \infty)$. The lecture's examples of real scenes span relative brightness values from $1$ to $2{,}000{,}000{,}000$, while a stored picture holds $0$ to $255$. The exposure picks which slice of that range fits. The last stage of the camera pipeline then remaps sensor values to pixel values with a curve, which is itself a point process ([[1.1. Digital Images]]). Point processing remaps the stored values again, for display or analysis. The name says that each pixel is treated as an isolated point.

Every $T$ is a choice of which gray levels to spread apart. Where the curve is steeper than the diagonal, nearby input levels move apart and contrast grows. Where it is flatter, they move together and contrast shrinks. The $\gamma = 0.4$ curve above is steep near $0$, so it opens up the shadows at the cost of the highlights. Histogram equalization picks the slope from the data. It makes $T$ steep where many pixels sit and flat where few do.

# Properties

#### *(Why the CDF Flattens)* The cumulative histogram sends each pixel to its rank, and ranks are spread evenly.

Treat the gray level of a random pixel as a continuous random variable $R$ with [[2.2c.1 Probability Density Function|density]] $p_R$. Its cumulative distribution $F(r) = \int_0^r p_R(t)\, dt$ is the fraction of pixels darker than $r$. If $F$ is strictly increasing, the new level $S = F(R)$ satisfies $\mathbb{P}[S \leq s] = \mathbb{P}[R \leq F^{-1}(s)] = s$, so $S$ is uniform on $[0, 1]$. Multiplying by $L - 1$ stretches it over the full range. With discrete levels, equalization can merge input levels but cannot split one. A crowded level stays crowded, and some output levels stay empty. The result is only roughly flat, as the figure shows for the image in the Medium example.

#### *(Lookup Tables)* A point process is applied by computing $T$ once per gray level and indexing.

Since $T$ depends only on $r$, an 8-bit image needs only $256$ evaluations of $T$, stored in an array `lut`. The output is `lut[img]`, one table lookup per pixel, whatever the cost of $T$. Increasing maps never swap the order of two gray levels, so edges stay where they were. Their strength does change. Discussion 3 notes that a Sobel edge response ignores a constant brightness shift but not a contrast change such as histogram equalization. The negative is decreasing, so it reverses the sign of every edge.

#### *(Gamma on 8-Bit Values)* The formula $s = c\, r^\gamma$ with $c = 1$ assumes values in $[0, 1]$.

For 8-bit values the map is $s = 255\,(r / 255)^{\gamma}$. Applied to raw levels with $c = 1$, a $\gamma = 2$ map would send $255$ to $65{,}025$. The lecture's plot draws the curves on $[0, L - 1]$, and all of them pass through $(L - 1, L - 1)$, which matches $c = (L - 1)^{1 - \gamma}$. The slope $\gamma r^{\gamma - 1}$ grows without bound near $0$ when $\gamma < 1$, which is why shadows open up. The lecture's washed-out aerial photo goes the other way. Maps with $\gamma = 3$, $4$ and $5$ darken it and bring back detail in its bright areas.

#### *(Color Transfer Formula)* Each channel is shifted and scaled so that its mean and standard deviation match the target's.

For a channel with source mean $\mu_s$ and standard deviation $\sigma_s$, and target statistics $\mu_t$ and $\sigma_t$, every pixel value $r$ becomes
$$s = \frac{\sigma_t}{\sigma_s}\,(r - \mu_s) + \mu_t.$$
A pixel that sat one standard deviation above the source mean ends up one standard deviation above the target mean. Reinhard et al. work in $l\alpha\beta$, where $l$ is lightness and $\alpha$ and $\beta$ are yellow-blue and red-green opponent channels. In RGB the channels are strongly correlated, since a brighter surface is usually brighter in all three. Changing RGB channels one at a time therefore tends to create odd colors. In $l\alpha\beta$ the channels are close to independent, so per-channel matching behaves well. The $Y'C_bC_r$ space of [[2.9. JPEG Compression]] and the Lab space of [[8.3. Image Colorization]] separate lightness from color in a similar way.

#### *(Blind to Position)* A point process cannot denoise, sharpen, or correct light that varies across the image.

The lecture shows a photo and a noise image with the same histogram. Any point process changes them in exactly the same way, because it sees only the list of values. Removing noise or sharpening edges requires comparing a pixel with its neighbors, as [[2.1.1. Linear Filters|linear filters]] do. A histogram discards position in the same way. Texture descriptors therefore count filter responses, which encode local structure, instead of raw pixel values ([[9.3. Texture Histograms]]).

# Examples

>[!example] (Easy) Opening Up the Shadows
>A photo has normalized gray levels. Two shadow pixels have $r = 0.1$ and $r = 0.2$. Two highlight pixels have $r = 0.8$ and $r = 0.9$.
>
>>[!example]- Apply $\gamma = 0.5$ and then $\gamma = 2$. How does the gap between each pair change? What does $\gamma = 0.5$ do to the 8-bit value $26$?
>>With $\gamma = 0.5$ the four values become $0.316$, $0.447$, $0.894$ and $0.949$. The shadow gap grows from $0.1$ to $0.131$. The highlight gap shrinks from $0.1$ to $0.054$. With $\gamma = 2$ the values become $0.01$, $0.04$, $0.64$ and $0.81$. The shadow gap shrinks to $0.03$ and the highlight gap grows to $0.17$.
>>
>>For 8-bit data, $s = 255\,(26/255)^{0.5} \approx 81.4$, which rounds to $81$. A pixel near black moves almost a third of the way up the range.

>[!example] (Medium) Equalizing a Dark 8-Level Image
>A $10 \times 10$ image has $L = 8$ gray levels. Its histogram is $n = [22, 30, 24, 14, 6, 3, 1, 0]$ for levels $0$ to $7$, so most pixels are dark.
>
>>[!example]- Compute the equalization map, the output histogram, and the mean level before and after. Is the output histogram flat?
>>With $n = 100$ pixels, $p = [0.22, 0.30, 0.24, 0.14, 0.06, 0.03, 0.01, 0]$. The cumulative histogram is $[0.22, 0.52, 0.76, 0.90, 0.96, 0.99, 1, 1]$. Multiplying by $L - 1 = 7$ gives $[1.54, 3.64, 5.32, 6.30, 6.72, 6.93, 7, 7]$, which rounds to
>>$$T = [2, 4, 5, 6, 7, 7, 7, 7].$$
>>The output histogram over levels $0$ to $7$ is $[0, 0, 22, 0, 30, 24, 14, 10]$. The four brightest input levels merge into level $7$. The crowded levels $0$, $1$ and $2$ move apart, with gaps of $2$ and $1$. The mean level rises from $1.65$ to $4.38$.
>>
>>The output is not flat. Levels $0$, $1$ and $3$ are empty, and level $4$ still holds $30$ pixels. Equalization cannot split a level, so a crowded level stays crowded. The darkest pixels also land at $2$ and not at $0$. A common variant subtracts the smallest nonzero cumulative value first, computing $(L - 1)(c_k - c_{\min})/(1 - c_{\min})$. Here that gives $[0, 3, 5, 6, 7, 7, 7, 7]$ and uses the bottom of the range.

>[!example] (Hard) A Shadow Across a Page
>A printed page is photographed with part of it in shadow. Paper has reflectance $0.8$ and ink has reflectance $0.1$. The illumination is $1$ in the lit part and $0.125$ in the shadow.
>
>>[!example]- Compute the four pixel values. Can any point process make all paper white and all ink black?
>>Using $f = \text{reflectance} \times \text{illumination}$, lit paper is $0.8$, lit ink is $0.1$, shaded paper is $0.8 \times 0.125 = 0.1$, and shaded ink is $0.0125$.
>>
>>Lit ink and shaded paper both have the value $0.1$. A point process sees only that value, so it must send both pixels to the same output. No choice of $T$, increasing or not, can make one white and the other black. The product of reflectance and illumination causes this. A dark surface in bright light can match a bright surface in dim light. Fixing it requires information from the neighborhood, such as an estimate of the illumination from a heavily blurred copy of the page.
