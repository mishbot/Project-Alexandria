>[!note] Convolutional Layer
>A **convolutional layer** computes each output from a small neighborhood of its input. It takes a weighted sum of the neighborhood, adds a bias, and applies an activation function. The weights form the **kernel** or **filter** $\boldsymbol{\omega}$, and the same kernel is used at every position. Two sliding-window operators differ only in one sign:
>
>- **Cross-correlation** $\star$ slides the kernel as it is. CNNs and PyTorch's `conv2d` compute it, although deep learning calls it "convolution".
>- **Convolution** $*$ rotates the kernel by $180°$ before sliding it. Signal processing uses it.
>
>In 2D they read
>$$(\boldsymbol{\omega} \star \mathbf{x})[r,c] = \sum_{i,j} \omega[i,j] \cdot x[r+i,\, c+j],$$
>$$(\boldsymbol{\omega} * \mathbf{x})[r,c] = \sum_{i,j} \omega[i,j] \cdot x[r-i,\, c-j] = \sum_{i,j} x[i,j] \cdot \omega[r-i,\, c-j].$$
>Here $r$ and $c$ are the row and column of the output. The indices $i$ and $j$ run over the entries of the kernel. In 1D the second index drops out. A $3$-tap kernel indexed from its center gives $(\boldsymbol{\omega} \star \mathbf{x})[r] = \omega[-1]\,x[r-1] + \omega[0]\,x[r] + \omega[1]\,x[r+1]$. Lecture and Prince write these entries as $\omega_1, \omega_2, \omega_3$.
>
>The cross-correlation $\boldsymbol{\omega} \star \mathbf{x}$ is a whole map of outputs. The layer adds the same scalar bias $\beta \in \mathbb{R}$ to every entry of that map. This equals adding the matrix $\beta\,\mathbf{1}\mathbf{1}^T$, whose entries all equal $\beta$. Sharing one bias across positions, like sharing the kernel, keeps the layer equivariant to shifts. The activation function $a[\cdot]$ then acts on each entry. Inputs and hidden layers have several **channels**, also called **feature maps**, and an RGB image has three. Output channel $c_{\text{out}}$ has its own bias and adds one cross-correlation per input channel $c_{\text{in}}$:
>$$\mathbf{h} = a\big[\beta + \boldsymbol{\omega} \star \mathbf{x}\big], \qquad \mathbf{h}_{c_{\text{out}}} = a\Big[\beta_{c_{\text{out}}} + \sum_{c_{\text{in}}=1}^{C_{\text{in}}} \boldsymbol{\omega}_{c_{\text{out}},c_{\text{in}}} \star \mathbf{x}_{c_{\text{in}}}\Big].$$
>The input is $\mathbf{x} \in \mathbb{R}^{C_{\text{in}} \times H \times W}$, each kernel is $\boldsymbol{\omega}_{c_{\text{out}},c_{\text{in}}} \in \mathbb{R}^{K \times K}$, and the biases form $\boldsymbol{\beta} \in \mathbb{R}^{C_{\text{out}}}$. A layer with $C_{\text{out}}$ output channels and $K \times K$ kernels therefore has $C_{\text{in}} C_{\text{out}} K^2$ weights and $C_{\text{out}}$ biases. PyTorch stores the weights as a $C_{\text{out}} \times C_{\text{in}} \times K \times K$ tensor. The count does not depend on the size of the image.
>
>Three hyperparameters set the output size:
>- **Padding** $p$ adds $p$ values on each side of the input. The added values can be filled in three ways:
>    - **Zero padding** uses zeros.
>    - **Circular padding** wraps around and copies the values at the opposite edge.
>    - **Reflect padding** mirrors the values next to the edge.
>- **Stride** $s$ evaluates the kernel only at every $s$-th position.
>- **Dilation** $d$ spaces the kernel taps $d$ positions apart, so $K$ weights cover $d(K-1)+1$ inputs.
>
>Along each spatial axis an input of size $W_{\text{in}}$ gives
>$$W_{\text{out}} = \left\lfloor \frac{W_{\text{in}} + 2p - d(K-1) - 1}{s} \right\rfloor + 1,$$
>which reduces to $\lfloor (W_{\text{in}} + 2p - K)/s \rfloor + 1$ when $d = 1$. Two settings have names:
>- **Valid** convolution uses $p = 0$. With stride $1$ its output is $K - 1$ shorter than the input.
>- **Same** convolution uses $s = 1$ and $p = (K-1)/2$, so its output has the size of the input.
>
>A convolutional layer is a dense layer whose weight matrix is sparse, with the same values repeated along each diagonal band.
>
>Three topics have their own notes:
>- [[5.2.1a. Receptive Field|Receptive field]]: how much of the input a unit sees, and how stacking layers grows it.
>- [[5.2.1b. Equivariance and Invariance|Equivariance and invariance]]: why a shifted input gives a shifted feature map.
>- [[5.2.1c. 1x1 and Depthwise Convolution|$1 \times 1$ and depthwise convolution]]: special cases that mix only channels or only space.

>[!warning] Flipped Convolution in Hand Calculations
>Lecture and PyTorch's `conv2d` compute $\boldsymbol{\omega} \star \mathbf{x}$. Some homework problems use the convolution $\mathbf{x} * \mathbf{h}$ instead, which rotates the kernel by $180°$. Others write $*$ for the unflipped CNN operation. For a learned kernel the choice does not matter, because training finds the rotated weights. For a hand calculation it changes the answer whenever the kernel is not symmetric. Check whether each problem's sum reads $x[r+i]$ or $x[r-i]$. [[2.1.1. Linear Filters]] compares the two operations and writes cross-correlation as $\otimes$.

One homework writes $K$, $P$ and $S$ for kernel size, padding and stride. It also writes $F$ for the number of filters and $W \times H \times C$ for the input shape. Another writes $\mathbf{X} \in \mathbb{R}^{n \times n}$, $\mathbf{w} \in \mathbb{R}^{k \times k}$ and $\mathbf{Y} \in \mathbb{R}^{m \times m}$ with $m = n - k + 1$. The discussions write $W_{\text{in}}$, $K$, $s$ and $p$.

# Intuition

A $224 \times 224$ RGB image has $150{,}528$ input values. A [[2. Neural Networks|dense layer]] with the same number of hidden units would need $150{,}528^2 \approx 22.7$ billion weights. Images also have structure that a dense layer ignores. Nearby pixels are strongly related, and a tree shifted a few pixels to the left is still a tree. A dense layer treats every pair of pixels alike, so it must learn what a tree looks like separately at every position. A convolutional layer builds in three assumptions instead:
- **Locality**: each unit looks only at a small neighborhood.
- **Weight sharing**: the same detector runs at every position, which respects translation.
- **Hierarchy**: stacking layers lets small parts combine into larger wholes.

Sliding one kernel across the input turns a single weighted sum into a whole map of outputs. The figure shows a kernel of size three. Every output uses the same three weights, and the outputs at the edge reach into the padding. The operation is the [[2.2b LTI Convolution|convolution of signal processing]] without the flip. It is also the same sliding window as the [[2.1.1. Linear Filters|linear filters]] of image processing. The difference is that the network learns the kernel from data instead of using a hand-designed one.

One kernel is not enough. A weighted sum blurs its neighborhood, and the ReLU discards every negative response, so a single map loses information. A layer therefore runs many kernels in parallel, one per output channel, and the next layer sums over all of them. Each layer looks at a neighborhood of the layer below. Units deep in the network therefore see a large part of the image, even though every kernel is small. [[5.2.1a. Receptive Field]] follows this growth layer by layer.

# Properties

#### *(Counting Kernel Positions)* The output size formula counts the positions where the kernel fits inside the padded input.

Padding on both sides gives $W_{\text{in}} + 2p$ values. A dilated kernel spans $d(K-1) + 1$ of them, so its first tap can sit at $W_{\text{in}} + 2p - d(K-1)$ positions. A stride of $s$ keeps the first position and every $s$-th one after it. Counting offsets from the first position, the last kept offset is the largest multiple of $s$ that is at most $W_{\text{in}} + 2p - d(K-1) - 1$. This gives the floor in the formula. The floor means that some input columns at the far edge are never covered when the stride does not divide evenly. With $W_{\text{in}} = 8$, $K = 3$, $p = 0$ and $s = 2$, the formula gives $\lfloor 5/2 \rfloor + 1 = 3$ outputs. They start at positions $1$, $3$ and $5$, so the eighth input is never used.

#### *(Banded Weight Matrix)* A convolution is a dense layer with most weights fixed at zero and the rest tied together.

Write a 1D layer without the activation as $\mathbf{h} = \beta\mathbf{1} + \boldsymbol{\Omega}\mathbf{x}$. For a valid convolution with $K = 3$ on $D$ inputs, $\boldsymbol{\Omega}$ is a $(D-2) \times D$ matrix. Every row holds the kernel, shifted one column to the right of the row above:
$$\boldsymbol{\Omega} = \begin{bmatrix} \omega_1 & \omega_2 & \omega_3 & 0 & \cdots & 0 \\ 0 & \omega_1 & \omega_2 & \omega_3 & \cdots & 0 \\ & & \ddots & \ddots & \ddots & \\ 0 & \cdots & 0 & \omega_1 & \omega_2 & \omega_3 \end{bmatrix}.$$
Each diagonal is constant, which makes $\boldsymbol{\Omega}$ a Toeplitz matrix. The other settings change the matrix as follows:
- **Zero padding** adds one row at each end with the kernel cut off, $[\omega_2, \omega_3, 0, \dots]$ on top and $[\dots, 0, \omega_1, \omega_2]$ at the bottom.
- **Stride** $s$ keeps every $s$-th row.
- **2D inputs** make $\boldsymbol{\Omega}$ block Toeplitz: a Toeplitz arrangement of blocks that are themselves Toeplitz.
- **Channels** add a $C_{\text{out}} \times C_{\text{in}}$ grid of such blocks.

A dense layer on the same input would have $D^2$ free weights, while the convolution has $K$. A **locally connected** layer keeps the band but gives each row its own values. It has $(D - K + 1)K$ weights for a valid output and respects locality but not translation.

#### *(Full-Size Kernel Equals a Dense Layer)* A kernel as large as the input, with no padding, turns the convolutional layer into a fully connected layer.

Take $K \times K = H \times W$ and $p = 0$. The kernel then fits at exactly one position, and each filter outputs one number:
$$h_{c_{\text{out}}} = a\Big[\beta_{c_{\text{out}}} + \sum_{c_{\text{in}}=1}^{C_{\text{in}}} \sum_{i,j} \omega_{c_{\text{out}},c_{\text{in}}}[i,j] \cdot x_{c_{\text{in}}}[i,j]\Big].$$
This is a weighted sum of every input value plus a bias, which is one unit of a dense layer. The filter's kernels, stacked into a $C_{\text{in}} \times H \times W$ block, form that unit's row of the weight matrix. The layer has $C_{\text{out}} C_{\text{in}} H W$ weights, the same as a dense layer from $C_{\text{in}} H W$ inputs to $C_{\text{out}}$ outputs. For example, ten $28 \times 28$ filters on a $1 \times 28 \times 28$ image compute the same function as a dense layer from $784$ inputs to $10$ outputs. With padding the equivalence fails. The kernel then slides over several positions, and each filter outputs a whole map with shared weights. The full-size kernel also loses both inductive biases of a convolution. It sits at only one position, so no weights are shared. Its window covers the whole image, so there is no locality. A larger kernel therefore makes a layer closer to fully connected and less dependent on how the pixels are arranged.

#### *(Unfolding Into a Matrix Product)* GPUs compute a convolution as one large matrix product over unfolded patches.

>[!warning] Not Taught in Lecture
>Lecture did not cover im2col. A homework problem on the Muon optimizer introduced it.

The unfolding is called **im2col**. Each receptive-field patch of the input holds $C_{\text{in}} K^2$ values, and each becomes one column of a matrix $\mathbf{X}' \in \mathbb{R}^{C_{\text{in}} K^2 \times H_{\text{out}} W_{\text{out}}}$. Flattening every dimension of the kernel except $C_{\text{out}}$ gives a matrix $\mathbf{C} \in \mathbb{R}^{C_{\text{out}} \times C_{\text{in}} K^2}$. The layer output is then
$$\mathbf{C}\mathbf{X}' + \boldsymbol{\beta}\mathbf{1}^T \in \mathbb{R}^{C_{\text{out}} \times H_{\text{out}} W_{\text{out}}},$$
which is reshaped to $C_{\text{out}} \times H_{\text{out}} \times W_{\text{out}}$. The product costs $C_{\text{out}} \cdot C_{\text{in}} K^2 \cdot H_{\text{out}} W_{\text{out}}$ multiply-accumulate operations, each of which multiplies two numbers and adds the result to a running sum. Optimizers that act on weight matrices, such as Muon, use the same flattened $\mathbf{C}$ for a convolutional kernel.

#### *(Channels Prevent Information Loss)* A layer needs many output channels because one weighted sum followed by a ReLU discards information.

A single kernel averages its neighborhood, and the ReLU clips every negative result to zero. Computing several convolutions in parallel keeps different pieces of information in different channels. A common reading treats each channel as a detector for one pattern at the scale of its receptive field. First-layer channels often look like edge detectors and fit this reading well. Deeper channels are harder to interpret, so the reading is a useful simplification rather than an exact description. Convolutional networks usually double the number of channels each time they halve the height and width. The next layer then has a quarter of the positions and four times the weights per position. Its computation therefore stays about the same.

#### *(Shared Weights Sum Their Gradients)* The gradient of a shared weight is the sum of its gradients at every position where it is used.

Consider a model in which every weight is tied to one value $a$, such as $\mathcal{L} = \sum_i (a x_i - y_i)^2$. The chain rule gives $\partial \mathcal{L}/\partial a = \sum_i 2(a x_i - y_i)\, x_i$, one term per use. Take a single-channel 2D valid layer $\mathbf{Y} = \mathbf{W} \star \mathbf{X} + \beta$ with a scalar bias $\beta \in \mathbb{R}$. Its $K \times K$ kernel is indexed from $0$, and its output is $M \times M$. Its forward pass and upstream gradient are
$$y[r,c] = \sum_{i,j=0}^{K-1} w[i,j] \cdot x[r+i,\, c+j] + \beta, \qquad dy[r,c] = \frac{\partial \mathcal{L}}{\partial y[r,c]}.$$
A weight touches every output, and an input touches every output whose window covers it. The chain rule therefore gives
$$\frac{\partial \mathcal{L}}{\partial w[i,j]} = \sum_{r,c} dy[r,c] \cdot x[r+i,\, c+j], \qquad \frac{\partial \mathcal{L}}{\partial x[r,c]} = \sum_{i,j} w[i,j] \cdot dy[r-i,\, c-j], \qquad \frac{\partial \mathcal{L}}{\partial \beta} = \sum_{r,c} dy[r,c].$$
Each gradient is itself a sliding-window operation:
- The **weight gradient** reads $x[r+i]$, so it is a cross-correlation, $\partial \mathcal{L}/\partial \mathbf{W} = d\mathbf{Y} \star \mathbf{X}$.
- The **input gradient** reads $dy[r-i]$, so it is a full convolution, $\partial \mathcal{L}/\partial \mathbf{X} = \mathbf{W} * d\mathbf{Y}$. Terms where $dy$ falls outside the output count as zero. This is the same as a [[5.2.3. Upsampling|transposed convolution]] of $d\mathbf{Y}$ with the kernel.
- The **bias gradient** sums $d\mathbf{Y}$ over all positions.

One SGD step subtracts $\eta$ times a weighted sum of input patches from the kernel. A trained kernel is therefore its initialization plus a weighted sum of patches of the layer's input. In the first layer these are patches of the training images. The sum has one term for each of the $M^2$ output positions. For independent zero-mean inputs with variance $\sigma_x^2$ and upstream gradients with variance $\sigma_g^2$, its variance is $M^2 \sigma_x^2 \sigma_g^2$. The typical size of a weight gradient therefore grows in proportion to the image side length.

# Examples

>[!example] (Easy) Shapes and Parameter Counts
>A layer receives a $3 \times 64 \times 64$ image (channels, height, width). It has $16$ filters of size $5 \times 5$, stride $2$ and padding $2$.
>
>>[!example]- What is the output shape, how many parameters does the layer have, and how many would a dense layer with the same input and output sizes need?
>>Along each axis $W_{\text{out}} = \lfloor (64 + 2 \cdot 2 - 5)/2 \rfloor + 1 = \lfloor 31.5 \rfloor + 1 = 32$, so the output is $16 \times 32 \times 32$. Each filter has $3 \cdot 5 \cdot 5 = 75$ weights, so the layer has $16 \cdot 75 = 1200$ weights and $16$ biases, $1216$ parameters in total. A dense layer maps $3 \cdot 64^2 = 12{,}288$ inputs to $16 \cdot 32^2 = 16{,}384$ outputs. It needs $12{,}288 \cdot 16{,}384 = 201{,}326{,}592$ weights and $16{,}384$ biases, about $165{,}000$ times as many parameters. Doubling the image side leaves the convolution at $1216$ parameters and multiplies the dense layer by $16$.

>[!example] (Medium) A 1D Convolution as a Matrix
>A signal $\mathbf{x} = [2, -1, 0, 3, 1]^T$ is filtered by the kernel $\boldsymbol{\omega} = [1, 0, -1]^T$ with zero padding $1$, no bias and no activation.
>
>>[!example]- Write the $5 \times 5$ matrix of the layer for stride $1$, compute the output, and give the output for stride $2$.
>>Index the kernel from its center, so $\omega[-1] = 1$, $\omega[0] = 0$ and $\omega[1] = -1$. With $p = 1$ the output is $h[r] = x[r-1] - x[r+1]$, with $x[0] = x[6] = 0$. The first and last rows lose one tap to the padding:
>>$$\boldsymbol{\Omega} = \begin{bmatrix} 0 & -1 & 0 & 0 & 0 \\ 1 & 0 & -1 & 0 & 0 \\ 0 & 1 & 0 & -1 & 0 \\ 0 & 0 & 1 & 0 & -1 \\ 0 & 0 & 0 & 1 & 0 \end{bmatrix}, \qquad \boldsymbol{\Omega}\mathbf{x} = \begin{bmatrix} 1 \\ 2 \\ -4 \\ -1 \\ 3 \end{bmatrix}.$$
>>Stride $2$ keeps rows $1$, $3$ and $5$, giving $[1, -4, 3]^T$, which matches $\lfloor (5 + 2 - 3)/2 \rfloor + 1 = 3$ outputs.
>
>>[!example]- What does the convolution $\boldsymbol{\omega} * \mathbf{x}$ give with the same padding?
>>The convolution reads $x[r-i]$, so $h[r] = \omega[-1]\,x[r+1] + \omega[1]\,x[r-1] = x[r+1] - x[r-1]$. Every output changes sign: $[-1, -2, 4, 1, -3]^T$. The kernel is antisymmetric, $\omega[1] = -\omega[-1]$, so flipping it only changes the sign. Any kernel that is not symmetric gives different answers under the two operators.

>[!example] (Hard) Backpropagating Through a 2D Convolution
>A layer computes the valid cross-correlation $\mathbf{Y} = \mathbf{W} \star \mathbf{X} + \beta$. It maps the $3 \times 3$ input $\mathbf{X}$ to a $2 \times 2$ output $\mathbf{Y}$ with the $2 \times 2$ kernel $\mathbf{W}$:
>$$\mathbf{X} = \begin{bmatrix} 1 & 2 & 0 \\ 0 & 1 & 3 \\ 2 & 1 & 1 \end{bmatrix}, \qquad \mathbf{W} = \begin{bmatrix} 1 & 2 \\ 3 & -1 \end{bmatrix}, \qquad d\mathbf{Y} = \begin{bmatrix} 1 & 0 \\ -1 & 2 \end{bmatrix}.$$
>
>>[!example]- Compute $\partial \mathcal{L}/\partial \mathbf{W}$, $\partial \mathcal{L}/\partial \beta$ and $\partial \mathcal{L}/\partial \mathbf{X}$.
>>The weight gradient $d\mathbf{Y} \star \mathbf{X}$ slides $d\mathbf{Y}$ over $\mathbf{X}$. For $w[0,0]$ the window is the top-left $2 \times 2$ block of $\mathbf{X}$, so $1 \cdot 1 + 2 \cdot 0 + 0 \cdot (-1) + 1 \cdot 2 = 3$. The other three windows give
>>$$\frac{\partial \mathcal{L}}{\partial \mathbf{W}} = \begin{bmatrix} 3 & 7 \\ 0 & 2 \end{bmatrix}, \qquad \frac{\partial \mathcal{L}}{\partial \beta} = 1 + 0 - 1 + 2 = 2.$$
>>For the input gradient, each $dy[r,c]$ sends $dy[r,c]\,\mathbf{W}$ back onto the $2 \times 2$ window of $\mathbf{X}$ that produced $y[r,c]$. Adding the four copies, weighted by $1$ (top-left), $0$ (top-right), $-1$ (bottom-left) and $2$ (bottom-right), gives
>>$$\frac{\partial \mathcal{L}}{\partial \mathbf{X}} = \begin{bmatrix} 1 & 2 & 0 \\ 2 & -1 & 4 \\ -3 & 7 & -2 \end{bmatrix}.$$
>>The center entry collects all four copies: $-1 \cdot 1 + 3 \cdot 0 + 2 \cdot (-1) + 1 \cdot 2 = -1$. This matrix is the full convolution $\mathbf{W} * d\mathbf{Y}$. Padding $d\mathbf{Y}$ with one ring of zeros and cross-correlating it with $\mathbf{W}$ rotated by $180°$ gives the same result. A finite-difference check, raising one $x[r,c]$ by $1$ and recomputing $\sum_{r,c} dy[r,c]\, y[r,c]$, gives the same entries because the layer is linear.
