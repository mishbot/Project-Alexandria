>[!note] Flow-Based Image Editing
>**Flow-based image editing** reuses a pretrained text-conditioned [[10.3.2. Flow Matching|flow model]] $v_\theta(x_t, t, c)$ for tasks it was never trained on. Nothing is retrained. Each method changes only where sampling starts or how predicted velocities are combined. Time runs from $t = 0$ (pure noise) to $t = 1$ (clean image), and a noisy image is
>$$x_t = (1 - t)\,\epsilon + t\,x_1, \qquad \epsilon \sim \mathcal{N}(0, I),$$
>where $x_1$ is a clean image with pixel values in $[-1, 1]$. Project 3 Part A applies these tools with the PixNerd model at $512 \times 512$.
>
>The **one-step estimate** extrapolates to the clean image with one velocity, $\hat{x}_1 = x_t + (1 - t)\,v_\theta(x_t, t, c)$. **Euler sampling** takes steps $x_{t+h} = x_t + h\,v(x_t, t, c)$ with $h = 0.02$ and shortens the last step to end at $t = 1$. All creative applications use the [[10.3.2. Classifier-Free Guidance|guided]] velocity $v = v_c + w\,(v_c - v_u)$ with $w = 7$, where $v_c$ uses the prompt and $v_u$ the empty prompt.
>
>**Image-to-image editing**, inspired by SDEdit, noises a real image to a starting time $t_s$, $x_{t_s} = (1 - t_s)\,\epsilon + t_s\,x_{\text{orig}}$, and runs Euler sampling from $t_s$ to $1$. A smaller $t_s$ adds more noise and gives a larger edit. Project 3 uses $t_s \in \{0.02, 0.04, 0.06, 0.10, 0.14, 0.25, 0.5\}$. Starting from a drawing or painting **projects** it onto the natural-image manifold. **Text-guided editing** runs the same procedure with a prompt that describes the change.
>
>**Visual anagrams** (Geng, Park, Owens, CVPR 2024) make one image that shows prompt $p_1$ upright and prompt $p_2$ upside down. At every Euler step,
>$$v_1 = \text{CFG}(x_t, t, p_1), \qquad v_2 = \text{flip}\big(\text{CFG}(\text{flip}(x_t), t, p_2)\big), \qquad v = \tfrac{1}{2}(v_1 + v_2),$$
>where CFG returns the guided velocity and flip rotates the image by $180^\circ$ (both axes reversed). **Hybrid images** (Factorized Diffusion) combine frequency bands of two guided velocities,
>$$v = f_{\text{lowpass}}(v_1) + f_{\text{highpass}}(v_2), \qquad f_{\text{highpass}}(v) = v - f_{\text{lowpass}}(v),$$
>with $v_1, v_2$ the guided velocities for prompts $p_1, p_2$. The low-pass filter is a Gaussian blur with kernel size $265$ and $\sigma = 16$ pixels.

>[!warning] Time Direction and Guidance Scale
>Project 3 and the flow lecture put noise at $t = 0$ and the clean image at $t = 1$, so editing integrates forward in $t$. The diffusion slides run the other way, including the lecture's visual-anagram slide. There $x_T \sim \mathcal{N}(0, I)$ is noise, $x_0$ is clean, and the network predicts noise $\epsilon_t$ instead of a velocity. [[10.3.1. Diffusion Models]] uses the same diffusion convention. Project 3's guidance weight $w$ relates to the lecture's CFG scale $s$ by $s = 1 + w$. So $w = 7$ means $s = 8$, and $w = 0$ means plain conditional sampling.

# Intuition

A flow model trained on photos knows one operation. Given a noisy image and a time, it predicts which way to move toward a natural image that fits the prompt. Image editing starts this process from a noisy copy of an existing image instead of pure noise. The starting time sets how much of the input survives. At $t_s = 0.5$ the input and the noise have equal weight, so the model keeps most of the image and cleans up details. At $t_s = 0.02$ the input has weight $0.02$ against noise of weight $0.98$. Only large, high-contrast shapes survive, and the model invents everything else. In Project 3's Campanile sweep, $t_s = 0.02$ leaves only a pale vertical shape against blue, and the clock face and belfry arches return only at $t_s = 0.25$. The name SDEdit refers to the stochastic differential equations of diffusion models. Project 3 runs the same idea with a deterministic flow.

The same view explains projection onto the manifold. A crayon drawing is not a natural image, and the model saw only noisy natural images in training. Noise hides the drawing's flat colors and hard outlines but keeps its layout and palette. The model treats the result as a noisy photo, so its velocities lead to a realistic image with the drawing's composition. The figure sketches image space in one dimension. The dotted line is the path from the noise sample $\epsilon$ to $x_{\text{orig}}$, and $x_{t_s}$ is its point at time $t_s$.

# Properties

#### *(One-Step Estimate Is a Mean)* The one-step estimate approximates the average of all clean images consistent with $x_t$, so it is blurry at small $t$.

Training fits $v_\theta$ to $x_1 - x_0$ with squared error, so the ideal model predicts $v^* = \mathbb{E}[x_1 - x_0 \mid x_t]$. Solving $x_t = (1 - t)\,x_0 + t\,x_1$ for $x_0$ gives $x_1 - x_0 = (x_1 - x_t)/(1 - t)$. Taking the conditional expectation and rearranging gives
$$x_t + (1 - t)\,v^*(x_t, t) = \mathbb{E}[x_1 \mid x_t].$$
At small $t$ many clean images fit $x_t$, and their average is a blur, like the averaged colors in [[8.3. Image Colorization]]. Euler sampling recomputes the velocity after every small step. The set of consistent images shrinks as $t$ grows, so the final image stays sharp. Project 3's comparison of Gaussian blur, the one-step estimate and Euler sampling on the same noisy input shows this difference.

#### *(What Survives Noising)* Wide, high-contrast shapes survive at smaller $t_s$ than small, faint details, because noise averages out over large regions.

In $x_{t_s}$ the image enters with weight $t_s$, and the noise has standard deviation $1 - t_s$ per pixel. Averaging the noise over a $k \times k$ block of independent pixels divides its standard deviation by $k$. Take a feature of width $s$ pixels whose value differs from its surroundings by $\Delta$ on the $[-1, 1]$ scale. With blocks of size $k = s$, the feature stands out roughly when $t_s \Delta$ exceeds twice the averaged noise, $2(1 - t_s)/s$. Solving for $t_s$ gives the rough threshold
$$t_s \gtrsim \frac{2}{2 + s\,\Delta}.$$
Below the threshold the feature is lost in the noise, and the model must regenerate it. The edit keeps what survives and invents the rest.

#### *(Realism Versus Faithfulness)* The starting time trades realism of the output against faithfulness to the input, and drawings show the trade-off most clearly.

In Project 3 a house drawing becomes a portrait at $t_s = 0.02$ and a figure under a peaked shape at $t_s = 0.04$ to $0.06$. It returns as a drawing by $t_s = 0.10$. A flower drawing becomes a recognizable flower at $t_s = 0.10$ and returns to flat circles by $0.25$. At large $t_s$ the noisy input is close to the drawing, and sampling stays near the drawing. The useful range for projection is narrow and depends on the input. Text-guided editing shows the same trade-off. With the prompt "a photograph of a rocket on a launch pad", the prompt wins at low $t_s$ and the Campanile wins at high $t_s$. At $t_s = 0.06$ to $0.14$ the result keeps the tower's framing with a rocket's surface.

#### *(Why Flipping Is Allowed)* A flipped noisy image is a valid model input at the same time $t$, because a $180^\circ$ rotation only permutes pixels.

Rotating $x_t = (1 - t)\,\epsilon + t\,x_1$ gives $(1 - t)\,\text{flip}(\epsilon) + t\,\text{flip}(x_1)$. The rotated noise $\text{flip}(\epsilon)$ is again independent $\mathcal{N}(0, 1)$ per pixel, so the second branch sees an ordinary noisy image at time $t$. Its velocity lives in the rotated frame. Flipping it back moves each prediction to the pixel it belongs to before averaging. The rotation is its own inverse, so one function does both flips. Any view that permutes pixels keeps these properties. A view that blurs or resizes the image changes the noise statistics and breaks the method. The name follows from this. An anagram rearranges letters into a new word, and a visual anagram rearranges pixels into a new picture.

#### *(Combining Velocities)* Both illusions add velocities, so every Euler step moves the image toward agreement with both prompts.

Averaging gives each prompt half of every step. The image is pulled toward a state where the upright view fits $p_1$ and the rotated view fits $p_2$. The hybrid method gives each prompt control of one frequency band instead. The low-pass filter is linear, so $f_{\text{lowpass}}(v) + f_{\text{highpass}}(v) = v$. With $p_1 = p_2$ the hybrid method reduces to ordinary guided sampling. With different prompts, $p_1$ sets the coarse layout seen from far away. Prompt $p_2$ sets the fine detail seen up close, as in [[2.7. Hybrid Images|classical hybrid images]]. Project 3 warns that both illusions may need several runs before one works well.

#### *(Reading the Blur Parameters)* With $\sigma = 16$ at $512 \times 512$, the low-pass band holds patterns of about six cycles or fewer across the image.

A Gaussian with standard deviation $\sigma$ pixels has the frequency response $\exp(-2\pi^2 \sigma^2 f^2)$, with $f$ in cycles per pixel ([[2.2. Fourier Transform in Images]]). It falls to one half at $f = \sqrt{\ln 2 / 2}\,/\,(\pi \sigma) \approx 0.0117$. That is a period of about $85$ pixels, or $6$ cycles across $512$ pixels. So $p_1$ controls only patterns with periods longer than about $85$ pixels. The kernel size $265$ has half-width $132 = 8.25\,\sigma$, so truncating the Gaussian at the kernel edge discards a negligible part of it.

# Examples

>[!example] (Medium) What Survives at Each Starting Time
>Model the Campanile in a $512 \times 512$ photo with two features. The tower is about $100$ pixels wide and differs from the sky by $\Delta = 1$ on the $[-1, 1]$ scale. The clock face is about $20$ pixels wide with a weaker contrast, $\Delta = 0.3$. These sizes and contrasts are assumptions chosen for illustration.
>
>>[!example]- Use the threshold $t_s \gtrsim 2/(2 + s\Delta)$ to find when each feature survives noising, and compare with Project 3's sweep. How many Euler steps and network evaluations does an edit from $t_s = 0.25$ take?
>>For the tower, $2/(2 + 100 \cdot 1) \approx 0.020$, so at $t_s = 0.02$ the tower sits right at the threshold. Averaged over a $100 \times 100$ block, the noise has standard deviation $0.98 / 100 \approx 0.0098$. The tower adds a signal of $0.02 \cdot 1 = 0.02$, about twice that. For the clock face, $2/(2 + 20 \cdot 0.3) = 2/8 = 0.25$. Project 3 reports the same pattern. At $t_s = 0.02$ only a pale vertical shape survives, and the clock face returns at $t_s = 0.25$. Details below the threshold at small $t_s$ are new inventions of the model.
>>
>>From $t_s = 0.25$ with $h = 0.02$, the remaining time is $0.75 = 37.5\,h$. The sampler takes $37$ full steps to $t = 0.99$ and one shortened step of $0.01$, so $38$ steps in all. Classifier-free guidance evaluates the model twice per step, with the prompt and with the empty prompt. The edit therefore costs $76$ network evaluations.

>[!example] (Hard) Flip Bookkeeping and an Invalid View
>Take a $2 \times 2$ toy image. At one step, the guided velocity for $p_1$ on $x_t$ is $v_1$, and the guided velocity for $p_2$ on $\text{flip}(x_t)$ is $u$:
>$$v_1 = \begin{bmatrix} 0.2 & -0.4 \\ 0.6 & 0.0 \end{bmatrix}, \qquad u = \begin{bmatrix} 0.4 & 0.2 \\ -0.2 & 0.8 \end{bmatrix}.$$
>
>>[!example]- (a) Compute $v_2$, $v$ and the Euler update with $h = 0.02$. (b) A student replaces the rotation with a $3 \times 3$ box blur as the second view. Explain why the method breaks.
>>(a) A $180^\circ$ rotation reverses both rows and columns, so the top-left entry of $u$ moves to the bottom-right. This gives
>>$$v_2 = \text{flip}(u) = \begin{bmatrix} 0.8 & -0.2 \\ 0.2 & 0.4 \end{bmatrix}, \qquad v = \tfrac{1}{2}(v_1 + v_2) = \begin{bmatrix} 0.5 & -0.3 \\ 0.4 & 0.2 \end{bmatrix}.$$
>>The Euler update adds $h\,v = \begin{bmatrix} 0.010 & -0.006 \\ 0.008 & 0.004 \end{bmatrix}$ to $x_t$. Averaging $v_1$ with $u$ directly would mix velocities that were predicted for different pixels.
>>
>>(b) The model expects noise with variance $(1 - t)^2$ per pixel. A $3 \times 3$ box blur averages $9$ independent noise values with weight $1/9$ each. The noise variance drops to $9 \cdot (1/9)^2 = 1/9$ of its value. The blurred input looks like an image at a later time with less noise, so the predicted velocity does not match time $t$. A box blur also removes some frequencies completely, so it has no inverse to map the velocity back. A rotation permutes pixels, which keeps the noise independent with unchanged variance and has an exact inverse.
