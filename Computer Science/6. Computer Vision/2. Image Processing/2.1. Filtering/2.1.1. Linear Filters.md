>[!note] Linear Filters
>A **linear filter** modifies an image by replacing each pixel with a **weighted sum of pixel intensities** in a local neighborhood. The weights form the **kernel** (or filter mask) $H$, a $(2k+1) \times (2k+1)$ array indexed by offsets $u, v \in \{-k, \dots, k\}$. The same weights are used at every pixel. The operation is **linear**, meaning $\text{filter}(aF_1 + bF_2) = a\,\text{filter}(F_1) + b\,\text{filter}(F_2)$. It is also **shift-invariant**: shifting the input shifts the output by the same amount. Every linear, shift-invariant operation on images is a convolution with some kernel.
>
>Let $F$ be the input image and $G$ the output. **Cross-correlation**, written $G = H \otimes F$, slides the kernel over the image without flipping it:
>$$G[i,j] = \sum_{u=-k}^{k} \sum_{v=-k}^{k} H[u,v]\, F[i+u,\, j+v].$$
>**Convolution**, written $G = H * F$, flips the kernel in both directions (a $180°$ rotation) before sliding it:
>$$G[i,j] = \sum_{u=-k}^{k} \sum_{v=-k}^{k} H[u,v]\, F[i-u,\, j-v].$$
>In both formulas $i$ is the row and $j$ the column of the output pixel. The two operations agree whenever $H[-u,-v] = H[u,v]$, as for box and Gaussian kernels. Convolution is commutative and associative. Cross-correlation is neither.
>
>The **unit impulse** $e$ has a $1$ at the center and $0$ elsewhere, and it leaves the image unchanged. A single $1$ away from the center shifts the image. The **box filter** $H[u,v] = 1/(2k+1)^2$ replaces each pixel by the mean of its neighborhood. The **Gaussian filter** weights neighbors by their distance from the center:
>$$G_\sigma(x, y) = \frac{1}{2\pi\sigma^2} \exp\!\left(-\frac{x^2 + y^2}{2\sigma^2}\right).$$
>Here $(x, y)$ is the offset from the center, and the standard deviation $\sigma$, in pixels, sets the amount of smoothing. A discrete Gaussian kernel uses a half-width of about $3\sigma$ and is renormalized to sum to $1$. Smoothing kernels have nonnegative weights that sum to $1$. Derivative kernels have positive and negative weights that sum to $0$.
>
>For an $M \times M$ image and an $N \times N$ kernel ($N = 2k+1$), the output is $(M+N-1) \times (M+N-1)$ in **full** mode, $M \times M$ in **same** mode, and $(M-N+1) \times (M-N+1)$ in **valid** mode. Full and same modes need values outside the image. These come from zero padding (clip filter, black), wrap-around (circular), copy edge, or reflect across edge. Median filtering, thresholding, absolute values and squaring are not linear filters.

>[!warning] Notation Across the Slides
>The filtering slides write $F$ for the image, $H$ for the kernel and $G$ for the output. They use $\otimes$ for cross-correlation and $*$ for convolution. The slides on sharpening and template matching switch to $f$ for the image, $g$ for the kernel or template, and $h$ for the output. The letter $G$ also names the Gaussian. Read each formula with its own legend.

>[!warning] Two Slide Typos
>One Gaussian-filtering slide writes the exponent as $-(u^2+v^2)/\sigma^2$. The normalized 2D Gaussian with standard deviation $\sigma$ has $2\sigma^2$ in the denominator, as on the following slide. The output-size slide says the full output is the "sum" and the valid output the "difference" of the image and kernel sizes. The exact sizes are $M + N - 1$ and $M - N + 1$.

# Intuition

Many basic image edits are local. A blur replaces each pixel with an average of its neighbors. An edge detector compares each pixel with the pixel beside it. In both cases the rule is a weighted sum over a small window, and the rule is the same everywhere in the image. In 1D the simplest case is a moving average. The weights $[\dots, 0, 1, 1, 1, 1, 1, 0, \dots]/5$ replace each sample by the mean of five samples. Bell-shaped weights such as $[1, 4, 6, 4, 1]/16$ give nearer samples more influence. The output at one pixel is the [[3.4a Inner Product|inner product]] of the kernel with the image patch under it. "Linear" means the output depends linearly on the input image. "Filter" comes from signal processing, where a filter passes some frequencies and blocks others.

Linearity and shift invariance mean the kernel describes the filter completely. A filter of this kind is an [[2.2a LTI System|LTI system]], and its [[2.2c LTI Impulse Response|impulse response]] is its kernel. Feeding a single bright pixel into a convolution returns a copy of $H$. Feeding it into a cross-correlation returns $H$ rotated by $180°$. Cross-correlation is the natural "compare the kernel with this patch" operation, and [[2.1.5. Template Matching|template matching]] uses it in that sense. Convolution flips the kernel so that the impulse response is $H$ itself. The flip makes convolution commutative and associative, and it makes the convolution theorem of the [[2.2. Fourier Transform in Images|Fourier transform]] hold. The diagram shows which kernel weight meets which pixel in each case.

# Properties

#### *(When the Flip Matters)* The flip changes the output only for kernels that are not symmetric under a $180°$ rotation.

Box and Gaussian kernels satisfy $H[-u,-v] = H[u,v]$, so both operations give identical results. An antisymmetric kernel satisfies $H[-u,-v] = -H[u,v]$, and for it convolution returns the negative of cross-correlation. The derivative kernel $[1, 0, -1]$ is the standard case. A shift kernel changes direction. Cross-correlating with a $1$ at $H[0, 1]$, right of center, moves the image one pixel left, and convolving with the same kernel moves it right. Library names follow the math: `scipy.signal.convolve2d` flips and `scipy.signal.correlate2d` does not. PyTorch's `conv2d`, used in the [[5.2.1. Convolutional Layer|convolutional layers]] of CNNs, computes cross-correlation. The flip does not matter there, because the network learns whichever weights it needs.

#### *(Sum Rule)* The sum of the kernel weights is the filter's gain on a constant image.

If $F = c$ everywhere, then $G = c \sum_{u,v} H[u,v]$ at every interior pixel. A blur kernel that sums to $1$ therefore leaves flat regions and overall brightness unchanged. A kernel that sums to more than $1$ brightens the image, and one that sums to less darkens it. A common bug is a $9 \times 9$ box of ones without the factor $1/81$. It multiplies the brightness by $81$ and saturates almost every pixel to white. Derivative kernels sum to $0$, so they ignore a constant added to the whole image. They are not invariant to contrast, since multiplying the image by $a$ multiplies their output by $a$.

#### *(Separable Kernels)* A 2D Gaussian is the outer product of two 1D Gaussians, so it can be applied as two 1D passes.

The 2D Gaussian factors as $G_\sigma(x, y) = g_\sigma(x)\, g_\sigma(y)$, where $g_\sigma$ is the 1D Gaussian. By associativity, filtering with the 2D kernel equals filtering every row with $g_\sigma$ and then every column with $g_\sigma$. An $N \times N$ kernel costs $N^2$ multiplications per pixel, while two 1D passes cost about $2N$. One way to build the 2D kernel is to take a 1D Gaussian, for example from `cv2.getGaussianKernel`, and form its outer product with itself. The box filter is separable too. A disk-shaped kernel is not.

#### *(Kernel Size)* A Gaussian kernel needs a half-width of about $3\sigma$, or it starts to behave like a box.

The Gaussian never reaches zero, so every discrete kernel truncates it. At distance $3\sigma$ from the center the weight is $e^{-4.5} \approx 1.1\%$ of the center weight. In 1D the interval $[-3\sigma, 3\sigma]$ holds $99.73\%$ of the Gaussian's mass. A kernel cut much shorter has a visible jump at its border, and that jump brings back box-like artifacts. After truncation, divide by the sum of the weights so the kernel sums to $1$. Changing $\sigma$ without enlarging the kernel produces a different, truncated filter.

#### *(Boundary Artifacts)* Each way of inventing pixels beyond the border leaves its own artifact.

The table pads the row $[1, 2, 3, 4]$ by two pixels on each side.

| Method | Padded row |
|---|---|
| Zero padding (clip filter) | $0\ 0 \mid 1\ 2\ 3\ 4 \mid 0\ 0$ |
| Wrap-around (circular) | $3\ 4 \mid 1\ 2\ 3\ 4 \mid 1\ 2$ |
| Copy edge | $1\ 1 \mid 1\ 2\ 3\ 4 \mid 4\ 4$ |
| Reflect across edge | $2\ 1 \mid 1\ 2\ 3\ 4 \mid 4\ 3$ |

Zero padding pulls blurred borders toward black and creates false edges for derivative filters. Wrap-around mixes the left border with the right one, and it is the boundary that the discrete Fourier transform assumes. Copy edge and reflect usually look the most natural. In `scipy.signal.convolve2d` the options are `boundary='fill'` (zeros by default), `'wrap'` and `'symm'`, which reflects with the edge pixel repeated as in the table. `np.pad` offers `mode='edge'` for copy edge, and its `mode='reflect'` omits the edge pixel, giving $3\ 2 \mid 1\ 2\ 3\ 4 \mid 3\ 2$. Valid mode avoids the choice by dropping every output pixel whose window leaves the image.

#### *(Even-Length Kernels)* An even-length kernel has no center pixel, so its same-mode output is offset by half a pixel.

The two-tap difference $[-1, 1]$ estimates a derivative halfway between two pixels. In same mode the library must store that value at one of the two neighbors. For the row $[10, 10, 10, 50, 50, 50]$, `correlate2d` with $[-1, 1]$ puts the response $40$ at index $2$, and `convolve2d` puts $-40$ at index $3$. The odd kernel $[1, 0, -1]$ is centered on a pixel and has no such ambiguity. This is one reason to prefer it for gradients.

#### *(What Is Not a Convolution)* An operation is a convolution only if it is both linear and shift-invariant.

The [[2.1.4. Median Filter|median filter]] fails linearity. The medians of $[0, 0, 1]$ and of $[1, 0, 0]$ are both $0$, but the median of their sum $[1, 0, 1]$ is $1$. Gradient magnitude fails too, because it squares its inputs. A blur whose $\sigma$ changes across the image is linear but not shift-invariant, so no single kernel describes it. Such operations have no frequency response, and the convolution theorem does not apply to them.

# Examples

>[!example] (Easy) Shifting a Photo by One Pixel
>A $3 \times 3$ kernel has a $1$ in the middle of its right column and $0$ elsewhere, so $H[0, 1] = 1$. It is applied to a $5 \times 5$ image whose entries are $1, 2, \dots, 25$ in row-major order. The output uses same mode with zero padding.
>
>>[!example]- Which way does the image move under cross-correlation, and under convolution? Which kernel gives a left shift under convolution?
>>Cross-correlation gives $G[i,j] = H[0,1]\,F[i, j+1] = F[i, j+1]$. The first output row is $[2, 3, 4, 5, 0]$. Every value moved one column to the left, and the padded zero fills the right column. Convolution gives $G[i,j] = F[i, j-1]$, and the first output row is $[0, 1, 2, 3, 4]$, a shift to the right. To shift left with convolution, put the $1$ at $H[0,-1]$, the middle of the left column. The flip then moves it to the right side, which reproduces the cross-correlation result.

>[!example] (Medium) Where the Flip Changes the Answer
>A row of a photo crosses from a dark wall to a bright window: $F = [10, 10, 10, 50, 50, 50]$, indexed $0$ to $5$. The kernel is $H = [1, 0, -1]$ with $H[-1] = 1$, $H[0] = 0$ and $H[1] = -1$.
>
>>[!example]- Compute the valid-mode output of cross-correlation and of convolution. Then compute the same-mode and full-mode convolution with zero padding, and explain the values at the ends.
>>Cross-correlation gives $G[i] = H[-1]F[i-1] + H[1]F[i+1] = F[i-1] - F[i+1]$. The valid positions are $i = 1, \dots, 4$, and the output is $[0, -40, -40, 0]$. Convolution gives $G[i] = H[-1]F[i+1] + H[1]F[i-1] = F[i+1] - F[i-1]$, so the output is $[0, 40, 40, 0]$. The kernel is antisymmetric, so the flip negates every value. Convolution with $[1, 0, -1]$ reports a dark-to-bright step as positive, and cross-correlation reports it as negative.
>>
>>The valid output has $6 - 3 + 1 = 4$ entries. Same mode keeps $6$ entries by padding one zero on each side, and convolution gives $[10, 0, 40, 40, 0, -50]$. The end values $10$ and $-50$ are false edges. At $i = 0$ the kernel compares $F[1] = 10$ with a padded $0$. At $i = 5$ it compares a padded $0$ with $F[4] = 50$. Copy-edge padding would give $0$ at both ends. Full mode has $6 + 3 - 1 = 8$ entries, $[10, 10, 0, 40, 40, 0, -50, -50]$, and the extra entries at both ends are again caused by the padding.

>[!example] (Hard) Budgeting a Gaussian Blur
>A $1000 \times 1000$ grayscale photo is blurred with a Gaussian of $\sigma = 2$ pixels.
>
>>[!example]- Choose the kernel size. Give the output size in each mode, and count the multiplications per output pixel for the 2D kernel and for two 1D passes.
>>The half-width is $\lceil 3\sigma \rceil = 6$, so the kernel is $N = 13$ pixels wide. Its outermost weight is $e^{-6^2/(2 \cdot 2^2)} = e^{-4.5} \approx 0.011$ times the center weight, so the truncation is harmless. Full mode gives $1000 + 13 - 1 = 1012$ pixels per side. Same mode gives $1000$, and valid mode gives $1000 - 13 + 1 = 988$. The $13 \times 13$ kernel needs $169$ multiplications per output pixel. The Gaussian is separable, so a row pass and a column pass with the normalized 1D kernel need about $13 + 13 = 26$. The two routes give the same valid output up to floating-point rounding, because convolution is associative.
