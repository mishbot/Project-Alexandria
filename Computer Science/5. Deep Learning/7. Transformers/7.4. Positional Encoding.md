>[!note] Positional Encoding
>[[7.1. Attention|Self-attention]] ignores the order of its inputs. Permuting the tokens permutes the outputs in the same way. "The woman ate the raccoon" and "the raccoon ate the woman" would give the same set of vectors. A **positional encoding** tells the model where each token sits. The lecture lists four schemes:
>- **Sinusoidal**: add a fixed vector $\mathbf p_n$ to the embedding of the token at position $n$. The original transformer used sines and cosines of many frequencies. The lecture notes that this scheme is no longer used.
>- **NoPE**: use no positional encoding at all.
>- **Learned relative bias**: add a learned number $b_{t-i}$ to the score of query $t$ and key $i$. The number depends only on the offset $t - i$.
>- **RoPE** (rotary position embedding): rotate each query and each key by an angle proportional to its position. The score then depends on the two positions only through their offset.
>
>The sinusoidal encoding of Vaswani et al. (2017) has, for even $D$ and $j = 0, \dots, D/2 - 1$,
>$$p_{n,2j} = \sin(\omega_j n), \qquad p_{n,2j+1} = \cos(\omega_j n), \qquad \omega_j = 10000^{-2j/D}.$$
>The learned relative bias changes the attention weights to
>$$a_{ti} = \frac{\exp(s_{ti} + b_{t-i})}{\sum_{j}\exp(s_{tj} + b_{t-j})}, \qquad s_{ti} = \frac{\mathbf q_t^T\mathbf k_i}{\sqrt{D_k}}.$$
>RoPE in two dimensions uses the rotation matrix $\mathbf R_t$ by the angle $\omega t$. The score of query $t$ and key $i$ becomes
>$$(\mathbf R_t\mathbf q_t)^T(\mathbf R_i\mathbf k_i) = \mathbf q_t^T\mathbf R_t^T\mathbf R_i\,\mathbf k_i = \mathbf q_t^T\mathbf R_{i-t}\,\mathbf k_i, \qquad \mathbf R_t = \begin{bmatrix}\cos\omega t & -\sin\omega t \\ \sin\omega t & \cos\omega t\end{bmatrix}.$$

# Intuition

The Fall 2022 lecture 19 notes describe the sinusoidal encoding with the hands of a clock. Each pair $(\sin\omega_j n, \cos\omega_j n)$ is a hand that turns at speed $\omega_j$. The pair with $\omega_0 = 1$ turns fast, and the last pairs turn very slowly. Position $n$ sets the angle of every hand. Moving $k$ positions turns every hand by a fixed angle, and turning is a linear map. A query can therefore ask for "the token $3$ places back" with a learned linear map. The network has no sine units, but it does not need any. The learned projections $\mathbf W_q$ and $\mathbf W_k$ can learn the needed rotations.

The obvious way to add position is to concatenate $\mathbf p_n$ to the embedding $\mathbf x_n$. That costs extra dimensions. In practice $\mathbf p_n$ is added to $\mathbf x_n$, which seems to mix content and position. It works because the vectors are long, with hundreds or thousands of entries. Write a query as a content part plus a position part, $\mathbf q = \mathbf q_{\mathrm{c}} + \mathbf q_{\mathrm{p}}$, and the same for a key. Then
$$\mathbf q^T\mathbf k = \mathbf q_{\mathrm{c}}^T\mathbf k_{\mathrm{c}} + \mathbf q_{\mathrm{c}}^T\mathbf k_{\mathrm{p}} + \mathbf q_{\mathrm{p}}^T\mathbf k_{\mathrm{c}} + \mathbf q_{\mathrm{p}}^T\mathbf k_{\mathrm{p}}.$$
Unrelated vectors in high dimensions are nearly orthogonal, so the two cross terms are small. A query can then match on content, on position or on both.

The last two schemes act inside attention instead of on the inputs. Position only matters when a query compares itself with keys. The relative bias and RoPE change exactly that comparison.

# Properties

#### *(Shifts Are Rotations)* Shifting a sinusoidal encoding by $k$ positions is a rotation that does not depend on the position $n$.

Take one pair with angle $\theta = \omega_j n$ and shift by $\phi = \omega_j k$. The angle addition formulas give
$$\begin{bmatrix}\sin(\theta + \phi) \\ \cos(\theta + \phi)\end{bmatrix} = \begin{bmatrix}\cos\phi & \sin\phi \\ -\sin\phi & \cos\phi\end{bmatrix}\begin{bmatrix}\sin\theta \\ \cos\theta\end{bmatrix}.$$
The matrix is a rotation that depends on $k$ but not on $n$. Stacking one such block per pair gives $\mathbf p_{n+k} = \mathbf M_k\mathbf p_n$ for a block-diagonal $\mathbf M_k$. The inner product of two encodings also depends only on the offset:
$$\mathbf p_n^T\mathbf p_m = \sum_{j}\big(\sin\omega_j n\,\sin\omega_j m + \cos\omega_j n\,\cos\omega_j m\big) = \sum_j\cos\big(\omega_j(n - m)\big).$$
The encoding is absolute, since each position gets its own vector, but relative positions are easy to read from it.

#### *(The Relative Bias Changes the Attention Matrix)* The learned bias adds a matrix with constant diagonals to the scores, the same for every input.

Entry $(t, i)$ of the bias matrix is $b_{t-i}$, so every diagonal holds one number. Such a matrix is called a Toeplitz matrix. The bias does not depend on the tokens, only on how far apart they are. A head can learn $b_0$ large and $b_{t-i}$ falling with the distance, which makes it prefer recent tokens. For a context of $N$ tokens, each head learns $2N - 1$ numbers, or $N$ numbers if attention is causal. Shifting a whole sentence to later positions leaves every offset, and so every bias, unchanged. Prince notes that relative position often matters more than absolute position, since a passage of text can start anywhere.

#### *(RoPE Gives Relative Scores)* Rotating queries and keys by their positions makes every score depend on the positions only through $i - t$.

Rotations satisfy $\mathbf R_t^T = \mathbf R_{-t}$ and $\mathbf R_{-t}\mathbf R_i = \mathbf R_{i-t}$. The score $(\mathbf R_t\mathbf q_t)^T(\mathbf R_i\mathbf k_i)$ is therefore $\mathbf q_t^T\mathbf R_{i-t}\mathbf k_i$. Rotations also keep lengths, so the norms of queries and keys do not change. For $D_k > 2$, RoPE splits the query and the key into $D_k/2$ pairs. It rotates pair $j$ by $\omega_j t$, with frequencies like the sinusoidal ones. Each layer rotates its queries and keys but never its values. Nothing is added to the embeddings.

>[!warning] Not Taught in Lecture
>The general form follows Su et al. (2021). The lecture shows the two-dimensional case.

With $\theta_j = \mathrm{base}^{-2j/D_k}$ for $j = 0, \dots, D_k/2 - 1$, RoPE maps the pair $(x_{2j}, x_{2j+1})$ of a vector at position $t$ to
$$x'_{2j} = x_{2j}\cos(t\theta_j) - x_{2j+1}\sin(t\theta_j), \qquad x'_{2j+1} = x_{2j}\sin(t\theta_j) + x_{2j+1}\cos(t\theta_j).$$
The usual base is $10{,}000$. Many code bases pair coordinate $j$ with coordinate $j + D_k/2$ instead of $2j + 1$. This "rotate half" version precomputes the cosines and sines and needs no matrix. The two pairings differ only by a fixed reordering of the coordinates, which the learned projections can absorb.

#### *(Why NoPE Can Work)* A decoder with causal attention can find positions without any encoding, because the mask itself depends on position.

>[!warning] Not Taught in Lecture
>The lecture names NoPE without explaining it. The explanation follows Haviv et al. (2022) and Kazemnejad et al. (2023).

Unmasked self-attention cannot tell positions apart. The causal mask breaks this symmetry, since token $n$ sees exactly $n$ tokens. A head that spreads its weight evenly gives the first token the weight $1/n$. If the first token is `<start>`, the output at position $n$ then carries the number $1/n$. Later layers can turn this into a sense of position. Decoder-only language models trained this way perform about as well as models with encodings. An encoder without a mask cannot do this.

#### *(Learned Absolute Encodings)* Many models learn one vector per position instead of using sinusoids, which fixes their maximum input length.

>[!warning] Not Taught in Lecture
>This follows Prince §12.3.1 and its chapter notes.

BERT and GPT-3 learn a table of position vectors, like the [[7.3. Token Embeddings|token table]]. The table has one row per position up to the training length, such as $512$ for BERT. A longer input has positions with no vector. Prince reports that learned and sinusoidal encodings perform about the same. Relative encodings did better in the comparison he cites. Sinusoidal encodings, relative biases and RoPE can be computed for any position. Press et al. (2022) show that sinusoidal and rotary models still degrade on inputs longer than in training.

# Examples

>[!example] (Easy) Sinusoidal Encodings
>Use $D = 4$, so the two frequencies are $\omega_0 = 1$ and $\omega_1 = 10000^{-1/2} = 0.01$.
>
>>[!example]- Compute $\mathbf p_0$, $\mathbf p_1$ and $\mathbf p_2$. Check that $\mathbf p_0^T\mathbf p_1 = \mathbf p_1^T\mathbf p_2$.
>>The encodings are
>>$$\mathbf p_0 = (0,\ 1,\ 0,\ 1), \quad \mathbf p_1 = (0.841,\ 0.540,\ 0.010,\ 1.000), \quad \mathbf p_2 = (0.909,\ -0.416,\ 0.020,\ 1.000).$$
>>The first pair turns by $1$ radian per position. The second pair turns by $0.01$ radians and barely moves. The inner products are $\mathbf p_0^T\mathbf p_1 = \cos 1 + \cos 0.01 = 1.540$ and $\mathbf p_1^T\mathbf p_2 = 1.540$. Both pairs of positions have offset $1$, so their inner products match. For offset $2$, $\mathbf p_0^T\mathbf p_2 = \cos 2 + \cos 0.02 = 0.584$.

>[!example] (Medium) A Relative Bias
>A causal head has the biases $b_0 = 1$, $b_1 = 0$ and $b_2 = -1$. All content scores $s_{ti}$ equal $1$, so only the biases matter.
>
>>[!example]- Find the weights of the query at $t = 3$ on the keys $i = 1, 2, 3$. Repeat for the query at $t = 5$ on the keys $3, 4, 5$.
>>The query at $t = 3$ has the offsets $2$, $1$ and $0$. Its scores plus biases are $0$, $1$ and $2$. The softmax gives
>>$$(a_{31}, a_{32}, a_{33}) = (0.090,\ 0.245,\ 0.665).$$
>>The head prefers the current token and gives less weight further back. The query at $t = 5$ has the same offsets to keys $3$, $4$ and $5$. It gives them the same weights. The pattern moves with the query, and the head learns it once for all positions. The constant content score cancels in the softmax.

>[!example] (Hard) RoPE by Hand
>Use $D_k = 2$ and $\omega = \pi/4$. A query $\mathbf q = (1, 2)$ sits at position $t = 2$, and a key $\mathbf k = (3, -1)$ sits at position $i = 1$.
>
>>[!example]- Compute the rotated score in two ways. Then move both tokens $3$ places later and compare.
>>Rotating the query by $2\omega = \pi/2$ gives $\mathbf R_2\mathbf q = (-2, 1)$. Rotating the key by $\omega = \pi/4$ gives
>>$$\mathbf R_1\mathbf k = \tfrac{1}{\sqrt 2}(3 + 1,\ 3 - 1) = (2.828,\ 1.414).$$
>>Their inner product is $-5.657 + 1.414 = -4.243$.
>>
>>The second way uses $\mathbf q^T\mathbf R_{i-t}\mathbf k$ with $i - t = -1$. Rotating $\mathbf k$ by $-\pi/4$ gives $\tfrac{1}{\sqrt 2}(3 - 1,\ -3 - 1) = (1.414, -2.828)$. The inner product with $\mathbf q$ is $1.414 - 5.657 = -4.243$, the same.
>>
>>At positions $t = 5$ and $i = 4$, the offset is still $-1$, so the score is again $-4.243$. Without RoPE the score would be $\mathbf q^T\mathbf k = 1$ at every pair of positions. With the key $2$ places back instead of $1$, the score becomes $\mathbf q^T\mathbf R_{-2}\mathbf k = -7$. The score now carries the offset, while the lengths of $\mathbf q$ and $\mathbf k$ stay the same.
