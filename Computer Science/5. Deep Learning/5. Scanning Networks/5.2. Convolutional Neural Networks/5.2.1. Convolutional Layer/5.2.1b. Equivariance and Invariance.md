>[!note] Equivariance and Invariance
>A function $f$ is **equivariant** (or covariant) to a transformation $t$ if transforming the input transforms the output in the same way:
>$$f\big[t[\mathbf{x}]\big] = t\big[f[\mathbf{x}]\big].$$
>It is **invariant** to $t$ if transforming the input leaves the output unchanged:
>$$f\big[t[\mathbf{x}]\big] = f[\mathbf{x}].$$
>An image classifier should be invariant to translation, since a shifted mountain is still a mountain. A segmentation network should be equivariant, since its label map must move with the image. The parts of a CNN treat translation differently:
>- **Convolution** with stride $1$ is equivariant: shifting the input shifts every feature map by the same amount. This holds exactly for circular shifts with circular padding, and away from the border otherwise.
>- **Pointwise operations**, such as adding the bias and applying the ReLU, act on every position alike and keep equivariance.
>- **Strided convolution and pooling** are equivariant only to shifts by a multiple of the stride. Max pooling gives partial invariance to small shifts that keep each maximum inside its window.
>- **Global average pooling** averages each feature map over all positions. It is invariant to circular shifts, and to any shift that keeps the pattern away from the border.
>
>A stack of equivariant layers is equivariant, and an invariant layer at the end makes the whole network invariant. Nothing in a standard CNN builds in rotation, scale or reflection. The network learns those from the variation in its training data, mostly supplied by [[4.4.2. Data Augmentation|data augmentation]].

# Intuition

Weight sharing runs the same detector at every position. A detector for a vertical edge fires wherever a vertical edge is, so moving the edge moves the response. This is equivariance, and it means the network does not have to learn the same pattern again at every location. A classifier then has to forget where the pattern was. Pooling does this. Global average pooling forgets position completely, while a $2 \times 2$ max pooling forgets only shifts within its window.

The guarantees are exact only in idealized settings. Zero padding treats the border differently from the interior, and a stride of $2$ cannot represent a one-pixel shift. Real CNNs are therefore only approximately equivariant. A shift of a single pixel can change the prediction of a trained classifier noticeably.

# Properties

#### *(Composition)* Equivariant layers compose into an equivariant network, and an invariant layer anywhere after them makes the network invariant.

If $f_1$ and $f_2$ are both equivariant to $t$, then
$$f_2\big[f_1[t[\mathbf{x}]]\big] = f_2\big[t[f_1[\mathbf{x}]]\big] = t\big[f_2[f_1[\mathbf{x}]]\big].$$
If $g$ is invariant to $t$, then $g[f_1[t[\mathbf{x}]]] = g[t[f_1[\mathbf{x}]]] = g[f_1[\mathbf{x}]]$. A single layer that is not equivariant, placed before the invariant one, removes the guarantee for the whole network. A single strided layer limits the whole network to shifts by a multiple of its stride. Layers after the invariant one, such as the final dense classifier, keep the invariance. Their input no longer changes under the shift.

#### *(Borders and Strides)* Translation equivariance is exact only for circular shifts under circular padding, and with stride $s$ only for shifts by multiples of $s$.

Zero padding replaces the values beyond the border with zeros. When a pattern moves toward the edge, part of it falls into the padding. The edge units then respond differently from units in the interior. A stride of $s$ breaks equivariance in a different way. Shifting the input by one pixel does not shift a stride-2 output by a whole unit. The layer is equivariant only to shifts by multiples of $s$, and the output then moves by $1/s$ of the shift. A one-pixel shift can even move a feature from a sampled position to a skipped one. Its response then disappears from the output.

>[!warning] Not Taught in Lecture
>Prince mentions in the chapter notes that max-blur-pooling (Zhang, 2019) restores much of the lost shift equivariance. It blurs each map before subsampling it.

#### *(Weight Sharing Is What Gives Equivariance)* Among linear layers on a circular signal, the shift-equivariant ones are exactly the convolutions.

>[!warning] Not Taught in Lecture
>Lecture and Prince state that convolution is equivariant. The converse below is standard linear algebra.

A linear layer $\mathbf{h} = \boldsymbol{\Omega}\mathbf{x}$ on a length-$D$ signal is equivariant to circular shifts exactly when $\boldsymbol{\Omega}\mathbf{S} = \mathbf{S}\boldsymbol{\Omega}$, where $\mathbf{S}$ is the cyclic shift matrix. Entry by entry, this says $\Omega_{i+1,\, j+1} = \Omega_{i,\, j}$ with indices taken modulo $D$. Every diagonal is then constant and wraps around, so $\boldsymbol{\Omega}$ is a circulant matrix. A circulant matrix is a circular convolution with the kernel stored in its first row. A [[5.2.1. Convolutional Layer|locally connected layer]] gives each row its own weights, so it is not equivariant. For linear layers on circular signals, equivariance and weight sharing are therefore equivalent.

#### *(Only Translation Is Built In)* A convolution is not equivariant to rotation, scaling or reflection.

A kernel tuned to vertical edges does not respond to horizontal ones. Rotating the input by $90°$ therefore does not rotate the feature maps. It changes which kernels respond. A network becomes approximately invariant to such transformations only by seeing transformed examples during training. This is the role of [[4.4.2. Data Augmentation|data augmentation]]. Group-equivariant CNNs build some rotations and reflections into the architecture. They share weights across rotated copies of each kernel, but they are not standard.

# Derivation

Write a stride-1 1D layer as $\mathbf{h} = \boldsymbol{\omega} \star \mathbf{x}$, so $h[r] = \sum_i \omega[i] \cdot x[r+i]$. Let $t$ shift the input by $\tau$, so $t[\mathbf{x}][r] = x[r-\tau]$. Applying the layer to the shifted input gives
$$(\boldsymbol{\omega} \star t[\mathbf{x}])[r] = \sum_i \omega[i] \cdot x[r+i-\tau] = h[r-\tau] = t[\mathbf{h}][r].$$
In operator form, $\boldsymbol{\omega} \star t[\mathbf{x}] = t[\boldsymbol{\omega} \star \mathbf{x}]$. The output is $\mathbf{h}$ shifted by $\tau$, which is equivariance. The step uses only that the same $\omega[i]$ appear at every position $r$. The bias adds the same $\beta$ everywhere and the activation acts on each $h[r]$ alone, so neither changes the argument. The indices $r + i - \tau$ must exist. With circular padding they always do, since they wrap around. With zero padding they do whenever the shifted pattern stays away from the border.

# Examples

>[!example] (Easy) Sorting Functions by Their Symmetry
>Consider five functions of a vector $\mathbf{x} \in \mathbb{R}^D$: the elementwise ReLU, the sum $\sum_i x_i$, the first entry $x_1$, the centered vector $\mathbf{x} - \bar{x}\mathbf{1}$, and the cumulative sum $c_k = \sum_{i \le k} x_i$.
>
>>[!example]- Which are equivariant, invariant or neither under circular shifts?
>>- **ReLU** is equivariant, because it acts on each entry alone.
>>- **The sum** is invariant, because a circular shift only reorders the entries.
>>- **The first entry** is neither. Shifting $[1, 0, 0]$ to $[0, 1, 0]$ changes it from $1$ to $0$, and its output is a scalar that a shift cannot move.
>>- **The centered vector** is equivariant. The mean is invariant, and subtracting it is a pointwise operation.
>>- **The cumulative sum** is neither. For $[1, 0, 0]$ it gives $[1, 1, 1]$, and for the shifted $[0, 1, 0]$ it gives $[0, 1, 1]$. Shifting the first output gives $[1, 1, 1]$ again, not $[0, 1, 1]$, so the map is not equivariant. The two outputs differ, so it is not invariant either.

>[!example] (Medium) A Stride Breaks Equivariance
>A layer with a $1 \times 1$ kernel $\omega = 1$ and stride $2$ keeps the entries at positions $1$, $3$ and $5$ of a length-$6$ signal. It is applied to $\mathbf{x} = [4, 0, 1, 0, 2, 0]$ and to its circular shifts by one and by two positions.
>
>>[!example]- Compute the three outputs.
>>The original gives $[4, 1, 2]$. The shift by one is $[0, 4, 0, 1, 0, 2]$, which gives $[0, 0, 0]$. Every nonzero value moved to a skipped position, so the response vanished. The shift by two is $[2, 0, 4, 0, 1, 0]$, which gives $[2, 4, 1]$. This is $[4, 1, 2]$ shifted circularly by one. A shift by $2$ in the input moves the output by $2/s = 1$. A shift by $1$ has no output counterpart at all.

>[!example] (Hard) Invariance Needs Circular Padding
>A tiny network applies a 1D convolution with kernel $\boldsymbol{\omega} = [1, 2, 3]^T$, no bias and stride $1$ to an input of length $4$. A ReLU and a global average over the four positions follow. The input $\mathbf{x} = [1, 0, 0, 0]^T$ is compared with its shift $\mathbf{x}' = [0, 1, 0, 0]^T$.
>
>>[!example]- Compute the feature maps and outputs with circular padding and with zero padding.
>>Each unit is $h[r] = x[r-1] + 2x[r] + 3x[r+1]$. With circular padding, $x[0] = x[4]$ and $x[5] = x[1]$. For $\mathbf{x}$ this gives $\mathbf{h} = [2, 1, 0, 3]$, where $h[4] = 3x[5] = 3x[1]$ wraps around. For $\mathbf{x}'$ it gives $\mathbf{h}' = [3, 2, 1, 0]$, which is $\mathbf{h}$ shifted circularly by one position, so the layer is equivariant. Both averages are $6/4 = 1.5$, so the network is invariant to the shift.
>>
>>With zero padding, $x[0] = x[5] = 0$. Now $\mathbf{h} = [2, 1, 0, 0]$, because the contribution $3x[1]$ to $h[4]$ is lost. The shifted input still gives $\mathbf{h}' = [3, 2, 1, 0]$. The averages are $0.75$ and $1.5$, so the output changes. The pattern at the border lost part of its response to the padding. Shifting $\mathbf{x}'$ one more step to $[0, 0, 1, 0]$ gives $[0, 3, 2, 1]$, again with average $1.5$. Zero padding keeps the invariance for shifts in the interior and breaks it at the border.
