>[!note] U-Net
>A **U-Net** (Ronneberger et al., MICCAI 2015) is a convolutional encoder-decoder with skip connections. It is built for **dense prediction**, where the output holds one value or vector per pixel. It maps an $H \times W \times C$ input to an $H \times W \times F$ output. The **encoder** alternates convolutions with downsampling by max or average pooling or by stride-2 convolution. Each level halves the height and width and usually increases the number of channels. The **decoder** mirrors the encoder with upsampling by transpose convolution or unpooling, and each level doubles the height and width. **Skip connections** copy the encoder activations at each resolution and concatenate them along the channel axis with the decoder activations of the same size. The convolutions after each concatenation combine fine detail from the encoder with context from the decoder. Drawn with resolution decreasing downward, the network has the shape of a U, which gives it its name. The original U-Net used valid convolutions, which shrink each map by two pixels per $3 \times 3$ layer. Its encoder maps were therefore cropped to the decoder's size before concatenation. Later versions use zero padding and need no cropping. The original network has no dense layers, so after training it runs on images of any size.
>
>The design meets two needs at once. Each output pixel needs a large receptive field, and the network should not waste computation. $n$ stacked $3 \times 3$ convolutions with stride 1 have a receptive field of $2n + 1$ pixels, so seeing $200$ pixels takes $100$ layers. Running a CNN on a patch around every pixel recomputes the same features many times. Downsampling grows the receptive field quickly and makes deep layers cheap. It also discards high-frequency detail, so a decoder without skips produces blobby outputs that miss object boundaries. The skips restore that detail. For kernel size $k$, stride $s$ and padding $p$, a convolution maps size $H$ to $\lfloor (H + 2p - k)/s \rfloor + 1$, and a transpose convolution maps $H$ to $(H - 1)\,s - 2p + k$.
>
>U-Nets are used for semantic segmentation (the original use, on biomedical images), depth and surface-normal prediction, [[8.3. Image Colorization|colorization]], the generator of [[8.4. Pix2Pix]], and the denoiser in [[10.3.1. Diffusion Models|diffusion]] and [[10.3.2. Flow Matching|flow matching]] models. Every U-Net is an encoder-decoder. An encoder-decoder without skip connections is not a U-Net.

>[!warning] Counting Overlapping Patches
>The lecture asks how many times a per-patch CNN filters a single pixel and gives the answer $(2n - 1)^2$. That count holds when $n$ is the patch half-width, so that each patch is $(2n - 1) \times (2n - 1)$ pixels. For patches of side $n$ cut around every pixel, each pixel lies in $n^2$ patches. In both readings the repeated work grows with the square of the patch size.

>[!warning] Two Meanings of Encoder-Decoder
>In a U-Net, the encoder is the downsampling path and the decoder is the upsampling path of one convolutional network. In [[7.5. Encoder and Decoder Models|transformer encoder-decoders]], the same words name two stacks of attention layers joined by cross-attention. The shared idea is a compressed internal representation, but the mechanisms differ.

# Intuition

A classification CNN shrinks an image to one vector. Per-pixel tasks, such as labeling which pixels belong to a cyclist, need an output as large as the input. Each output pixel still needs context from far away. A patch of shirt is much easier to label "person" when the network can see the rest of the person. Two naive designs fail. Stacking stride-1 convolutions keeps full resolution, but the receptive field grows by only two pixels per layer. Cropping a patch around every pixel and classifying it gives enough context. Neighboring patches overlap almost entirely, however, so the same features are computed again and again. Large receptive fields and low cost are in direct conflict for both designs.

The encoder-decoder resolves the conflict by downsampling toward the middle of the network and upsampling back out. Every halving doubles the reach of the following $3 \times 3$ convolutions and divides the cost per layer by four. Downsampling also loses detail. Like a downsampled image in [[2.3. Resampling|resampling]], the bottleneck has lost the high frequencies, and the decoder cannot invent them. The U-Net copies the encoder's high-resolution activations across to the decoder, as the dashed arrows in the figure show. The figure is the MNIST U-Net from Project 3, with $D$ hidden channels.

# Properties

#### *(Receptive Field Arithmetic)* Each downsampling doubles the number of input pixels that every later convolution adds to the receptive field.

Track two numbers through the network: the receptive field $r$, and the jump $j$, the distance in input pixels between neighboring outputs of a layer. Both start at $1$. A layer with kernel size $k$ and stride $s$ updates them as
$$r \leftarrow r + (k - 1)\,j, \qquad j \leftarrow j\,s.$$
A stride-1 $3 \times 3$ convolution adds $2j$ to $r$. Without downsampling $j$ stays $1$, which gives $2n + 1$ after $n$ layers. After $m$ halvings $j = 2^m$, and each $3 \times 3$ convolution adds $2^{m+1}$ pixels. Each halving also divides the area of the feature map by four, so deep layers stay cheap even with more channels. The receptive field is a window, and padding can cover part of it. Features near the border see less of the image than features near the center.

#### *(Where Detail Is Lost)* The high-frequency detail sits in the early, high-resolution encoder layers, and skip connections carry it to the output.

Halving the resolution halves the highest frequency that a feature map can represent, the same limit that motivates [[2.4. Anti-Aliasing|anti-aliasing]]. Fine edges and exact object boundaries are high-frequency content. A decoder that sees only the bottleneck must guess them, so segmentation masks come out blobby and slightly misaligned with the image. Copying the early encoder activations forward gives the decoder that detail at the right resolution. The convolutions after each skip learn how to fuse the copied detail with the decoded context.

#### *(Concatenating Skips)* U-Net skips stack channels side by side, so the next convolution can weigh detail and context separately.

Concatenating a $D_1$-channel tensor with a $D_2$-channel tensor of the same height and width gives $D_1 + D_2$ channels. The next convolution has separate weights for each group. A [[5.2.5. Residual Networks|residual block]] in a ResNet instead outputs $x + F(x)$, where $F$ is a few convolution layers. Addition keeps the channel count, and residual blocks let networks with hundreds of layers train. A U-Net skip spans the whole encoder-decoder at one scale, while a residual skip spans a few layers. Many denoising U-Nets use residual blocks inside each level and concatenating skips across levels.

#### *(Skips Carry What Smoothing Removes)* An encoder that averages away noise also averages away sharp edges, and the skip connection brings part of the edge back.

Consider a 1D signal that steps from $0$ to $9$, observed with independent noise. An encoder level that convolves with $[\tfrac{1}{3}, \tfrac{1}{3}, \tfrac{1}{3}]$ divides the noise variance by three, and it also spreads the step over three samples. A $2\times$ pooling then merges neighboring samples, and [[5.2.3. Upsampling|duplication upsampling]] gives each merged pair identical values. The two outputs on either side of a jump that falls inside a pooling window become equal, so the decoder cannot place the edge more precisely than the pooling grid. Combining the upsampled signal with the encoder's first-level output restores part of the difference between neighbors. The skip also carries that level's noise, which is less smoothed than the bottleneck's. A skip therefore trades some noise for spatial precision, and the convolutions after it learn how to weight the two. Max pooling in such an encoder adds a further upward bias on noisy flat regions, as [[5.2.2. Pooling]] shows.

#### *(Per-Patch Waste)* Classifying a patch around every pixel recomputes shared features once per overlapping patch.

With $n \times n$ patches cut around every pixel, each pixel lies in $n^2$ patches, and the first layer processes it again in each one. For $64 \times 64$ patches that is $4096$ times. A U-Net computes each feature map once over the whole image and shares it among all output pixels. The encoder computes the features that a patch classifier would compute, and the decoder turns its coarse output back into a full-resolution map.

#### *(Conditioning the Network)* Project 3 injects the time $t$ and the class $c$ by scaling and shifting whole channels.

An FCBlock is a linear layer, a GELU, and a second linear layer. It maps the scalar $t \in [0, 1]$, or the one-hot class vector $c \in \mathbb{R}^{10}$, to one number per channel. Each number multiplies or shifts its entire channel, the same at every pixel. The time-only model replaces the $2D \times 7 \times 7$ output of Unflatten by $t_1 \odot \text{unflatten}$ and the $D \times 14 \times 14$ output of the first UpBlock by $t_2 \odot \text{up}_1$. The class-conditioned model uses $c_1 \odot \text{unflatten} + t_1$ and $c_2 \odot \text{up}_1 + t_2$. Here $t_1, t_2$ come from FCBlocks applied to $t$ and $c_1, c_2$ from FCBlocks applied to $c$. During training the class vector is zeroed 10% of the time, which enables [[10.3.2. Classifier-Free Guidance|classifier-free guidance]]. One set of weights then serves every time step and every class.

#### *(Block Sizes Vary)* The number of levels, the channel counts and the bottleneck size are design choices.

Some networks stop downsampling while the bottleneck still has spatial extent. Others encode all the way to a single vector and decode from it. Project 3 does the second. Its Flatten layer averages the $7 \times 7$ map to $1 \times 1$, and its Unflatten layer expands it back with a $7 \times 7$ transpose convolution. Diagrams of U-Nets should not be read as fixed block sizes.

# Examples

>[!example] (Easy) Tensor Shapes in the Project 3 U-Net
>Project 3 builds a U-Net for $1 \times 28 \times 28$ MNIST digits with $D = 64$ hidden channels. Written as (kernel, stride, padding), DownConv is a convolution $(3, 2, 1)$, UpConv is a transpose convolution $(4, 2, 1)$, Flatten is a $7 \times 7$ average pool, and Unflatten is a transpose convolution $(7, 7, 0)$.
>
>>[!example]- Compute the spatial size after each of these layers and the channel count after each concatenation.
>>The first DownConv maps $28$ to $\lfloor (28 + 2 - 3)/2 \rfloor + 1 = 14$, and the second maps $14$ to $\lfloor (14 + 2 - 3)/2 \rfloor + 1 = 7$. Flatten maps $7$ to $(7 - 7)/7 + 1 = 1$. Unflatten maps $1$ to $(1 - 1) \cdot 7 - 0 + 7 = 7$. The first UpConv maps $7$ to $(7 - 1) \cdot 2 - 2 + 4 = 14$, and the second maps $14$ to $(14 - 1) \cdot 2 - 2 + 4 = 28$. The transpose convolution $(4, 2, 1)$ gives $(H - 1) \cdot 2 - 2 + 4 = 2H$ for every $H$, which makes it a common choice for doubling. At $7 \times 7$ the encoder's $2D = 128$ channels meet the Unflatten output's $128$ channels, giving $4D = 256$. At $14 \times 14$ and at $28 \times 28$ the concatenation gives $D + D = 128$ channels. A final ConvBlock reduces this to $D$, and a $3 \times 3$ convolution produces the $1 \times 28 \times 28$ output.

>[!example] (Medium) Receptive Field of the Project 3 Encoder
>The encoder of the same network applies, in order, two stride-1 $3 \times 3$ convolutions (a ConvBlock), a DownConv $(3, 2, 1)$ and two stride-1 $3 \times 3$ convolutions (a DownBlock), and a second DownBlock. All convolutions use padding $1$.
>
>>[!example]- Find the receptive field of one feature at the $7 \times 7$ level. How many stride-1 $3 \times 3$ convolutions would give the same receptive field? Does every $7 \times 7$ feature see the whole digit?
>>Apply $r \leftarrow r + 2j$ for each $3 \times 3$ layer and $j \leftarrow 2j$ after each stride-2 layer, starting from $r = j = 1$.
>>
>>| layer | $r$ | $j$ |
>>|---|---|---|
>>| conv, conv | $3$, $5$ | $1$ |
>>| DownConv | $7$ | $2$ |
>>| conv, conv | $11$, $15$ | $2$ |
>>| DownConv | $19$ | $4$ |
>>| conv, conv | $27$, $35$ | $4$ |
>>
>>Eight layers give a $35 \times 35$ receptive field. Stride-1 $3 \times 3$ convolutions would need $(35 - 1)/2 = 17$ layers, all at full $28 \times 28$ resolution. The window is larger than the digit, but padding covers part of it near the border. Tracing the index ranges shows that the features in rows and columns $3$ and $4$ (counting from $0$) of the $7 \times 7$ map see all $28$ pixels in each direction. The corner feature sees only the $18 \times 18$ corner of the image. The Flatten layer then averages all $49$ features, so the bottleneck vector summarizes the whole digit.
