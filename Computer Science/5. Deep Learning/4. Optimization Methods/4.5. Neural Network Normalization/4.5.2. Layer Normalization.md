>[!note] Layer Normalization
>**Layer normalization** (LayerNorm) standardizes the activations of one example using statistics computed within that example. For an example whose layer holds the $D$ values $h_1, \dots, h_D$, it computes
>$$m = \frac{1}{D}\sum_{d=1}^{D} h_d, \qquad s = \sqrt{\frac{1}{D}\sum_{d=1}^{D} (h_d - m)^2},$$
>and outputs
>$$h_d \leftarrow \gamma_d\,\frac{h_d - m}{s + \epsilon} + \delta_d.$$
>The $D$ values depend on the kind of layer:
>- In a **convolutional layer** they are all $C \times H \times W$ activations of the example, so the statistics run over every channel and every position. The learned scale and offset are shared by all positions of a channel, so $\gamma_d$ and $\delta_d$ depend only on the channel that holds value $d$.
>- In a [[7.2. Transformer Architecture|transformer]] they are the features of one token, and each token is normalized on its own.
>
>The standard deviation $s$ is the root-mean-square norm of the centered vector $\mathbf{h} - m\mathbf{1}$.
>
>LayerNorm does not depend on the batch. It computes the same function during training and at test time, works with a batch of one, and needs no stored statistics. It is the standard normalization in transformers and recurrent networks. Unlike [[4.5.1. Batch Normalization|batch normalization]], it adds no noise from the batch, so it lacks that source of regularization.

# Intuition

Batch normalization asks how an activation compares with the same activation in other examples. Layer normalization asks how it compares with the other activations of the same example. The second question can always be answered, whatever the batch looks like, which is why LayerNorm took over in sequence models. A sentence of any length can be normalized one token at a time, and the computation at test time is the same as during training.

The price is what the normalization erases. LayerNorm removes the overall level and spread of each example's activations. If one input produces a layer whose activations are all three times those of another, the two become identical after LayerNorm. Batch normalization would keep that difference, since it compares the two examples feature by feature.

# Properties

#### *(No Batch Coupling)* Each example is normalized independently, so the layer behaves identically for every batch size and at test time.

Batch normalization's output for one example depends on the other examples in the batch, and its test-time behavior depends on frozen statistics. LayerNorm has neither dependence. It works with a batch of one, with batches split across machines, and with sequences of any length. Each token of a sequence is normalized with its own statistics, so nothing has to be stored per time step. Training and testing use the same formula, so there is no train-test mismatch to manage.

#### *(What It Removes)* LayerNorm makes a layer's output invariant to shifting or rescaling all of its input activations together.

If every $h_d$ of an example is replaced by $a h_d + b$ with $a > 0$, the mean becomes $am + b$, the spread becomes $as$, and the standardized values do not change. The overall magnitude of a layer's response to an input is therefore lost after the layer. This is useful when that magnitude is a nuisance, such as the length of a token vector growing through many residual blocks. It is harmful when the magnitude carries meaning that later layers need. The learned $\gamma$ and $\delta$ cannot restore it, because they are the same for every example.

#### *(Placement in Transformers)* Modern transformers apply LayerNorm at the start of each residual block.

>[!warning] Not Taught in Lecture
>Lecture introduced the pre-norm convention for residual blocks but had not yet covered transformers when this note was written.

In a pre-norm block the input of the attention or feedforward branch is normalized, and the branch's output is added to the unnormalized input. This keeps a clean identity path through the [[5.2.5. Residual Networks|residual connections]], as in pre-activation ResNets. The original transformer applied LayerNorm after each addition instead, which is called post-norm.

# Examples

>[!example] (Easy) Normalizing a Token
>One token has the feature vector $\mathbf{h} = [1, -1, 3, 5]$, and its LayerNorm has $\gamma = \mathbf{1}$ and $\delta = \mathbf{0}$.
>
>>[!example]- Compute the output.
>>The mean is $m = 2$. The centered vector is $[-1, -3, 1, 3]$, so $s = \sqrt{(1 + 9 + 1 + 9)/4} = \sqrt{5} \approx 2.236$. The output is $[-0.447, -1.342, 0.447, 1.342]$. Any other token whose features are $a\mathbf{h} + b\mathbf{1}$ with $a > 0$ gives the same output.

>[!example] (Medium) LayerNorm Versus BatchNorm on the Same Batch
>A batch of two examples with three features each is stored as the rows of
>$$\mathbf{X} = \begin{bmatrix} 1 & 2 & 3 \\ 3 & 6 & 9 \end{bmatrix},$$
>so the second example is three times the first.
>
>>[!example]- Normalize the batch with LayerNorm and with BatchNorm, using $\gamma = 1$, $\delta = 0$ and negligible $\epsilon$. What does each one keep?
>>LayerNorm normalizes each row. The first row has mean $2$ and standard deviation $\sqrt{2/3} \approx 0.816$. The second has mean $6$ and standard deviation $\approx 2.449$. Both become $[-1.225, 0, 1.225]$. BatchNorm normalizes each column. Every column has the form $[a, 3a]$, with mean $2a$ and standard deviation $a$, so every column becomes $[-1, 1]$:
>>$$\text{LN}(\mathbf{X}) = \begin{bmatrix} -1.225 & 0 & 1.225 \\ -1.225 & 0 & 1.225 \end{bmatrix}, \qquad \text{BN}(\mathbf{X}) = \begin{bmatrix} -1 & -1 & -1 \\ 1 & 1 & 1 \end{bmatrix}.$$
>>LayerNorm keeps the pattern across features within each example and erases the fact that the second example is larger. BatchNorm keeps which example is larger for each feature and erases the pattern across features. The same batch carries different information after each layer.
