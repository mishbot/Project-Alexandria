>[!note] Self-Supervised Learning
>**Self-supervised learning** trains a network on unlabeled data by making the labels from the data itself. Each example $\mathbf x$ supplies both an input $\mathbf x_{\mathrm{in}}$ and a target $\mathbf x_{\mathrm{tgt}}$, and both are computed from $\mathbf x$. A network $f_\theta$ with parameters $\theta$ learns to predict the target from the input:
>$$\min_\theta \; \frac{1}{n}\sum_{i=1}^{n} \ell\big(f_\theta(\mathbf x_{i,\mathrm{in}}),\ \mathbf x_{i,\mathrm{tgt}}\big).$$
>Here $\ell$ is a loss suited to the data, such as squared error for real values or cross-entropy for words. This prediction problem is called a **pretext task**. It uses the same losses and [[2.3. Backpropagation|backpropagation]] as supervised learning. No person writes a label. Often the pretext task matters less than the representation the network builds to solve it. That representation later serves a **downstream task**, which may have few labels. The common pretext tasks differ in how they form the input and the target:
>
>- **Next-thing prediction**: in a causal sequence $\mathbf x_1, \dots, \mathbf x_T$, predict $\mathbf x_{t+1}$ from $\mathbf x_1, \dots, \mathbf x_t$. One sequence gives $T - 1$ training pairs. [[9.1. LLMs|Language models]] use this task with words as the elements.
>- **Masking**: hide random parts of the input, such as words, image patches or graph nodes, and predict them from the rest. Filling in a hidden image region is called **inpainting**.
>- **Reconstruction**: pass the whole input through a narrow code and reproduce it, as an [[6.2. Autoencoders|autoencoder]] does.
>- **Denoising**: corrupt the input with noise and predict the clean version.
>
>Two lessons from the learned Kalman filter apply to pretext tasks in general. A network can learn a **partial pattern**, such as a hidden state known only up to a change of basis. Such a pattern can still be useful. The pretext model may also need **scaffolding**, meaning extra parts or assumptions that exist only to make the task trainable.
>
>Classical **unsupervised learning** also uses no labels. Its two main problems are dimensionality reduction, such as [[7.1. Principal Component Analysis|PCA]], and clustering, such as [[6.1. K-Means|k-means]]. Self-supervised learning recasts such problems as prediction problems, so the tools of supervised deep learning apply. Methods that hide part of the data and predict it are called **generative** self-supervised learning. The other main family is **contrastive** self-supervised learning.

>[!warning] Not Taught in Lecture
>Contrastive self-supervised learning has not been covered yet. It compares pairs of examples that share something with unrelated pairs. A related pair might be two transformed versions of one image (Prince, *Understanding Deep Learning*, section 9.3.7). SimCLR (Chen et al., 2020) maps two versions of the same image to nearby representations. It pushes versions of different images apart.

# Intuition

Labeled data are expensive, since a person must write each label. Unlabeled data, such as text, images and sensor logs, are plentiful. Self-supervised learning uses the unlabeled data by hiding part of each example and asking the network to guess it. A good guess requires knowledge. To predict a hidden word, the network must track grammar and meaning. To fill in a dog's hidden ear, it must know what dogs look like. The network learns this knowledge while solving the pretext task, and a later task can reuse it.

The figure shows the two main ways to hold data back. Blue boxes are visible, and red boxes are the targets. Next-thing prediction hides the future and suits causal models, such as an [[5.3.1. RNNs|RNN]] that reads a sequence in order. Masking replaces random entries with a mask vector $\mathbf m$ and lets the network use context on both sides. The same idea works on graphs. A [[6.1.1. Message Passing|message-passing]] network replaces a hidden node's features with a learnable mask vector and predicts what was there.

The last animation computes the contrastive loss for a batch of three images. We divide each row of cosines by a temperature $\tau$, exponentiate it, and normalize it into probabilities. # Properties

#### *(Partial Patterns Are Still Useful)* A pretext task can fix a model's predictions without fixing its internal coordinates.

Consider a linear system with hidden state $\mathbf x_t \in \mathbb R^{d_x}$, controls $\mathbf u_t$ and observations $\mathbf y_t$:
$$\mathbf x_{t+1} = \mathbf A\mathbf x_t + \mathbf B\mathbf u_{t+1} + \mathbf w_{t+1}, \qquad \mathbf y_{t+1} = \mathbf C\mathbf x_{t+1} + \mathbf D\mathbf u_{t+1} + \mathbf v_{t+1}.$$
The noises are $\mathbf w_t \sim \mathcal N(\mathbf 0, \mathbf K_w)$ and $\mathbf v_t \sim \mathcal N(\mathbf 0, \mathbf K_v)$. Suppose only $\mathbf u_t$ and $\mathbf y_t$ are recorded, and a learned [[3.12.1 Kalman Filter|Kalman filter]] is trained to predict $\mathbf y_{t+1}$. For any invertible $\mathbf M \in \mathbb R^{d_x \times d_x}$, the state $\tilde{\mathbf x}_t = \mathbf M\mathbf x_t$ follows a system with matrices $\mathbf M\mathbf A\mathbf M^{-1}$, $\mathbf M\mathbf B$, $\mathbf C\mathbf M^{-1}$ and $\mathbf D$. Its state noise has covariance $\mathbf M\mathbf K_w\mathbf M^T$. Both systems produce the same observations, so no amount of $(\mathbf u, \mathbf y)$ data can tell them apart. The learned state is the true state in an unknown basis. It still holds all the information in the true state. A linear head trained on a small labeled set could learn $\mathbf M^{-1}$ and convert it. Assuming a diagonal $\mathbf A$ narrows the ambiguity. With distinct diagonal entries, only permutations and rescalings of the state coordinates remain. A linear [[6.2. Autoencoders|autoencoder]] shows the same pattern, since it learns the principal subspace in an unknown basis.

#### *(Scaffolding)* The pretext model often needs parts that exist only to create a training signal.

In the learned Kalman filter without state data, nothing gives a target for the state estimate $\hat{\mathbf x}_{t+1}$. A linear head is therefore added. It maps $\hat{\mathbf x}_{t+1}$ and the control $\mathbf u_{t+1}$ to a predicted observation. The loss compares that prediction with the recorded $\mathbf y_{t+1}$. The head copies the form $\mathbf C\mathbf x + \mathbf D\mathbf u$ of the true observation equation. An autoencoder's decoder plays the same role, since it is usually discarded after training. We judge a scaffold by how useful the remaining network is after training. The scaffold itself can look unrelated to the downstream task.

#### *(Pretraining Then Fine-Tuning)* After the pretext task, the network is reused for the downstream task by replacing its output layer.

>[!warning] Not Taught in Lecture
>This reuse step is transfer learning, described in Prince, *Understanding Deep Learning*, sections 9.3.6 and 9.3.7.

The last layer, which produced the pretext prediction, is removed. A new head suited to the downstream task takes its place, such as a classifier over a few classes. The pretrained layers can stay fixed while only the new head trains. Alternatively, the whole network is fine-tuned on the labeled data. Prince describes the pretrained weights as a starting point in a good region of parameter space. The downstream task then often needs fewer labels than training from scratch would.

#### *(No Access to the Target)* A pretext model must never see the value it is asked to predict.

If the input of a next-thing predictor includes $\mathbf x_{t+1}$, the network can copy it. The loss then falls to zero, and the network learns nothing. Causal models prevent this by construction. An RNN's state $\mathbf h_t$ depends only on $\mathbf x_1, \dots, \mathbf x_t$, and a [[7.2. Transformer Architecture|transformer]] decoder blocks attention to later positions. A causal model also produces all $T - 1$ predictions in one pass. Every position therefore adds a loss term. The same rule applies to normalization. Statistics computed over a whole sequence would make earlier positions depend on future values. Masked prediction has the same requirement. Each hidden entry is replaced by the mask vector before the network sees the input.

#### *(Language Models)* Next-word prediction on text is the pretext task behind language models.

>[!warning] Not Taught in Lecture
>Language models have not been covered yet. Prince's chapter 9 notes cite next-word prediction (Radford et al., 2019) and masked word prediction (Devlin et al., 2019).

A text of $T$ words gives $T - 1$ targets, each scored by cross-entropy over the vocabulary. Predicting the next word well requires grammar, facts and the meaning of the context. The targets come from the text itself, so the training set can grow with the available text. A causal model trained this way can also generate text. It samples a word, appends it to the input and predicts again. A masked word predictor sees context on both sides, which helps tasks that read a whole text. It is not built to generate text one word at a time.

#### *(Mask Vector Instead of Deletion)* A graph network hides a node by replacing its features, because deleting the node would change the graph.

Deleting a node also deletes its edges. This can disconnect the graph and change what the remaining nodes receive from their neighbors. A learnable mask vector $\mathbf m$ keeps every edge in place. All masked nodes share the same $\mathbf m$, so the network learns to treat it as "unknown". During training, random nodes with known values are masked, and the loss is computed on those nodes. At test time the nodes with missing values receive $\mathbf m$, and the network predicts them from their neighbors. Transformers trained by masked word prediction use a learned mask token in the same way.

#### *(The Task Must Be Hard Enough)* If a pretext task has a shortcut, the network learns the shortcut.

Masking a single pixel is a weak task, since the average of its neighbors already predicts it well. A network trained on it can score well by learning local smoothing and little about objects. Masking large regions removes the shortcut, since nearby pixels no longer reveal the answer. A plain autoencoder needs a bottleneck, noise or masking for the same reason. Without them the identity map solves the task.

>[!warning] Not Taught in Lecture
>The masking ratios come from the original papers. BERT (Devlin et al., 2019) masks $15\%$ of the words in a text. Masked autoencoders for images (He et al., 2022) mask $75\%$ of the image patches. They argue that images are far more redundant than text.

#### *(Clustering and PCA as Reconstruction)* The two classical unsupervised problems are reconstruction tasks with restricted codes.

PCA gives the best linear reconstruction through a $k$-dimensional code, by the Eckart-Young theorem. K-means minimizes $\sum_i \|\mathbf x_i - \boldsymbol\mu_{z_i}\|^2$, which is also a reconstruction loss. Its code is a single cluster index $z_i \in \{1, \dots, K\}$, and its decoder looks up the center $\boldsymbol\mu_{z_i}$. The hard choice of index has no useful gradient. K-means is therefore solved by alternating updates (Lloyd's algorithm) instead of gradient descent. Replacing the hard index with softmax weights makes the assignment differentiable. [[6.1.3. Graph Pooling|DiffPool]] uses this idea to cluster the nodes of a graph.

# Examples

>[!example] (Easy) Making Labels From Three Unlabeled Datasets
>A utility has five years of hourly electricity demand. An online shop has a million product photos without tags. A city has a road graph whose intersections record traffic counts.
>
>>[!example]- Design a pretext task for each dataset. What is the input, and what is the label?
>>
>>- **Demand**: use next-thing prediction. The input is the demand up to hour $t$, and the label is the demand at hour $t+1$. Five years hold about $5 \cdot 365 \cdot 24 = 43{,}800$ hours, so one series gives about $43{,}800$ training pairs.
>>- **Photos**: use masking. Hide large random patches of each photo, and use the hidden pixels as the label. Denoising also works, with the clean photo as the label.
>>- **Traffic**: use masking on nodes. Replace the counts at random intersections with a learnable mask vector. The label is the hidden count, predicted from the neighbors by message passing.
>>
>>No person wrote any of these labels. Each task also asks for knowledge that a later task needs. The demand model must learn daily and weekly cycles. The photo model must learn object shapes, and the traffic model must learn how traffic flows between intersections.

>[!example] (Medium) Two Systems With the Same Observations
>A scalar system starts at $h_0 = 0$ and follows $h_{t+1} = 0.5\,h_t + 2\,u_{t+1}$, with observation $y_t = 3\,h_t$. A learned model instead uses $h'_{t+1} = 0.5\,h'_t + 12\,u_{t+1}$ and $y_t = 0.5\,h'_t$, also from $h'_0 = 0$. The input is $u = (1, 0, 0)$.
>
>>[!example]- Compute both state sequences and both outputs. Could training on $(u, y)$ data tell the two apart?
>>The first system gives $h = (2, 1, 0.5)$ and $y = (6, 3, 1.5)$. The learned model gives $h' = (12, 6, 3)$ and $y = (6, 3, 1.5)$. The outputs agree. The learned model is the change of basis $M = 6$, since $0.5 = 6 \cdot 0.5 \cdot 6^{-1}$, $12 = 6 \cdot 2$ and $0.5 = 3/6$. For any input, $h'_t = 6\,h_t$, so the outputs always agree. Training on $(u, y)$ data cannot prefer one model over the other. The learned state is still useful, since it is the true state times $6$. One labeled value of the true state would fix the factor. In one dimension a diagonal $A$ is no restriction, so the rescaling ambiguity remains.

>[!example] (Hard) When Masking Is Too Easy
>A row of an image has brightness $x[t] = t^2$ for $t = 0, 1, \dots, 8$, so the row is $(0, 1, 4, 9, 16, 25, 36, 49, 64)$. A baseline predictor fills hidden pixels by linear interpolation between the nearest visible pixels on each side.
>
>>[!example]- Find the baseline's errors when $x[4]$ alone is hidden, and when $x[3]$, $x[4]$ and $x[5]$ are hidden together. What must a network learn to beat the baseline in each case?
>>With only $x[4]$ hidden, the baseline predicts $(x[3] + x[5])/2 = (9 + 25)/2 = 17$ against the true $16$. The error is $1$. The same holds at every interior position, since $\big((t-1)^2 + (t+1)^2\big)/2 = t^2 + 1$. With three pixels hidden, the baseline draws a line from $x[2] = 4$ to $x[6] = 36$. It predicts $12$, $20$ and $28$ against the true $9$, $16$ and $25$. The errors are $3$, $4$ and $3$. A network trained on single-pixel masks can come within $1$ by learning to average neighbors. To beat the baseline on the block, it must learn that the row curves upward. That is a property of the whole row. With larger masks, only a network that models the whole row can beat the baseline. A downstream task is more likely to need that knowledge.
