>[!note] Residual Networks
>A **residual connection**, or **skip connection**, adds the input of a block back to the block's output. The block then computes an additive change to its input instead of a new representation. A **residual block** with input $\mathbf{h}_{k-1}$ and processing function $\mathbf{f}_k$ outputs
>$$\mathbf{h}_k = \mathbf{h}_{k-1} + \mathbf{f}_k[\mathbf{h}_{k-1}, \boldsymbol{\phi}_k],$$
>where $\boldsymbol{\phi}_k$ are the block's weights and biases. The output of $\mathbf{f}_k$ must have the shape of its input. A **residual network** chains such blocks. Substituting each block into the next shows that the output is the input plus several smaller networks, for example $\mathbf{y} = \mathbf{x} + \mathbf{f}_1[\mathbf{x}] + \mathbf{f}_2[\mathbf{x} + \mathbf{f}_1[\mathbf{x}]]$ for two blocks. A network of $K$ blocks contains $2^K$ paths from input to output, because each block can be passed through or skipped.
>
>For a block with two weight layers and no biases, $\mathbf{X}_1 = \mathbf{W}_2\,\mathrm{ReLU}(\mathbf{W}_1 \mathbf{X}_0) + \mathbf{X}_0$, the Jacobian is
>$$\frac{\partial \mathbf{X}_1}{\partial \mathbf{X}_0} = \mathbf{W}_2 \mathbf{D} \mathbf{W}_1 + \mathbf{I},$$
>where $\mathbf{D}$ is diagonal with $D_{ii} = 1$ if $(\mathbf{W}_1\mathbf{X}_0)_i > 0$ and $0$ otherwise. The identity term gives every gradient a direct path backward. When the block changes the height, width or number of channels, the skip carries a learned projection instead, $\mathbf{X}_1 = \mathbf{W}_2\,\mathrm{ReLU}(\mathbf{W}_1\mathbf{X}_0) + \mathbf{P}\mathbf{X}_0$. In a CNN, $\mathbf{P}$ is a [[5.2.1c. 1x1 and Depthwise Convolution|$1 \times 1$ convolution]], with stride $2$ when the resolution halves.
>
>A block should end with a linear layer or convolution, not a ReLU. A block that ends with a ReLU can only add nonnegative values to its input. The usual order is therefore normalization, then ReLU, then convolution, repeated twice, and the network starts with a plain convolution before the first block. With [[4.1. Weight Initialization|He initialization]], each block keeps the variance of its input, so adding the input back doubles the variance at every block. After $K$ blocks the variance has grown by $2^K$. Two fixes exist:
>- **Rescaling**: multiplying the sum $\mathbf{h}_{k-1} + \mathbf{f}_k$ by $1/\sqrt{2}$ after each block keeps the variance constant.
>- **Normalization**: [[4.5.1. Batch Normalization|batch normalization]] at the start of each block makes the variance grow only linearly, from $1$ to $K + 1$. This is the usual fix.
>
>Residual connections alone roughly double the depth that can be trained. With batch normalization, ResNets of about $1000$ layers still train effectively.
>
>A **ResNet** is a CNN made of residual blocks. A **bottleneck block** uses three convolutions, each preceded by batch normalization and a ReLU:
>- A [[5.2.1c. 1x1 and Depthwise Convolution|$1 \times 1$ convolution]] reduces the channels.
>- A $3 \times 3$ convolution works on the reduced channels.
>- A $1 \times 1$ convolution restores the original channel count.
>
>**ResNet-200** starts with a $7 \times 7$ convolution of stride $2$ and a max pool. Bottleneck blocks follow, with periodic stride-2 downsampling and doubling of the channels. Global average pooling and a $1000$-way dense layer end the network. It reached $4.8\%$ top-5 and $20.1\%$ top-1 error on ImageNet, against a human top-5 error of $5.1\%$.

>[!warning] Two Conventions for the Block
>The original ResNet applied convolution, batch normalization and ReLU, then a second convolution and batch normalization, and applied the last ReLU after the addition. The order above, with normalization and ReLU first, is the later "pre-activation" block. Pre-norm, which places the normalization at the start of each block, is the convention in modern networks, including [[7.2. Transformer Architecture|transformers]].

# Intuition

Deep plain networks are hard to train even when their gradients have a sensible size. A 56-layer CNN trains to a worse error than a 20-layer one, on the training set as well as the test set. The extra layers could in principle copy their input and match the shallow network, but optimization does not find that solution. Each layer of a plain network must pass everything forward and must pass every gradient backward through all the layers after it. A small change to an early layer changes the input to every later layer. The gradient then changes unpredictably, a problem called **shattered gradients**.

A residual block changes the default. Doing nothing is easy, because the block only has to output zero. Each block learns a correction to the running representation, a "change in the function" rather than a replacement. The skip also gives each layer a short route to the output, so its gradient no longer depends only on a long product of Jacobians.

# Properties

#### *(Shattered Gradients)* In a deep plain network the gradient for an early layer changes almost randomly from one input to the next, and residual connections reduce this.

For a plain network $\mathbf{y} = \mathbf{f}_4[\mathbf{f}_3[\mathbf{f}_2[\mathbf{f}_1[\mathbf{x}]]]]$, the derivative with respect to the first layer's output is the product
$$\frac{\partial \mathbf{y}}{\partial \mathbf{f}_1} = \frac{\partial \mathbf{f}_2}{\partial \mathbf{f}_1}\frac{\partial \mathbf{f}_3}{\partial \mathbf{f}_2}\frac{\partial \mathbf{f}_4}{\partial \mathbf{f}_3}.$$
Changing $\mathbf{f}_1$ moves the point at which every later factor is evaluated, so after a finite update step the product can be completely different. Measured on a network with one input and one output, the gradient $\partial y/\partial x$ of a shallow network changes slowly with $x$. For $24$ layers it looks like noise, and its autocorrelation drops to zero almost immediately. Gradient descent assumes that the gradient after a step resembles the gradient before it, so this breaks training. The residual version of the same derivative is
$$\frac{\partial \mathbf{y}}{\partial \mathbf{f}_1} = \mathbf{I} + \frac{\partial \mathbf{f}_2}{\partial \mathbf{f}_1} + \Big(\frac{\partial \mathbf{f}_3}{\partial \mathbf{f}_1} + \frac{\partial \mathbf{f}_2}{\partial \mathbf{f}_1}\frac{\partial \mathbf{f}_3}{\partial \mathbf{f}_2}\Big) + \cdots,$$
with one term per path through the four blocks that contains $\mathbf{f}_1$. The identity and the short chains are well behaved and dominate the sum.

#### *(An Ensemble of Paths)* A residual network behaves like a sum of many shallower networks, and most of its gradient flows through the short ones.

Unraveling $K$ blocks gives $2^K$ paths, and block $\mathbf{f}_1$ lies on half of them. Path lengths follow a binomial distribution, so most paths are of medium length. Experiments on trained ResNets show that almost all of the gradient travels along short and medium paths. In a network of $54$ blocks, paths of $5$ to $17$ blocks carried nearly all of it, although they are only $0.45\%$ of all paths. Deleting one block from a trained ResNet barely changes its accuracy, while deleting one layer from a plain network such as VGG ruins it. Adding blocks therefore adds more parallel shallow paths. The network does not become much deeper in effect.

#### *(The Identity Is Not a Guarantee)* The skip keeps the block's Jacobian near the identity only when the residual branch is small.

The Jacobian $\mathbf{W}_2\mathbf{D}\mathbf{W}_1 + \mathbf{I}$ has singular values near $1$ when $\mathbf{W}_2\mathbf{D}\mathbf{W}_1$ is small in operator norm. Then the block passes gradients back with their size roughly unchanged. Nothing forces this. If $\mathbf{W}_2\mathbf{D}\mathbf{W}_1 = -\mathbf{I}$, the Jacobian is zero and no gradient passes at all. Small initial weights in the residual branch, or a learned scale on the branch initialized near zero, keep each block close to the identity at the start of training. Gradient clipping limits exploding gradients, but it does nothing for vanishing ones. The skip connection addresses the vanishing case.

#### *(Variance Doubles per Block)* Adding a block's output to its input adds their variances, so without normalization the activations grow exponentially with depth.

He initialization keeps the variance of a linear-plus-ReLU layer equal to the variance of its input. The residual branch and the skip are roughly uncorrelated at initialization, so their sum has twice the variance of the input. The figure shows the growth: $1, 2, 4, 8$ over three blocks, and $2^K$ after $K$. The values eventually exceed floating-point range in the forward pass, and the gradients explode in the backward pass. Batch normalization at the start of each block, with scale $\gamma = 1$ and offset $\delta = 0$, gives every branch input unit variance. Each block then adds exactly one unit of variance, so block $k$ outputs variance $k + 1$. A side effect is that late blocks change the representation little at initialization, so the network starts effectively shallow. Training can increase the scales $\gamma$ and so control its own effective depth.

#### *(Order of Operations)* Putting the ReLU at the end of a residual branch makes every block push its input upward.

A standard layer applies a linear map and then a ReLU, so its output is nonnegative. In a residual block that order means $\mathbf{h}_k = \mathbf{h}_{k-1} + (\text{something} \ge 0)$, and the representation can only grow. Reversing the order, ReLU first and linear map last, lets each block add positive and negative values. A network built this way must start with a plain linear layer or convolution. Otherwise a negative input would be clipped to zero by the first block's ReLU, and that block would contribute nothing. Most blocks contain two or three such layers, and all of them end with the linear step.

#### *(Changing Shape Across a Skip)* When a block halves the resolution or changes the channels, the skip must transform its input to the new shape.

A block that maps a $100 \times 100 \times 32$ input to a $50 \times 50 \times 64$ output cannot add the two directly. The common fix is a $1 \times 1$ convolution with $32 \cdot 64$ weights and stride $2$ on the skip path, the matrix $\mathbf{P}$ in the callout. An alternative with no parameters subsamples the input and appends zero channels. Either way the skip is no longer an exact identity at these few points, which is why ResNets change shape only a handful of times. A [[6.4. U-Net|U-Net]] uses a different kind of skip. It concatenates encoder maps with decoder maps across the whole network, and it does not replace the block-by-block residual connections inside each stage.

#### *(More Than Depth)* Residual connections smooth the loss surface, which helps even when the network is not very deep.

The early explanation for ResNets' success was depth. Two observations weaken it. Shallow and wide residual networks, for instance with $16$ layers and many channels, can beat much deeper and narrower ones with the same number of parameters. And the gradient flows mostly along short paths, so a very deep ResNet acts like a combination of shallower networks. The current view is that the skips change the loss surface itself. Consider the loss plotted around the minimum that SGD finds. For a 56-layer network with skips it is a smooth bowl. Without the skips, the same network has a chaotic surface with many sharp peaks. A smoother surface is easier to descend and makes the final weights more robust to small errors.

# Examples

>[!example] (Easy) Paths and Variance in Three Blocks
>A residual network has three blocks with He-initialized branches and unit-variance input.
>
>>[!example]- How many paths connect the input to the output, and what is the output variance at initialization without normalization, with a $1/\sqrt{2}$ rescaling after each block, and with batch normalization at the start of each block?
>>Each block can be passed through or skipped, so there are $2^3 = 8$ paths. Without normalization each block doubles the variance, giving $2^3 = 8$. Rescaling the sum by $1/\sqrt{2}$ divides the variance by $2$ after each doubling, so it stays at $1$. With batch normalization each branch adds one unit of variance, giving $1 + 3 = 4$. The rescaling keeps the forward pass stable but does not address shattered gradients. Batch normalization also smooths the loss surface and allows larger learning rates.

>[!example] (Medium) A Scalar Residual Block
>A block with scalar weights computes $x_1 = w_2\,\mathrm{ReLU}(w_1 x_0) + x_0$, with $w_1 = 0.5$ and $w_2 = -0.4$. A plain block computes $x_1 = w_2\,\mathrm{ReLU}(w_1 x_0)$ with the same weights.
>
>>[!example]- Find $dx_1/dx_0$ for both blocks at $x_0 = 2$ and at $x_0 = -2$. What happens to the gradient after ten identical blocks?
>>At $x_0 = 2$ the pre-activation is $w_1 x_0 = 1 > 0$, so the ReLU passes its input and $D = 1$. The plain block has derivative $w_2 w_1 = -0.2$ and the residual block has $-0.2 + 1 = 0.8$. At $x_0 = -2$ the pre-activation is $-1$, so $D = 0$. The plain block has derivative $0$, a dead unit, and the residual block has derivative $1$. Now chain ten identical blocks starting from $x_0 = 2$. The first plain block outputs $-0.4$, so the second has pre-activation $-0.2$, its ReLU is off, and the gradient through the chain is exactly $0$. Each residual block maps a positive $x$ to $0.8x$, so every value stays positive and every block has derivative $0.8$. The gradient through ten residual blocks is $0.8^{10} \approx 0.11$. A block with $w_2 w_1 = -1$ would have derivative $0$ even with the skip, which shows that the identity term does not guarantee gradient flow.

>[!example] (Medium) A Projection Shortcut
>A block takes a $64 \times 56 \times 56$ map (channels, height, width) and outputs $128 \times 28 \times 28$.
>
>>[!example]- Design the skip path and count its parameters.
>>A $1 \times 1$ convolution with $128$ filters, stride $2$ and no padding maps the height to $\lfloor (56 - 1)/2 \rfloor + 1 = 28$, and likewise the width. It changes the channels from $64$ to $128$. It has $64 \cdot 128 = 8192$ weights and $128$ biases, $8320$ parameters. A $3 \times 3$ convolution of the same shape in the residual branch has $9 \cdot 64 \cdot 128 = 73{,}728$ weights, so the projection is cheap.

>[!example] (Hard) Why Bottlenecks
>A deep ResNet stage has $256$ channels. One design uses two $3 \times 3$ convolutions with $256$ channels in each block. The bottleneck design uses a $1 \times 1$ convolution from $256$ to $64$ channels, a $3 \times 3$ convolution with $64$ channels, and a $1 \times 1$ convolution back to $256$.
>
>>[!example]- Compare the weights per block, ignoring biases and normalization, and the receptive field each block adds.
>>The standard block has $2 \cdot 9 \cdot 256^2 = 1{,}179{,}648$ weights. The bottleneck block has $256 \cdot 64 + 9 \cdot 64^2 + 64 \cdot 256 = 16{,}384 + 36{,}864 + 16{,}384 = 69{,}632$, about $17$ times fewer. The standard block grows the receptive field by $4$ pixels at stride $1$, while the bottleneck grows it by $2$, since only its middle layer looks at neighbors. For the same parameter budget, a network can hold about $17$ times as many bottleneck blocks, which is how ResNet-200 stays practical.
