>[!note] Upsampling
>**Upsampling** increases the height and width of a feature map, usually by a factor of $2$. It acts on each channel separately unless it is a learned convolution. Networks that output an image, such as segmentation and denoising networks, use it to undo the downsampling of their first half. There are four common methods:
>- **Duplication** (nearest-neighbor upsampling) copies each value into a $2 \times 2$ block.
>- **Max unpooling** puts each value back at the position that won the matching [[5.2.2. Pooling|max pool]] and fills the rest of the block with zeros.
>- **Bilinear interpolation** fills the new positions with weighted averages of their nearest neighbors.
>- **Transposed convolution** learns its upsampling weights.
>
>In a transposed convolution, each input value multiplies a full copy of the kernel, and the copies are placed $s$ positions apart. Where copies overlap, their contributions add. Take 1D with stride $s$ and no padding, and index the input and kernel from $0$. Input $x[i]$ adds $x[i] \cdot \omega[k]$ to output position $t = si + k$:
>$$y[t] = \sum_{i} x[i] \cdot \omega[t - s\,i].$$
>With $s = 1$ this is the full convolution $\boldsymbol{\omega} * \mathbf{x}$.
>Padding $p$ then removes $p$ positions from each end. An input of length $n$ gives an output of length
>$$n' = s(n-1) + K - 2p,$$
>which inverts the size rule $\lfloor (n' + 2p - K)/s \rfloor + 1 = n$ of an ordinary convolution. The input and output sizes swap places relative to a strided convolution with the same $K$, $s$ and $p$. Its weight matrix is the transpose of that convolution's weight matrix, which gives the method its name. With channels it has $C_{\text{in}} C_{\text{out}} K^2$ weights, like an ordinary convolution.
>
>An equivalent recipe has three steps:
>1. Insert $s - 1$ zeros between neighboring inputs.
>2. Pad with $K - 1 - p$ zeros on each side.
>3. Cross-correlate with the reversed kernel at stride $1$, which is the same as convolving with $\boldsymbol{\omega}$.
>
>Duplication, max unpooling and interpolation have no parameters. A transposed convolution is the only one that learns. None of them can recover detail that downsampling destroyed, which is why encoder-decoder networks add skip connections such as those of the [[6.4. U-Net|U-Net]].

>[!warning] Deconvolution Is Not an Inverse
>Some papers call transposed convolutions "deconvolutions". A transposed convolution is not the inverse of a convolution. It has the transposed shape and connectivity, not the inverse effect, and applying a convolution and then its transpose does not return the input.

>[!warning] Not Taught in Lecture
>Lecture did not cover bilinear interpolation as an upsampling layer. The textbook treats it in section 10.4.2.

# Intuition

A classifier can end with a single vector, but a segmentation network must label every pixel. It still needs the wide context that only a downsampled representation provides. A patch of shirt is easier to label when the network can see the whole person, so it shrinks the image and then grows it back. Growing a map is the mirror image of shrinking it. A stride-2 convolution collects three neighboring inputs into each output. A stride-2 transposed convolution sends each input out to three neighboring outputs, as the figure shows. The outputs at positions $3$ and $5$ receive two contributions each and add them.

The fixed methods make simpler guesses. Duplication assumes the map is constant inside each block. Max unpooling assumes the feature sits exactly where the encoder last saw it. Interpolation assumes the map changes smoothly. A transposed convolution lets the network choose its own rule. All four face the same limit. Every halving of the resolution throws away the finest detail, and no upsampler can invent it again. The decoder can be sharp only if the encoder's high-resolution maps are copied across to it.

# Properties

#### *(Transpose of the Downsampling Matrix)* A transposed convolution multiplies by the transpose of the matrix that the matching strided convolution uses.

Consider a stride-2 convolution with $K = 3$ and zero padding $1$ that maps $8$ inputs to $4$ outputs. It is a $4 \times 8$ matrix $\boldsymbol{\Omega}$ in which each row holds the kernel. Each row starts two columns to the right of the row above, and the padding cuts the first row to $[\omega_2, \omega_3, 0, \dots, 0]$. Its transpose $\boldsymbol{\Omega}^T$ is $8 \times 4$, and each column holds the kernel. Multiplying a length-$4$ vector by $\boldsymbol{\Omega}^T$ places a scaled copy of the kernel for each input, two rows apart, which is the scatter-and-add rule. The same fact explains backpropagation. The gradient of a convolution with respect to its input is $\boldsymbol{\Omega}^T$ times the upstream gradient, so the backward pass of every [[5.2.1. Convolutional Layer|convolutional layer]] is a transposed convolution. Frameworks implement both with the same routine.

#### *(Zero-Insertion View)* A transposed convolution equals zero insertion followed by a cross-correlation with the reversed kernel.

Insert $s - 1$ zeros between consecutive inputs, which gives a sequence of length $s(n-1)+1$. Pad it with $K - 1 - p$ zeros on each side and cross-correlate it with the reversed kernel $[\omega_K, \dots, \omega_1]$ at stride $1$. The output length is $s(n-1) + 1 + 2(K-1-p) - K + 1 = s(n-1) + K - 2p$, which matches the rule in the callout. Each output entry collects the same products $x_i\,\omega_k$ as the scatter rule. For a symmetric kernel the reversal makes no difference. This view explains the old name "fractionally strided convolution": the kernel moves $1/s$ of an input position per output.

#### *(Fixed Upsamplers Are Special Cases)* Duplication and linear interpolation are transposed convolutions with fixed kernels.

In 1D with $s = 2$, the kernel $[1, 1]$ with $p = 0$ copies each input into two outputs, which is duplication. The kernel $[\tfrac{1}{2}, 1, \tfrac{1}{2}]$ with $p = 1$ places each input at an odd position and half of it at each neighbor. The result is $[x_1, \tfrac{x_1 + x_2}{2}, x_2, \tfrac{x_2 + x_3}{2}, \dots, x_n]$, which is linear interpolation. In 2D, bilinear interpolation uses the outer product of $[\tfrac{1}{2}, 1, \tfrac{1}{2}]$ with itself, applied to each channel separately. A learned transposed convolution can therefore match any of these and improve on them when the data reward it. Max unpooling is not of this form, because the positions it writes to depend on the input.

#### *(Checkerboard Artifacts)* When the kernel size is not a multiple of the stride, some outputs receive more contributions than others.

>[!warning] Not Taught in Lecture
>Lecture did not discuss checkerboard artifacts. The textbook's chapter notes mention them.

With $K = 3$ and $s = 2$, odd interior positions receive two contributions and even positions receive one. A constant input then produces an alternating output, and in 2D the pattern looks like a checkerboard. Training can learn to compensate, but the artifacts often survive in generated images. Choosing $K$ divisible by $s$, such as $K = 4$ with $s = 2$, gives every interior output the same number of contributions. Another fix replaces the transposed convolution by duplication or bilinear upsampling followed by an ordinary convolution.

#### *(Max Unpooling Needs the Indices)* Max unpooling reuses the positions recorded by an earlier max pool, so it only works in a network that pooled first.

During the forward pass, each $2 \times 2$ max pool records which of its four inputs won. A max-unpooling layer at the matching resolution in the decoder writes each value back to that recorded position and fills the other three with zeros. The result is sparse, and convolutions after it fill in the gaps. Early segmentation networks paired every max pool in the encoder with a max unpool in the decoder for this reason. The recorded positions carry a little spatial detail from the encoder to the decoder, a weaker version of a skip connection.

# Examples

>[!example] (Easy) Duplication and Max Unpooling
>A decoder receives the $2 \times 2$ map $\begin{bmatrix} 3 & 1 \\ 5 & 2 \end{bmatrix}$. The matching max pool in the encoder recorded its winners at positions $(2, 2)$, $(1, 4)$, $(3, 1)$ and $(4, 3)$ of the $4 \times 4$ map.
>
>>[!example]- Upsample the map by duplication and by max unpooling.
>>Duplication copies each value into its $2 \times 2$ block. Max unpooling writes each value at its recorded position and zeros elsewhere:
>>$$\begin{bmatrix} 3 & 3 & 1 & 1 \\ 3 & 3 & 1 & 1 \\ 5 & 5 & 2 & 2 \\ 5 & 5 & 2 & 2 \end{bmatrix}, \qquad \begin{bmatrix} 0 & 0 & 0 & 1 \\ 0 & 3 & 0 & 0 \\ 5 & 0 & 0 & 0 \\ 0 & 0 & 2 & 0 \end{bmatrix}.$$
>>Both keep the same four values. Duplication spreads them evenly, and max unpooling puts them back where the encoder found them.

>[!example] (Medium) A 1D Transposed Convolution Two Ways
>The input $\mathbf{x} = [1, 2, -1]^T$ passes through a transposed convolution with kernel $\boldsymbol{\omega} = [1, -1, 2]^T$ and stride $2$.
>
>>[!example]- Compute the output with $p = 0$ by scattering, check it by zero insertion, and give the output for $p = 1$.
>>Each input places a scaled kernel two positions after the previous one: $1 \cdot [1, -1, 2]$ at positions $1$ to $3$, $2 \cdot [1, -1, 2]$ at positions $3$ to $5$, and $-1 \cdot [1, -1, 2]$ at positions $5$ to $7$. Adding the overlaps at positions $3$ and $5$ gives
>>$$\mathbf{y} = [1,\; -1,\; 2 + 2,\; -2,\; 4 - 1,\; 1,\; -2] = [1, -1, 4, -2, 3, 1, -2],$$
>>with length $2(3-1) + 3 = 7$. For the check, insert one zero between inputs to get $[1, 0, 2, 0, -1]$, pad with $K - 1 - p = 2$ zeros on each side, and cross-correlate with the reversed kernel $[2, -1, 1]$. The first window $[0, 0, 1]$ gives $1$, the third window $[1, 0, 2]$ gives $2 + 0 + 2 = 4$, and the remaining windows reproduce $\mathbf{y}$. With $p = 1$ one position is removed from each end, giving $[-1, 4, -2, 3, 1]$ of length $2 \cdot 2 + 3 - 2 = 5$.

>[!example] (Medium) A 2D Transposed Convolution
>The input $\begin{bmatrix} 1 & -2 \\ 0 & 3 \end{bmatrix}$ passes through a transposed convolution with kernel $\begin{bmatrix} 2 & 1 \\ -1 & 0 \end{bmatrix}$, stride $1$ and no padding.
>
>>[!example]- Compute the $3 \times 3$ output.
>>Each input entry scales a copy of the kernel placed with its top-left corner at that entry's position. The entry $0$ contributes nothing, and the other three give
>>$$1\begin{bmatrix} 2 & 1 & 0 \\ -1 & 0 & 0 \\ 0 & 0 & 0 \end{bmatrix} - 2\begin{bmatrix} 0 & 2 & 1 \\ 0 & -1 & 0 \\ 0 & 0 & 0 \end{bmatrix} + 3\begin{bmatrix} 0 & 0 & 0 \\ 0 & 2 & 1 \\ 0 & -1 & 0 \end{bmatrix} = \begin{bmatrix} 2 & -3 & -2 \\ -1 & 8 & 3 \\ 0 & -3 & 0 \end{bmatrix}.$$
>>The output size is $1 \cdot (2 - 1) + 2 = 3$ in each direction. An ordinary $2 \times 2$ convolution without padding would map a $3 \times 3$ input back to $2 \times 2$, which confirms that the sizes have swapped.

>[!example] (Hard) Spotting Uneven Overlap
>Two decoders upsample the constant input $\mathbf{x} = [1, 1, 1, 1]^T$ with stride $2$ and no padding. One uses the kernel $[1, 1, 1]$ and the other uses $[1, 1, 1, 1]$.
>
>>[!example]- Compute both outputs and explain which kernel shape avoids artifacts. Then give a kernel of size $3$ that turns stride-2 upsampling into linear interpolation.
>>With $K = 3$ the copies cover positions $1$ to $3$, $3$ to $5$, $5$ to $7$ and $7$ to $9$, so the output is $[1, 1, 2, 1, 2, 1, 2, 1, 1]$. A constant input produces an alternating pattern, because odd interior positions get two contributions and even positions get one. With $K = 4$ the copies cover $1$ to $4$, $3$ to $6$, $5$ to $8$ and $7$ to $10$, so the output is $[1, 1, 2, 2, 2, 2, 2, 2, 1, 1]$. Every interior position gets exactly two contributions, because $4$ is a multiple of the stride. The kernel $[\tfrac{1}{2}, 1, \tfrac{1}{2}]$ with $p = 1$ turns $[x_1, x_2, x_3, x_4]$ into $[x_1, \tfrac{x_1+x_2}{2}, x_2, \tfrac{x_2+x_3}{2}, x_3, \tfrac{x_3+x_4}{2}, x_4]$. Its halved outer taps give the shared positions the same total weight as the others, so a constant input stays constant.
