>[!note] Normalization Layers
>A **normalization layer** rescales activations so that a chosen group of them has mean zero and standard deviation one, then applies a learned scale and offset. It stabilizes and speeds up training, and it does not reduce the capacity of the network. All variants take a tensor of shape $N \times C \times H \times W$ (batch, channels, height, width) and return one of the same shape. Each picks a set $S$ of entries, computes their mean and standard deviation,
>$$m = \frac{1}{|S|}\sum_{i \in S} h_i, \qquad s = \sqrt{\frac{1}{|S|}\sum_{i \in S} (h_i - m)^2},$$
>standardizes them, and rescales them with a learned scale $\gamma$ and offset $\delta$ for each channel:
>$$h_i \leftarrow \gamma\,\frac{h_i - m}{s + \epsilon} + \delta.$$
>Here $\epsilon > 0$ is a small constant that prevents division by zero. Every variant has $2C$ learned parameters per layer. The variants differ only in the set $S$:
>- [[4.5.1. Batch Normalization|Batch normalization]] uses one channel across the whole batch and all positions.
>- [[4.5.2. Layer Normalization|Layer normalization]] uses one example across all channels and positions.
>- [[4.5.3. Group Normalization|Group normalization]] uses one example and one group of channels.
>- **Instance normalization** uses one example and one channel, the extreme case of group normalization.
>- **Ghost batch normalization** is batch normalization computed on part of the batch.
>
>The decision rule is as follows:
>- **Batch normalization** is the default in CNNs trained with batches of moderate or large size.
>- **Layer normalization** fits when batch statistics are unreliable or unavailable: in RNNs, transformers and graph networks, with very small batches, or when the batch is split across machines.
>- **Group normalization** fits vision models that must train with only a few images per batch.
>- **Instance normalization** fits when the contrast of each channel within each image should be removed, as in style transfer.

# Intuition

A deep network passes its activations through many layers. Without control, their scale can grow or shrink at every layer, and the right learning rate for one layer is wrong for the next. Normalization resets each group of activations to a standard scale and lets the network learn, through $\gamma$ and $\delta$, which scale it wants. The variants answer one question differently: standardized relative to what? Batch normalization compares each example with the others in the batch, channel by channel. Layer and group normalization compare activations within one example.

This choice is the tension of the family. Batch statistics average over many values, so they are stable, and their randomness from batch to batch acts as a regularizer. They also tie each example's output to the rest of its batch, which complicates small batches, sequences and test time. Statistics computed within one example avoid all of that. They give up the regularizing noise, and they erase whatever information was carried by the overall level of the pooled activations. | [[4.5.3. Group Normalization\|Group norm]] | one example, one group of channels | no | yes | no | vision with few images per batch |

# When to Use Which

Start with batch normalization in a convolutional network. It allows higher learning rates, and its batch noise adds regularization for free. Switch to layer normalization when the batch is a poor sample of the data or is not available. Sequence models are the main case, since their statistics would have to be stored per time step and a test sequence may be longer than any training sequence. A stacked [[5.3.1. RNNs|RNN]] normalizes each hidden state over its own entries, so no statistic uses a future time step. Graph networks are another case. Graphs in a batch have different numbers of nodes and no shared positions. The batch therefore has no common block to average over. A [[6.1.1. Message Passing|GNN]] uses layer normalization over one graph or normalizes each node's vector across its channels. Very small batches and training split across machines are the remaining cases. Switch to group normalization in vision models whose batches are too small for batch normalization, such as detection and segmentation models with large images. Use instance normalization when each image's own contrast is a nuisance, as in style transfer. Ghost batch normalization is a tuning option inside batch normalization, used to restore regularizing noise when batches are very large.

# Examples

>[!example] (Easy) Counting Statistics
>A convolutional layer produces activations of shape $32 \times 64 \times 16 \times 16$ (batch, channels, height, width).
>
>>[!example]- How many means does each variant compute, how many values enter each mean, and how many learned parameters does each layer have? Use $8$ groups for group normalization.
>>Batch normalization computes $64$ means, one per channel, each over $32 \cdot 16 \cdot 16 = 8192$ values. Layer normalization computes $32$ means, one per example, each over $64 \cdot 256 = 16{,}384$ values. Group normalization with $8$ groups of $8$ channels computes $32 \cdot 8 = 256$ means, each over $8 \cdot 256 = 2048$ values. Instance normalization computes $32 \cdot 64 = 2048$ means, each over $256$ values. Every variant has the same $2 \cdot 64 = 128$ learned parameters, one scale and one offset per channel. With a batch of $2$ instead of $32$, each batch-normalization mean would rest on only $512$ values, while the other variants would be unaffected.
