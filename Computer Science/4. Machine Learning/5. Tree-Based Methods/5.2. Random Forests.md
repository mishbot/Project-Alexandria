>[!note] Random Forests
>A **random forest** (Breiman, 2001) averages many deep decision trees. Each tree grows on a bootstrap sample and sees a random subset of features at every split. The method extends **bagging**, short for bootstrap aggregating (Breiman, 1996). Bagging draws $B$ [[1.5.1 Classical Bootstrap|bootstrap]] samples of size $n$ with replacement from the $n$ training points. It grows one unpruned tree $\hat f^{*b}$ on each sample $b$ and combines them:
>$$\hat f_{\text{bag}}(\mathbf{x}) = \frac{1}{B}\sum_{b=1}^{B} \hat f^{*b}(\mathbf{x}).$$
>For regression the forest outputs this average. For classification it takes a majority vote of the trees, or it averages their class proportions and picks the largest.
>
>A random forest adds one rule. At each split, the tree may choose only among $m$ features drawn at random from the $d$ features. Setting $m = d$ recovers bagging. ESL (ch. 15) gives these defaults:
>
>- **Classification**: $m = \lfloor\sqrt{d}\rfloor$, with trees grown until each leaf holds one point.
>- **Regression**: $m = \lfloor d/3 \rfloor$, with a minimum leaf size of five.
>
>Suppose each tree's prediction at $\mathbf{x}$ has variance $\sigma^2$ and any two trees have correlation $\rho$. The average of $B$ trees then has variance
>$$\mathrm{Var}\big(\hat f_{\text{bag}}(\mathbf{x})\big) = \rho\sigma^2 + \frac{1 - \rho}{B}\sigma^2.$$
>More trees shrink only the second term, so the variance falls to $\rho\sigma^2$ as $B \to \infty$. Feature subsampling lowers $\rho$ and with it this floor.
>
>Each bootstrap sample misses a given training point with probability
>$$\left(1 - \frac{1}{n}\right)^n \approx e^{-1} \approx 0.368.$$
>The **out-of-bag (OOB) error** predicts each training point with only the trees that did not see it. It then averages the losses over all points. The forest gets this estimate of the test error without a separate validation set. A random forest is the standard strong baseline on tabular data, because it needs little tuning. [[5.3. Gradient Boosted Trees]] usually beat it after tuning, and a single [[5.1. Decision Trees|decision tree]] is easier to read.

# Intuition

One deep tree fits its training sample closely, so it changes a lot when the sample changes. A forest averages many such trees. The average is more stable than any one tree. In the same way, the mean of many noisy measurements varies less than one measurement. The average cancels only the part of the errors that differs between trees. Trees grown on bootstrap samples of the same data are similar. They are most similar when one feature is much stronger than the rest. Every tree then splits on that feature first, and the trees become near copies of each other. A random forest hides most features from each split. Different trees then take different paths, their errors become less correlated, and the average becomes more stable. The name refers to this collection of trees, each made different by random draws of rows and features.

# Properties

#### *(More Trees Never Overfit)* Adding trees changes only the $(1 - \rho)\sigma^2/B$ term, so the test error falls toward a limit and does not rise again.

The limit as $B \to \infty$ is the expected prediction over all bootstrap samples and feature draws. A finite forest is a Monte Carlo estimate of that limit, and more trees make the estimate more precise. The number of trees is therefore not a tuning parameter in the usual sense. Practitioners add trees until the OOB error curve flattens, often at a few hundred. The limit itself can still overfit noisy data, because it averages fully grown trees. Segal (2004) found small gains from limiting tree depth. ESL (ch. 15) reports that full-depth trees seldom cost much and save one tuning parameter.

Each bootstrap tree draws a different blocky boundary. The forest takes a vote, and its test error falls and levels off as $B$ grows.

#### *(Bias Equals One Tree's)* The trees are identically distributed, so the forest has the same bias as one of its trees.

Every tree comes from the same random procedure, so each has the same expected prediction $\mathbb{E}[\hat f^{*b}(\mathbf{x})]$. The average of $B$ trees has that expectation too. A forest therefore improves on one tree only through lower variance in the [[2.3.1. Bias-Variance Decomposition|bias-variance decomposition]]. Forests use deep, unpruned trees for this reason, since those have low bias and high variance. A forest of stumps would keep the high bias of a stump. Feature subsampling makes each tree slightly more biased, since a split cannot always use the best feature. A small $m$ lowers the test error when the variance it removes exceeds the squared bias it adds.

#### *(Why Feature Subsampling Helps)* When one feature dominates, bagged trees all split on it first, and subsampling hides it from most splits.

Suppose one of $d = 9$ features predicts house prices far better than the rest. With bagging, nearly every tree uses it at the root. The trees then share their top structure, and $\rho$ stays high. With $m = 3$, the strong feature is missing from the candidates at a given split with probability $1 - 3/9 = 2/3$. About two thirds of the trees therefore start from a different feature. Subsampling can also hurt. Suppose only $2$ of $100$ features matter and $m = 10$. A split then misses both with probability $0.81$, and most splits use noise features (ESL 15.3.4).

#### *(OOB Error Is Nearly Free)* The OOB estimate needs no refitting, and it is reliable only when the rows are independent.

The OOB estimate behaves like leave-one-out [[2.3.2. Cross-Validation|cross-validation]], and no model is refit. Each OOB prediction averages only about $0.37B$ trees, so it is noisier than the full forest's prediction. The OOB error therefore slightly overstates the full forest's test error. The estimate also assumes independent rows. If one patient contributes many rows, a tree almost surely trains on some of them. The patient's other rows are out of bag for that tree but not new to it. The OOB error is then too optimistic, and validation must split by patient, as in [[2.3. Generalization]].

#### *(Feature Importance)* Impurity importance favors features with many possible split points, and permutation importance avoids that bias.

Impurity importance, also called mean decrease in impurity, sums the impurity decreases from all splits on feature $j$. It then averages this sum over the trees. A continuous feature, or a categorical one with many levels, offers many thresholds. One of them often fits noise, so even a useless customer ID can score high (Strobl et al., 2007). Permutation importance shuffles feature $j$ in the OOB data and records the rise in OOB error. A useless feature then scores near zero. Both measures share credit between correlated features. Two near copies of a strong feature can each look much weaker than the feature alone.

# Derivation

Let $Z_b = \hat f^{*b}(\mathbf{x})$ be the prediction of tree $b$ at a fixed point. Over the random training sample and the random draws, each $Z_b$ has variance $\sigma^2$, and each pair has covariance $\rho\sigma^2$. The variance of the average expands into $B$ variance terms and $B(B-1)$ covariance terms:
$$\mathrm{Var}\Big(\frac{1}{B}\sum_{b=1}^{B} Z_b\Big) = \frac{1}{B^2}\Big(B\sigma^2 + B(B-1)\rho\sigma^2\Big) = \rho\sigma^2 + \frac{1-\rho}{B}\sigma^2.$$
With $\rho = 0$ this is the familiar $\sigma^2/B$ for independent draws. With $\rho = 1$ every tree is identical, and averaging changes nothing. Trees grown on the same data have $\rho > 0$, because any two bootstrap samples share many points.

# Examples

>[!example] (Easy) Variance of a Forest
>A forest predicts house prices in units of $10{,}000$ dollars. At a given house, each tree's prediction has variance $\sigma^2 = 1$. Any two trees have correlation $\rho = 0.3$.
>
>>[!example]- What is the variance of the forest's prediction with $B = 100$ trees, with $B = 10$, and in the limit?
>>With $B = 100$, the variance is $0.3 \cdot 1 + 0.7 \cdot 1/100 = 0.3 + 0.007 = 0.307$. With $B = 10$, it is $0.3 + 0.07 = 0.37$. As $B \to \infty$, it falls to $\rho\sigma^2 = 0.3$. Going from $10$ to $100$ trees removes $90\%$ of the gap to the limit. No number of trees gets below $0.3$, so further gains require a lower $\rho$.

>[!example] (Medium) Out-of-Bag Coverage
>A bank trains a forest on $n = 1000$ loan applications.
>
>>[!example]- For one application, how often does a tree leave it out? How many OOB trees does it get with $B = 300$ and with $B = 5$?
>>A bootstrap sample misses the application with probability $(1 - 1/1000)^{1000} = 0.3677$, close to $e^{-1} = 0.3679$. Each sample therefore holds about $632$ distinct applications. With $B = 300$, the application is out of bag for about $300 \cdot 0.3677 = 110$ trees. The chance that all $300$ trees saw it is $0.6323^{300} \approx 10^{-60}$. With $B = 5$, it is out of bag for only $1.8$ trees on average. All five trees see it with probability $0.6323^5 = 0.101$, so about $10\%$ of the applications get no OOB prediction. A small forest gives a noisy and incomplete OOB estimate.

>[!example] (Hard) Bagging Versus a Random Forest
>A regression problem has $d = 9$ features and noise variance $0.5$. Bagged trees ($m = 9$) have squared bias $0.10$, variance $\sigma^2 = 1.0$ and correlation $\rho = 0.6$. Random-forest trees with $m = 3$ have squared bias $0.15$, variance $\sigma^2 = 1.2$ and $\rho = 0.2$.
>
>>[!example]- Compare the expected test MSE of one tree and of $200$ trees for each method. How many trees bring the forest's variance within $1\%$ of its limit?
>>The expected test MSE is noise plus squared bias plus variance, as in [[2.3.1. Bias-Variance Decomposition]]. One bagged tree has $0.5 + 0.10 + 1.0 = 1.6$. One random-forest tree has $0.5 + 0.15 + 1.2 = 1.85$, so it is worse alone. With $200$ trees, bagging has variance $0.6 + 0.4/200 = 0.602$ and MSE $1.202$. The forest has variance $0.24 + 0.96/200 = 0.2448$ and MSE $0.895$. Each forest tree is worse alone, yet the forest wins because its trees are less correlated. The forest's limit is $\rho\sigma^2 = 0.24$. The extra term $0.96/B$ falls to $0.0024$, which is $1\%$ of that limit, at $B = 400$.
