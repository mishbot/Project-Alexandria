>[!note] Transformer Architecture
>A **transformer** is a stack of identical **blocks**. Each block reads an $N \times D$ matrix $\mathbf X$, one row per token, and returns a matrix of the same shape. A block has two parts, and each part sits on a [[5.2.5. Residual Networks|residual connection]]:
>- **Multi-head attention** mixes information across tokens. It is the only part of the block in which a token can read other tokens.
>- **MLP**, or feedforward network, transforms each token on its own. Every token passes through the same two-layer network, usually with a hidden width of $4D$.
>
>Modern transformers normalize at the start of each part. This is the **pre-LN** layout:
>$$\mathbf X \leftarrow \mathbf X + \mathrm{MHA}\big(\mathrm{Norm}(\mathbf X)\big), \qquad \mathbf x_n \leftarrow \mathbf x_n + \mathrm{MLP}\big(\mathrm{Norm}(\mathbf x_n)\big) \ \text{ for each token } n.$$
>The original transformer of Vaswani et al. (2017) normalized after each addition instead. This **post-LN** layout computes $\mathbf X \leftarrow \mathrm{Norm}\big(\mathbf X + \mathrm{MHA}(\mathbf X)\big)$, and likewise for the MLP. $\mathrm{Norm}$ is [[4.5.2. Layer Normalization|LayerNorm]] or RMSNorm, applied to each token separately. The MLP is
>$$\mathrm{MLP}(\mathbf x) = \mathbf W_2^T\,\mathrm{ReLU}(\mathbf W_1^T\mathbf x + \mathbf b_1) + \mathbf b_2, \qquad \mathbf W_1 \in \mathbb R^{D \times 4D},\ \mathbf W_2 \in \mathbb R^{4D \times D}.$$
>
>The full model wraps the stack with an input layer and an output layer:
>- **Input**: an [[7.3. Token Embeddings|embedding layer]] turns each token into a vector. A [[7.4. Positional Encoding|positional encoding]] gives the model the order of the tokens.
>- **Output**: a linear layer maps each final vector to one score per vocabulary entry. A softmax turns the scores into probabilities for the next token.
>
>The model in "Attention Is All You Need" is an [[7.5. Encoder and Decoder Models|encoder-decoder]] with $N_\times = 6$ blocks on each side. A decoder block has three parts: causal self-attention, cross-attention that reads the encoder output, and the MLP. During training the decoder receives the target sequence shifted right by one place, starting with `<start>`. At inference it starts from `<start>` alone and generates one token at a time.

# Intuition

The Spring 2023 lecture 18 notes build the transformer from the [[5.3.3. Sequence-to-Sequence Models|RNN encoder-decoder]] in five steps:

1. Add cross-attention, so that each decoder step can look up the relevant part of the input.
2. Add causal self-attention to the decoder, so that it can look up its own earlier outputs.
3. Remove the RNN from the decoder. Attention already gives access to the input and to the outputs so far. The state has nothing left to carry.
4. Add self-attention to the encoder and remove its RNN too. At first this self-attention is causal, like the RNN it replaces.
5. Remove the causal mask from the encoder. The whole input is known in advance, so every input token may read every other one.

What remains are attention parts, MLPs, residual connections and normalization. Each token's vector flows up the stack along the residual path. Every part reads that vector, computes a change, and adds the change back. Attention moves information between tokens, and the MLP processes each token's information on its own.

The weights are shared across positions, as in an RNN and a CNN. Every token in one layer uses the same projections and the same MLP. Each layer has its own weights and fills its own attention table. Some models also share weights across layers.

# Properties

#### *(Why the MLP Is Needed)* Attention outputs weighted averages of value vectors, so the block needs a separate part with a stronger nonlinearity.

The value vectors are linear in the input, and the attention weights are positive and sum to $1$. The softmax is a nonlinearity, but it only chooses how to average. Each output therefore lies in the convex hull of the values. The MLP applies a ReLU to a $4D$-wide hidden layer of every token. The Fall 2022 lecture 19 notes give this reason for the MLP. The MLP also holds most of the weights. With width $4D$, its two matrices have $8D^2$ weights, against $4D^2$ in attention. That is two thirds of the block.

#### *(How to Wire the Two Parts)* Attention and MLP must each get their own residual connection, either in series or in parallel.

The Spring 2023 lecture 18 notes compare several wirings. In the **serial** wiring, the attention part has its own skip and so does the MLP. The **parallel** wiring computes $\mathbf X + \mathrm{MHA}(\mathbf X) + \mathrm{MLP}(\mathbf X)$ from the same input. It behaves much like the serial one, since the next layer's attention follows this MLP. It is also simpler to run at large scale. One wiring fails. It places attention and the MLP inside a single residual connection. The skip then jumps over both parts, so the pair may learn little. The MLP also sees only the attention output and loses the token's own vector $\mathbf x_n$.

#### *(Pre-LN Versus Post-LN)* Placing the normalization inside each residual branch keeps a clean identity path from the output back to the input.

In pre-LN, $\mathbf x_n$ passes from the bottom of the stack to the top with only additions on the way. The gradient along this path is the identity, as in a [[5.2.5. Residual Networks|pre-activation ResNet]]. Pre-LN models add one more normalization after the last block, before the output layer. In post-LN, every block ends with a normalization on the main path, so the gradient passes through $2N_\times$ normalizations. The lecture notes that normalization now typically comes before the attention part.

>[!warning] Not Taught in Lecture
>The effect on training follows the notes to Prince chapter 12 and Xiong et al. (2020).

In post-LN, the gradients shrink as they pass back through the network at initialization. Training then needs a learning-rate warm-up, and in practice Adam. Xiong et al. show that pre-LN transformers can train without the warm-up.

#### *(Normalize the Query, Not Its Mean)* The query should have a stable size, so the norm rescales each token but needs no centering.

The Fall 2022 lecture 19 notes argue from the query's point of view. A query picks a direction, and its inner products rank the keys along it. Its size sets how sharp the softmax is, so it should not vary much between tokens. A key may stay short, which says "this direction, but weakly". The notes therefore normalize the queries and let the keys keep their sizes. Only the scale matters for exploding or vanishing values, so the mean need not be removed. This is **RMSNorm**, $\mathrm{Norm}(\mathbf x) = \boldsymbol\gamma \odot \mathbf x/\mathrm{RMS}(\mathbf x)$ with $\mathrm{RMS}(\mathbf x) = \sqrt{\frac{1}{D}\sum_i x_i^2}$. The Spring 2023 lecture 18 notes mention a recent paper that normalizes both queries and keys before their inner product.

#### *(Parallel Training, Sequential Generation)* A decoder trains on all positions of a sequence in one pass, but it generates one token per pass.

During training, the causal mask lets each position see only earlier positions. One pass therefore computes all $N$ next-token losses, as shown in [[7.1. Attention]]. An RNN must run its $N$ steps one after another even during training. At inference, each new token depends on the one before, so generation is sequential in any model. A transformer decoder stores past keys and values in a [[7.1.1. Multi-Head Attention|KV cache]], so each step only processes the new token.

#### *(Parameter and Compute Count)* A block with an MLP of width $4D$ has $12D^2$ weights and costs about $24D^2 + 4ND$ operations per token.

Attention has $4D^2$ weights and the MLP has $8D^2$, so $12D^2$ per block, with biases ignored. Each weight does one multiply and one add per token, which gives $24D^2$ operations. The scores $\mathbf q_n^T\mathbf k_m$ over all heads take $2ND$ operations per token, and the weighted sum of values takes another $2ND$. The weight term dominates when $N < 6D$. As a check, GPT-3 has $96$ blocks with $D = 12{,}288$. That gives $12 \cdot 96 \cdot 12{,}288^2 \approx 1.74 \times 10^{11}$ weights, close to its $175$ billion parameters. The embedding table adds the rest.

#### *(Weak Inductive Bias)* A transformer assumes little about its input, so it needs much more training data than a CNN or an RNN.

A CNN assumes that nearby pixels matter together and that patterns can appear anywhere. An RNN assumes that the past matters through a summary state. Self-attention lets any token read any token with weights that it learns. The Spring 2023 lecture 18 notes and the Fall 2022 lecture 19 notes stress the consequence. Transformers are trained on huge amounts of unlabeled text with [[8.1. Self-Supervised Learning|self-supervision]]. They are then adapted to the task that matters, as in [[7.5. Encoder and Decoder Models]]. Prince makes the same point for images, where transformers must learn what convolution builds in.

#### *(Sequence Length)* Attention costs grow as $N^2$, and the positional encoding decides whether a model can read sequences longer than in training.

Attention over $N$ tokens computes $N^2$ scores per head and layer, which limits the context length. [[7.1.2. Efficient Attention]] covers ways around this. A model with learned absolute position vectors has none beyond its largest training position, so it cannot read longer inputs. Sinusoidal encodings, relative biases and RoPE can be computed for any position. Their quality beyond the training length is a separate question, discussed in [[7.4. Positional Encoding]].

# Examples

>[!example] (Easy) Shapes Through One Block
>A pre-LN block has $D = 512$, $H = 8$ heads and an MLP of width $2048$. It reads $N = 10$ tokens.
>
>>[!example]- List the shape after each step of the block.
>>The input $\mathbf X$ is $10 \times 512$, and so is $\mathrm{Norm}(\mathbf X)$. Each head forms $10 \times 64$ queries, keys and values and a $10 \times 10$ attention matrix. The eight $10 \times 64$ head outputs side by side form $10 \times 512$, and $\mathbf W_o$ keeps that shape. Adding the input gives $10 \times 512$. The MLP lifts each token to $2048$ numbers, a $10 \times 2048$ matrix, and maps back to $10 \times 512$. The second addition gives the block output, again $10 \times 512$. The shape never changes, so blocks can be stacked.

>[!example] (Medium) Counting BERT's Parameters
>Prince describes BERT with $24$ blocks, $D = 1024$ and MLP width $4096$. It has a vocabulary of $30{,}000$ tokens and inputs of up to $512$ tokens. Prince quotes about $340$ million parameters.
>
>>[!example]- Count the weights of the blocks and the embeddings, then add the biases and normalization parameters.
>>Each block has $12 \cdot 1024^2 = 12{,}582{,}912$ weights, so $24$ blocks have $301{,}989{,}888$. The token embedding table has $30{,}000 \cdot 1024 = 30{,}720{,}000$ entries. Learned position vectors add $512 \cdot 1024 = 524{,}288$. Each block also has $4 \cdot 1024$ attention biases, $4096 + 1024$ MLP biases and $4 \cdot 1024$ normalization parameters. That is $13{,}312$ per block and $319{,}488$ in total. The sum is $333{,}553{,}664$, about $334$ million. The remaining few million come from smaller parts, such as the output head and the slightly larger real vocabulary. The blocks hold $91\%$ of the parameters.

>[!example] (Hard) When Attention Dominates the Cost
>Take one GPT-3 block, with $D = 12{,}288$, and use the count of $24D^2 + 4ND$ operations per token.
>
>>[!example]- Find the share of the attention scores in the cost for contexts of $N = 2048$ and $N = 32{,}768$ tokens. At what $N$ do the two terms match?
>>The weight term is $24 \cdot 12{,}288^2 = 3{,}623{,}878{,}656$ operations per token. For $N = 2048$, the attention term is $4 \cdot 2048 \cdot 12{,}288 = 100{,}663{,}296$. Its share is $100{,}663{,}296/3{,}724{,}541{,}952 = 2.7\%$. For $N = 32{,}768$ the attention term is $1{,}610{,}612{,}736$ and its share is $30.8\%$.
>>
>>The terms match when $4ND = 24D^2$, that is, at $N = 6D = 73{,}728$ tokens. Below this length the matrix multiplications with weights dominate the arithmetic. This is why the $N^2$ cost of attention mattered little for GPT-3's context of $2048$ tokens. Memory is a different story, since a stored attention matrix grows as $N^2$ at any width.
