>[!note] Image Warping
>**Image warping** geometrically transforms an image so that its pixels move to new locations according to a mapping function or [[3.1. Affine Transformations|transformation matrix]] $T$. Warping changes the domain of the image (where values sit), not the values themselves. Filtering does the opposite. Write $\mathbf{p}' = T\mathbf{p}$ for the map from a point $\mathbf{p}$ of the source image $f$ to a point $\mathbf{p}'$ of the destination image $g$. Then
>$$g(T\mathbf{p}) = f(\mathbf{p}), \qquad \text{equivalently} \qquad g(\mathbf{p}') = f(T^{-1}\mathbf{p}').$$
>In **forward warping**, each pixel of $f$ is sent to its new position $\mathbf{p}' = T\mathbf{p}$ in $g$. The landing point is usually between pixels. Distributing its color among the neighboring destination pixels is called **splatting**. Forward warping is simple, but it leaves holes where $T$ stretches the image and sends several source pixels to one destination pixel where $T$ shrinks it.
>
>Instead of pushing source pixels forward, **inverse warping** loops over the destination pixels $\mathbf{p}'$ and pulls each value from $\mathbf{p} = T^{-1}\mathbf{p}'$ in the source. Since $\mathbf{p}$ usually lies between pixels, its value is [[3.3. Image Interpolation|interpolated]] from nearby samples with nearest neighbor, bilinear, Gaussian or bicubic interpolation. Inverse warping is usually the better choice, because every output pixel gets exactly one value and no holes appear. It requires an invertible warp, which is not always available. For an affine or projective $T$, the inverse is a matrix of the same class. The output canvas comes from transforming the four source corners with $T$ and taking their bounding box.

>[!warning] The Direction of $T$
>The lecture first writes warping as $g(x) = f(T(x))$. In that formula $T$ maps output coordinates to input coordinates. Later slides write $(x', y') = T(x, y)$, where $T$ maps source to destination, which is the convention of this note. The two $T$'s are inverses of each other. Libraries also differ. `scipy.ndimage.affine_transform` expects the output-to-input matrix, in (row, column) order. Check the direction on one point before warping a whole image.

# Intuition

Forward warping scatters. Each source pixel carries its color to wherever $T$ sends it. The landing points do not line up with the destination grid, so some destination pixels receive nothing and others receive several values. With the landing points scattered irregularly, there is no regular neighborhood to interpolate from. Inverse warping gathers instead. Each destination pixel looks up where it came from in the source. That location lies on or between the points of a regular grid, where interpolation is well defined. The figure shows both for a scale by $2$.

# Properties

#### *(Inverse Warping in Code)* The loop runs over output pixels, maps each one back with $T^{-1}$, and interpolates.

The plain loop below matches the lecture's description. Here $f$ is the source image, $T$ is a $3 \times 3$ matrix from source to destination coordinates, and coordinates are $(x, y) = $ (column, row).

```python
def inverse_warp(f, T, out_h, out_w):
    g = zeros((out_h, out_w, f.shape[2]))
    T_inv = inv(T)                                   # output -> input
    for y_out in range(out_h):                       # loop over OUTPUT pixels
        for x_out in range(out_w):
            x, y, w = T_inv @ [x_out, y_out, 1]
            x, y = x / w, y / w                      # w stays 1 for affine T
            if 0 <= x <= f_width - 1 and 0 <= y <= f_height - 1:
                g[y_out, x_out] = interpolate(f, x, y)   # nearest, bilinear, ...
    return g                                          # pixels outside f stay 0
```

The lecture's "life-hack" removes both loops. Build the coordinates of every output pixel at once with `np.meshgrid`, stack them into a $3 \times N$ array of homogeneous points, and multiply by $T^{-1}$ once. Then divide by $w$ and call one interpolation routine on all points, such as `scipy.ndimage.map_coordinates`, `cv2.remap`, or MATLAB's `interp2`. These routines take (row, column) or $(x, y)$ in different orders, so the order must be checked.

#### *(Holes and Pile-Ups)* Forward warping misses output pixels in proportion to the stretch, and inverse warping aliases when it shrinks.

A forward warp that scales by $s > 1$ in both directions hits at most a fraction $1/s^2$ of the output pixels. Splatting each value over a small footprint fills gaps only up to the footprint's size. Where $T$ shrinks the image, many source pixels land on one output pixel. The simple loop then keeps whichever value was written last. A better rule adds up colors and weights and divides at the end. Inverse warping has the mirror-image problem. When $T$ shrinks the image a lot, neighboring output pixels pull from source points several pixels apart and skip the detail in between. That is [[2.4. Anti-Aliasing|aliasing]], and the fix is to blur the source before warping, for example by sampling from a coarser level of an [[2.5. Image Pyramids|image pyramid]].

#### *(Output Canvas)* The images of the four source corners give the size and offset of the output.

An affine map sends the source rectangle to a parallelogram, so the four transformed corners bound all of the output. Take the minimum and maximum of their coordinates to get the canvas size. If the minimum $(x_{\min}, y_{\min})$ is negative, compose a shift into the map, $T_{\text{total}} = T(-x_{\min}, -y_{\min})\,T$, and then invert $T_{\text{total}}$. Output pixels whose preimage falls outside the source get a fill value, often $0$, plus an alpha value of $0$ that later [[2.6. Multiresolution Blending|blending]] can use. The same corner rule works for a [[3.4. Homographies|homography]] as long as $w' > 0$ at all four corners. Then no point of the rectangle is sent to infinity.

#### *(Warps Without Inverses)* When $T^{-1}$ is unavailable, define the warp in the output-to-input direction from the start.

An affine map with a singular linear part flattens the image onto a line and has no inverse. A warp defined by sending each source pixel along its own motion vector has no closed-form inverse either. [[3.5. Image Morphing|Morphing]] avoids the problem by never inverting a forward map. For each triangle of the output shape, it directly builds the affine map from that triangle to the matching source triangle. Each such map is invertible as long as no triangle collapses to a line.

# Examples

>[!example] (Easy) Forward Warping a Thumbnail by a Factor of 2
>A $100 \times 100$ thumbnail is enlarged to $200 \times 200$ by forward warping with $T(x, y) = (2x, 2y)$ and no splatting.
>
>>[!example]- How many output pixels receive a value? What fraction are holes?
>>Source pixel $(x, y)$ with $x, y \in \{0, \dots, 99\}$ maps to $(2x, 2y)$. Only output pixels with both coordinates even receive a value. That is $100 \cdot 100 = 10{,}000$ pixels out of $200 \cdot 200 = 40{,}000$. The other $30{,}000$ pixels, or $75\%$, are holes. The output looks like a regular dot pattern on a black background. Inverse warping fills every pixel, because each output pixel $(x', y')$ reads the source at $(x'/2, y'/2)$ and interpolates there.

>[!example] (Medium) The Canvas for a Rotated Photo
>A $640 \times 480$ photo is rotated by $30^\circ$ about its center $(320, 240)$ with the lecture's $R(\theta)$. In image coordinates, with $y$ pointing down, this rotation looks clockwise on screen.
>
>>[!example]- What canvas size holds the full result, and what shift must be composed into $T$?
>>The corners $(0,0)$, $(640,0)$, $(640,480)$ and $(0,480)$ map to $(162.87, -127.85)$, $(717.13, 192.15)$, $(477.13, 607.85)$ and $(-77.13, 287.85)$. So $x$ ranges over $[-77.13, 717.13]$ and $y$ over $[-127.85, 607.85]$. The extent is $794.26 \times 735.69$, which needs a canvas of $795 \times 736$ pixels. The same numbers follow from $640\cos 30^\circ + 480\sin 30^\circ = 794.26$ and $640\sin 30^\circ + 480\cos 30^\circ = 735.69$. The shift $T(77.13, 127.85)$ moves the top-left of the bounding box to $(0,0)$. Inverse warping then uses $\left(T(77.13, 127.85)\,T\right)^{-1}$. The photo covers only $640 \cdot 480 / (795 \cdot 736) = 52.5\%$ of the canvas. The other $47.5\%$ is the four empty corner triangles, which inverse warping fills with the background value.

>[!example] (Medium) Passing the Right Matrix to SciPy
>The goal is to enlarge a $4 \times 4$ array by $2$ with `scipy.ndimage.affine_transform(img, M, output_shape=(8, 8), order=1)`, where `order=1` means bilinear interpolation.
>
>>[!example]- Should $M$ be $\mathrm{diag}(2, 2)$ or $\mathrm{diag}(0.5, 0.5)$? Check one output pixel.
>>SciPy reads the input at $M\mathbf{o}$ for each output index $\mathbf{o}$, so $M$ is the output-to-input map $T^{-1}$. Enlarging by $2$ needs $M = \mathrm{diag}(0.5, 0.5)$. With `img = np.arange(16).reshape(4, 4)`, the output at index $(2, 2)$ equals the input at $(1, 1)$, which is $5$. The output at $(2, 4)$ equals the input at $(1, 2)$, which is $6$. The output at $(2, 3)$ is the bilinear value $5.5$ halfway between them. Passing $\mathrm{diag}(2, 2)$ instead shrinks the image: output $(1, 1)$ reads input $(2, 2)$, which is $10$.
